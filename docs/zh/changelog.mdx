## [v0.8.7] - 2026-06-10

### 安全性

- **修复了双因素认证绕过漏洞。** API 和聊天/SSE 认证现在需要真正的访问令牌（SSE 流式传输也接受其短期票证）；2FA 临时令牌、刷新令牌和绑定/SSE 票证——全部使用相同密钥签名——不再能用于重放认证，因此单独的被盗密码无法再跳过第二因素。
- **OAuth 登录不再自动链接到未验证电子邮件的现有账户。** 第三方账户仅当提供商标记该电子邮件已验证时，才通过电子邮件与本地账户匹配，防止通过攻击者控制的未验证地址进行接管。

### 新增

- **`file_ops.apply_patch` — 应用V4A格式的diff补丁到文件。** 允许智能体使用基于行的分块和模糊空白匹配进行多行编辑，补充现有的`find_replace`功能，适用于精确子串匹配脆弱的场景。
- **用于输入和输出验证的内容护栏。** 新的`core/agent/guardrail`层与现有的工具权限闸门和安全检查并行运行（不替代）。输入护栏（默认：越狱短语检测器）在任何LLM调用前运行，如果触发则中止该轮次，节省令牌并在聊天中显示清晰的"已阻止"通知。输出护栏在最终答案后运行。通过`FIM_GUARDRAILS_INPUT`/`FIM_GUARDRAILS_OUTPUT`环境变量配置；每个智能体的UI配置将在未来版本中推出。

### 更改

- **`/settings?tab=billing` 现在以全宽渲染，与其他设置选项卡在视觉上保持一致。** 移除了 `max-w-4xl` 宽度限制和冗余的外层滚动容器；去掉了页面标题图标；将方案 / 使用量 / 订阅 / 方案对比卡片重写为与使用量选项卡相同的简洁边框分割模式（紧凑标签 + `tabular-nums` 数字）。旧布局看起来像一个独立的页面被意外插入了设置框架中。

### 已修复

- **代币配额现在在您的账单日期重置，而不是每月1日。** 使用情况始终按日历月计算，与订阅时间无关，因此付费用户可能在20日被收费，却要等到1日才能获得新配额——在月末开始的订阅实际上会在几天后获得第二个完整配额。配额现在在每个订阅的月度周年纪念日重置（免费用户仍按日历月重置）。按年计费的套餐现在每月正确补充，而不是每年一次。"套餐与账单"选项卡、"使用情况"卡片和超配额对话框现在都在同一时间窗口内测量使用情况并显示重置日期，因此显示的"本期使用情况"与聊天实际停止您的时间点相匹配。
- **订阅续订现在推进账单周期。** 在自动续订时，显示的周期结束日期保持冻结在前一个周期，即使Stripe已收费并将订阅向前推进——续订处理程序仅从发票有效负载中读取新周期，其中该信息不可靠。现在它从Stripe检索权威的周期边界，因此周期结束日期（和配额重置）在每次续订时向前移动。这也消除了一个潜在风险，即取消此类订阅可能会立即降级账户，而不是在真正的周期结束时降级。
- **原始工具调用协议不再泄露到智能体答案中。** 当模型即兴创作工具调用作为纯文本时（例如发出`<tool_call>`/`<tool_response>`块——当它尝试使用不可用的工具时很常见），该文本——包括其中的任何base64/文件转储——可能会逐字出现在回复中。所有答案路径现在都会剥离此伪协议，解析器另外将`{"name","arguments"}`方言识别为真正的工具调用，而不是泄露它。
- **智能体轮次期间间歇性的`APIConnectionError: Connection error`突发。** 共享HTTP连接池为空闲保活连接保留长达30秒；当上游中继或NAT静默回收空闲连接时，下一个请求重用半死的套接字并失败。保活过期时间现在默认为短5秒（轮次内的热连接仍被重用），池可通过`LLM_HTTP_MAX_CONNECTIONS` / `LLM_HTTP_MAX_KEEPALIVE` / `LLM_HTTP_KEEPALIVE_EXPIRY`调整——设置`LLM_HTTP_MAX_KEEPALIVE=0`可在不可靠的上游后面完全禁用连接重用。
- **API密钥使用统计（`total_requests`、`last_used_at`）现在在每个请求时持久化。** 以前增量是在请求的数据库会话中写入的，该会话仅由执行自己写入的端点提交——因此只读API密钥调用（仪表板、文件、模型、导出……）会静默回滚计数器。使用情况现在记录在独立的自提交会话上，与请求成功解耦。

## [v0.8.6] - 2026-05-08

### Added

- **Stripe 计费 — Pro 计划订阅。** `/settings?tab=billing` 下的新 `Plan & Billing` 标签页显示当前计划、每月令牌使用量、周期重置时间，以及 `Upgrade to Pro`（Stripe Checkout）或 `Manage subscription`（Customer Portal）。成功结账后打开一个庆祝模态框，显示购买的计划；重定向参数仅在关闭后才被移除，因此刷新不会重新触发。配额强制执行遵循每个用户的计划；已取消的订阅在付费期结束前保持 Pro 状态；中途 402 配额对话框现在跳转到计费标签页。管理员可在 Admin Panel → Billing 下管理计划和浏览订阅。Pro 目前使用 Stripe **test-mode** 价格；生产环境切换时替换价格 ID。
- **管理员控制的计费功能标志。** Admin → System Settings 中的 `Enable Stripe Billing` 开关控制整个 Stripe 管道——用户端 `/api/billing/*`、Stripe webhook、管理员计划/订阅 CRUD，以及前端计费标签页 + 管理员导航在关闭时隐藏或返回 503。首次激活时初始化 Free + Pro，设置 `default_plan_id` 指针，并回填 `users.plan_id`；后续的关闭/打开是纯标志位切换。没有 Stripe 凭证的私有部署保持干净。当计费关闭时，配额链回退到管理员设置的 `Default Monthly Token Quota`。
- **按用户无限配额 + Registered 列。** 空配额字段继承全局限制；`0` 授予无限配额。之前两者都折叠为同一状态。用户表还新增了 Registered 列。
- **非英文文档（`zh` / `ja` / `ko` / `de` / `fr`）现在显示完整的 API Reference 和 Channels Configuration 部分——`Endpoints` 组和 `Configuration > Channels` 子组之前仅提供英文版本。

### 已更改

- **`套餐与账单`现为设置标签页，而非独立页面。** 将`/settings/billing`合并回`/settings?tab=billing`，以便用户在切换套餐时左侧导航保持可见（与GitHub、Linear、Notion的做法一致）。独立路由会进行重定向，因此旧书签和早期部署的Stripe Checkout返回URL仍可正常工作。`订阅`标签页已重命名为`市场`，以区分计划订阅。
- **免费套餐配额在管理员套餐页面上为只读。** 配额来源于系统设置→默认月度Token配额；在该处编辑会自动传播。后端对免费套餐的PATCH请求会静默忽略`monthly_token_quota`。
- **Token配额在账单页面、套餐卡片和管理员套餐表中显示为`5M`/`100K`** 而非`5,000,000`。管理员输入字段仍接受原始数字。
- **翻译权限从各语言环境文件转移到单一词汇表。** 规则存放于[`scripts/translation-glossary.md`](https://github.com/fim-ai/fim-one/blob/master/scripts/translation-glossary.md)，在每次LLM翻译调用中加载（JSON、MDX、README）。提交前钩子无条件拒绝对生成的语言环境文件的手动编辑。若要修复翻译错误，请编辑词汇表并使用`--force`重新生成。
- **许可方和管辖法律。** FIM One源代码可用许可证现由**FIM Labs Pte. Ltd.**（新加坡）颁授；管辖法律从中国改为新加坡；争议由新加坡SIAC仲裁处理（单仲裁员，英文）。新增顶级`NOTICE`文件记录研发归属、商标和第三方组件政策。允许使用条款和限制条款未作改动。

### 修复

- **管理员对智能体、连接器、知识库和 MCP 服务器的审批/拒绝在 PostgreSQL 上不再失败。** publish-review `reviewed_at` 列现已支持时区，因此审批写入在 PG 上成功（该错误在 SQLite 开发数据库上不可见）。
- **OAuth 用户可以再次刷新其会话。** OAuth 颁发的刷新令牌以刷新端点无法匹配的形式存储，导致访问令牌过期后强制重新登录；现已将其存储为摘要形式，与其他路径一致。
- **浏览器标签页标题现在反映 `/settings` 和 `/admin` 中的活跃子标签页**（例如 `Settings · Billing — FIM One`），因此可以区分多个固定标签页。
- **使用情况页面在管理员设置了默认令牌配额时不再报告"无限制"** —— 现在可以通过统一配额链解析（每用户覆盖 → 计划层级 → 系统默认值）。
- **智能体设置：绑定资源在进入时不再闪烁为"(已删除)"。** 孤立徽章在库存获取完成后再渲染。
- **提示框现在遵循浅色/深色主题**，而不是硬编码为深色。
- **按智能体分类的使用情况不再为与已删除智能体关联的对话重复"直接对话"行。**
- **自托管 `./deploy.sh` 不再因 `container name already in use` 而失败** —— 在 `docker compose up` 前清理哈希前缀的僵尸容器和 DooD 沙箱子进程。
- **推送后不再出现冗余的 `chore(i18n): sync translations` 提交** —— 提交前钩子现在将 `.translation-cache.json` 与已翻译文件一起暂存。
- **智能体对话在确认必需的工具在未绑定智能体的会话中运行时不再崩溃** —— 当没有智能体可路由时，闸门会优雅地退出。
- **在严格交替提供商（Claude）上重试不再因历史记录中来自已停止转轮的孤立用户消息而失败** —— 相同角色的连续消息在分派前会折叠为单个转轮。
- **演练场重试在流前窗口期间不再短暂显示两次查询。**
- **ReAct 智能体现在在操作员拒绝审批请求后会确认并停止**，而不是重试改写的工具调用。
- **演练场"推荐后续"回归，现已按智能体选择性启用**（默认关闭；智能体设置中新增 `Follow-up Suggestions` 开关）。

## [v0.8.5] - 2026-04-23

### 新增

- **贡献者友好的国际化工作流**：贡献者无需配置 `LLM_API_KEY` 即可提交涉及英文源文件的 PR。如果跳过本地预提交翻译步骤（无密钥），新的 `.github/workflows/i18n-sync.yml` 工作流在 PR 合并后会在 `master` 上将 EN 翻译为 ZH/JA/KO/DE/FR，并自动提交结果。预提交钩子还会拒绝手动编辑生成的语言环境文件（通过 `ALLOW_LOCALE_EDIT=1` 覆盖以进行合法的翻译修复），防止 EN 源文件和翻译输出之间的无声漂移。
- **国际化 CI 回退端到端验证**：烟雾测试推送（仅 EN，跳过本地翻译钩子）确认了 GitHub Actions 工作流检测到更改的源文件、翻译成全部五种语言，并使用 `[skip ci]` 自动提交结果到 master，防止递归。
- **Exa 集成文档页面**：边栏中的专属集成部分，提供一流的 Exa 页面，涵盖完整的 Exa 搜索表面（神经搜索 / 快速 / 深度推理 / 即时），过滤、内容检索和三个为新闻监控、研究论文检索和深度推理智能体优化的预设。作为 Exa 集成目录的合作伙伴门户登陆页。
- **信创数据库支持**：数据库连接器现在除了 PostgreSQL/MySQL 之外，还列出了 KingbaseES（人大金仓）、HighGo（瀚高）和 DM8（达梦）。KingbaseES 和 HighGo 与 PG 兼容，无需额外依赖即可复用 `asyncpg`；DM8 使用官方 `dmPython` 供应商轮子。独立的 `scripts/test_xinchuang_dbs.py` 让运维人员能够从 CLI 验证实时连接性。
- **飞书通道 + 确认闸门（通过 IM）**：新的 `Channel` 资源类型（组织范围，静态加密凭据），使组织能够连接飞书应用用于出站消息。标记为 `requires_confirmation=True` 的工具现在会向配置的飞书群组发送"批准/拒绝"互动卡片，而不仅仅在门户中显示确认对话框——组织内任何授权成员都可以直接从飞书批准或拒绝。涵盖设置 → 通道管理 UI（列表、创建/编辑含脏态保护、带可复制回调 URL 的详情、测试发送）、CRUD API（`/api/channels`）和飞书事件回调端点（`/api/channels/{id}/callback`），包括签名验证和 URL 挑战支持。v0.9 IM 通道集成路线图项的第一步，提前于 2026-04-24 路演交付。
- **智能体钩子系统（框架）**：`src/fim_one/core/hooks/` 中的新 `PreToolUseHook` / `PostToolUseHook` 抽象允许确定性逻辑在 LLM 循环外运行——FeishuGateHook 是第一个具体实现，附加到确认闸门流程中。完整的钩子生命周期 + 用户定义的 YAML 钩子仍为 v0.9 范围。
- **钩子系统现已在 ReAct 和 DAG 运行时中运行**：在 `model_config_json` 中声明 `hooks.class_hooks` 的智能体会在每次聊天会话上实例化并注册这些钩子。第一个消费者——FeishuGateHook——当智能体调用其连接器操作标记为 `requires_confirmation=True` 的工具时自动触发、向组织的飞书群组发送"批准/拒绝"卡片、阻止该工具，并根据裁定恢复或中止。之前钩子抽象就位，但网页层中没有任何内容将其连接到实时聊天。
- **通道和钩子系统架构文档已发布**：新的 `docs/architecture/hook-system.mdx` 解释了三个钩子点、钩子为何在 LLM 循环外运行，并逐步演示了 FeishuGateHook。现有架构页面（system-overview、organization、react-engine、philosophy）交叉链接到它。README 现在将消息通道列为一流的 v0.8 功能，应用层图表的 IM 目标与门户/API/iframe 并列。
- **钩子审批演练场**：通道详情工作表现在有一个"测试审批流程"操作，可以模拟敏感工具调用、向关联的飞书群组推送真实确认卡片，并实时轮询审阅者的决定。与现有预览按钮不同，这演练了完整的生产路径（真实 `ConfirmationRequest` 行、真实飞书回调、状态转换），因此演示和交付前排练使用与生产钩子相同的代码路径。

- **按智能体任务完成通知**：智能体现在可以在长时间运行的 ReAct 或 DAG 任务完成时向组织的通道（目前为飞书）推送总结卡片。可在设置 → 智能体 → 通知中按智能体配置。通用出站通知模式的第一个消费者。
- **可配置的确认闸门——内联*或*通道**：每个智能体现在在设置中都有一个"审批"部分，具有三种路由模式（自动 / 仅内联 / 仅通道）、审批人范围选择器（发起人 / 智能体所有者 / 组织内任何人）、"要求每个工具调用都确认"覆盖，以及显式审批通道选择器。自动模式会在存在关联通道时使用它，并会优雅地回退到聊天流中的内联审批卡片——因此没有任何通道的智能体仍会获得真实的审批 UX，而不是无声地失败。新的 `POST /api/confirmations/{id}/respond` 端点与飞书 webhook 共享一个统一的决定记录路径，因此每个审批——无论在聊天中点击还是在飞书群组中点击——都会标记相同的 `approver_user_id` 和 `decided_at` 审计字段。

### Changed

- Playground加载指示器现在使用精细的文字闪烁效果，而不是在8秒后冻结在伪满宽度的不真实进度条。将两个现有的闪烁实现（`.shiny-text`和`.text-shimmer`）统一为单一的主题感知原始元素，具有可选的warm预设。
- 连接器卡片现在在连接器禁用`allow_fallback`时显示"Private default"徽章（带工具提示），以便所有者一目了然地识别哪些连接器需要每个用户提供自己的凭证。连接器设置表单中Allow-Fallback切换下的帮助文本也澄清该标志仅限制与其他用户的共享——所有者始终可以使用自己的默认凭证，无论如何。

### 已修复

- 连接器所有者通过设置 `allow_fallback=false` 并仅持有默认凭证（无按用户凭证）发起的连接器调用不再返回 401 "Requires authentication" 错误。所有者现已豁免于回退闸门——该标志仅控制*其他*用户是否可以借用所有者的默认凭证。此前所有者自己的智能体在无声地发送未认证请求，同样的问题也影响了工作流的 `connector_action` 节点。
- 会话导出现在为自动路由的 DAG 会话显示正确的模式标签（"Planner" / "规划"），而不是总是显示"Standard"。
- 导出时间戳现在遵循用户配置的时区，而不是显示原始 UTC。
- 上传的文件内容不再泄露到导出的会话中；仅包含用户的消息文本。
- 当提供商为每个流式工具调用增量重复使用 `index=0` 时，并行工具调用不再发生碰撞；聚合器现在通过 id 或名称变化检测边界，并将后续增量重新映射到正确的槽位。
- "设置"→"通道"现在反映当前用户的组织角色：成员（非管理员/所有者）会看到禁用的"新建通道"按钮、隐藏的编辑/启用-禁用/删除操作、只读横幅和权限感知的空状态——而不是在提交时失败并显示"需要组织管理员访问权限"的启用 CTA。
- 会话过期重定向现在保留查询字符串，因此用户在重新认证后会返回到他们之前查看的确切标签页/筛选器，而不是裸路径。
- Feishu 通道表单与铺在对话框上方的聊天选择器交互时不再显示虚假的"放弃未保存的更改"提示。
