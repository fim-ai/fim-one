## 常见问题

<AccordionGroup>
  <Accordion title="支持哪些LLM提供商？">
    FIM One 与**任何OpenAI兼容的LLM提供商**配合使用。这包括：

    - **商业API** — OpenAI、DeepSeek、Anthropic（Claude）、阿里巴巴通义千问、Google Gemini，以及任何公开`/v1/chat/completions`端点的提供商。
    - **本地/自托管** — Ollama、vLLM、LocalAI、LM Studio，以及任何其他提供OpenAI兼容API格式的运行时。

    你可以通过`.env`中的三个环境变量配置提供商：

    ```bash
    LLM_API_KEY=sk-your-key
    LLM_BASE_URL=https://api.openai.com/v1   # change for other providers
    LLM_MODEL=gpt-4o                         # change for other models
    ```

    有关提供商特定的示例，请参阅[快速开始](/quickstart)指南。
  </Accordion>

  <Accordion title="我可以使用本地或自托管模型吗？">
    可以。FIM One连接到任何实现OpenAI兼容API格式的端点。常见的自托管选项包括：

    | 运行时 | 基础URL | 示例模型 |
    |---------|----------|---------------|
    | **Ollama** | `http://localhost:11434/v1` | `qwen2.5:14b` |
    | **vLLM** | `http://localhost:8000/v1` | `Qwen/Qwen2.5-72B-Instruct` |
    | **LocalAI** | `http://localhost:8080/v1` | `llama3` |
    | **LM Studio** | `http://localhost:1234/v1` | （你加载的任何模型） |

    当提供商不需要身份验证时，将`LLM_API_KEY`设置为任何非空字符串（例如`ollama`）。所有智能体功能——ReAct推理、DAG规划、工具调用——无论模型是本地还是云托管，都以相同方式工作。
  </Accordion>

  <Accordion title="FIM One是开源的吗？">
    FIM One在**源代码可用许可证**下发布。这不是OSI批准的开源许可证，但为大多数用例提供了广泛的自由：

    **允许的用途：**
    - 在你的组织内部使用
    - 修改和自定义开发
    - 保持许可证完整的分发
    - 嵌入到你自己的（非竞争）应用程序中

    **受限的用途：**
    - 多租户SaaS产品
    - 竞争性智能体平台
    - 白标或移除品牌

    如有商业许可询问，请在[GitHub](https://github.com/fim-ai/fim-one)上提交issue。完整条款请参阅[LICENSE](https://github.com/fim-ai/fim-one/blob/master/LICENSE)。
  </Accordion>

  <Accordion title="我可以将FIM One用于付费客户或咨询项目吗？">
    可以——收费不是许可证限制的内容。你可以向单个客户交付基于FIM One的解决方案，前提是这是一个**专用的单租户部署**，供该客户自己内部使用，且**FIM One品牌保持完整**。

    以下三种情况需要单独的[商业许可证](mailto:license@fim.ai)：

    - **白标** — 移除或隐藏FIM One品牌，使其以客户品牌发布。（这是代理商和集成商最常见的问题。）
    - **多租户重用** — 从一个共享部署为多个客户服务，或任何"FIM One即服务"产品。
    - **竞争平台** — 使用FIM One构建另一个智能体编排、工作流或任务规划平台。

    有关完整分解，请参阅许可证页面上的[常见场景](/license#common-scenarios)。
  </Accordion>

  <Accordion title="我如何报告安全漏洞？">
    **不要为敏感漏洞开设公开GitHub issue。**

    - **敏感报告**（凭证泄露、身份验证绕过、注入等）— 使用[GitHub安全公告](https://github.com/fim-ai/fim-one/security/advisories/new)或发送邮件至**security@fim.ai**。
    - **低严重性问题**（缺失头部、信息披露）— 使用`security`标签开设常规GitHub issue。

    所有报告在48小时内（工作日）得到确认。关键问题尽快修补；其他问题随下一个版本发布。

    有关范围、响应时间表和自托管最佳实践，请参阅完整的[安全政策](https://github.com/fim-ai/fim-one/blob/master/SECURITY.md)。
  </Accordion>
</AccordionGroup>

## 部署

<AccordionGroup>
  <Accordion title="系统要求是什么？">
    **最低要求：**

    | 资源 | 要求 |
    |----------|-------------|
    | **Python** | 3.11+ |
    | **RAM** | 至少2 GB |
    | **磁盘** | 1 GB可用空间（另需为上传的文档和向量存储预留空间） |
    | **Node.js** | 18+（用于本地开发） |

    **生产环境推荐配置：**

    | 资源 | 建议 |
    |----------|----------------|
    | **RAM** | 4 GB以上（尤其是在本地运行嵌入模型时） |
    | **CPU** | 2个以上核心 |
    | **数据库** | 多工作进程部署使用 PostgreSQL |

    **Docker替代方案：** Docker 20+和 Docker Compose v2。不需要本地安装 Python或 Node.js——所有内容都会在容器内构建。
  </Accordion>

  <Accordion title="FIM One支持 ARM／Apple芯片吗？">
    支持。Docker和本地开发都支持 ARM架构，包括搭载 Apple芯片（M1/M2/M3/M4）的 Mac。Docker镜像会针对 `linux/arm64` 原生构建，所有 Python和 Node.js依赖项都有兼容 ARM的 wheel或备用方案。
  </Accordion>

  <Accordion title="支持哪些数据库？">
    FIM One以两种不同方式使用数据库：

    **1. 内部数据库（FIM One自身的数据）：**
    - **SQLite**——零配置默认选项，非常适合开发和单工作进程部署。
    - **PostgreSQL**——生产环境推荐选项，多工作进程设置（`WORKERS > 1`）必需。

    **2. 连接器目标（要连接的系统）：**

    FIM One可以通过数据库连接器连接外部数据库，将其作为数据源：

    | 数据库 | 状态 |
    |----------|--------|
    | PostgreSQL | 支持 |
    | MySQL | 支持 |
    | DM（达梦） | 支持 |
    | KingbaseES | 支持 |
    | Highgo | 支持 |

    每个数据库连接器会自动生成三个工具：`list_tables`、`describe_table`和 `query`。默认包含架构内省、AI驱动的注释以及只读查询执行功能。
  </Accordion>

  <Accordion title="多个用户可以共享同一个实例吗？">
    可以。FIM One从底层设计之初就支持多租户部署：

    - **JWT身份验证**——基于令牌的身份验证，并为每个用户隔离会话。
    - **组织隔离**——资源（智能体、连接器、MCP服务器）按组织进行限定。知识库对其所有者保持私有，绝不会直接共享。
    - **基于角色的访问控制**——提供管理员和用户角色，并设置适当的权限边界。
    - **资源所有权**——对话和配置按用户隔离。

    对于多用户生产部署，请使用 PostgreSQL作为内部数据库，并将 `WORKERS` 设置为与预期并发量相匹配的值。
  </Accordion>
</AccordionGroup>

## 功能

<AccordionGroup>
  <Accordion title="ReAct 和 DAG 模式有什么区别？">
    FIM One 提供两个执行引擎，各自适合不同的任务类型：

    | | ReAct（标准） | DAG（规划器） |
    |---|---|---|
    | **工作原理** | 单一推理循环：推理、行动、观察、重复 | LLM 将目标分解为依赖图；独立步骤并行运行 |
    | **最适合** | 聚焦查询、单系统查询、对话任务 | 多步骤任务、跨系统编排、并行数据收集 |
    | **并发性** | 顺序执行（一次一个工具） | 并发执行（独立步骤通过 asyncio 同时运行） |
    | **重新规划** | 不适用 | 如果目标未达成，最多 3 轮自动重新规划 |

    **自动模式**（默认模式）使用快速 LLM 分类器分析每个传入查询，并自动将其路由到最优引擎。您也可以通过聊天 UI 中的三向切换开关手动选择模式（自动/标准/规划器）。

    如需深入了解，请参阅[执行模式](/concepts/execution-modes)。
  </Accordion>

  <Accordion title="如何添加新的连接器？">
    FIM One 提供三种创建连接器的方式——无需 Python 代码：

    **1. 导入 OpenAPI 规范** — 上传 YAML、JSON 或指向 OpenAPI 规范的 URL。FIM One 解析规范并自动生成包含所有操作的连接器。

    **2. AI 聊天构建器** — 用自然语言描述您想要连接的 API。AI 在对话中生成并迭代连接器配置，使用 10 个专门的构建器工具进行设置、操作、测试和智能体接线。

    **3. MCP 协议** — 直接连接任何 MCP（模型上下文协议）服务器。第三方 MCP 生态系统开箱即用。

    对于数据库连接器，配置连接详情（主机、端口、凭证），FIM One 会自动生成模式内省和查询工具。

    请参阅 [AI 构建器](/concepts/ai-builder)文档和[扩展指南](/extension-guide)获取分步说明。
  </Accordion>

  <Accordion title="我可以将 FIM One 嵌入到现有系统中吗？">
    可以。FIM One 的**副驾驶模式**专门为嵌入主机系统而设计。您可以通过以下方式集成：

    - **iframe** — 将 FIM One 聊天界面直接嵌入任何网页。
    - **小部件** — 轻量级聊天小部件，覆盖在现有 UI 上。
    - **API** — 直接使用 FastAPI 后端进行完全自定义集成。

    在副驾驶模式下，AI 在用户熟悉的界面中与用户协作——查询数据、生成报告和编排操作，无需强制用户切换应用程序。

    请参阅[执行模式](/concepts/execution-modes)了解独立、副驾驶和中心交付模式的配置详情。
  </Accordion>

  <Accordion title="翻译系统如何工作？">
    FIM One 支持 6 种语言（英语、中文、日语、韩语、德语、法语），采用完全自动化的翻译管道：

    1. **仅编辑英文源文件** — `frontend/messages/en/*.json` 中的 UI 字符串、`docs/*.mdx`（根级别）中的文档和 `README.md`。
    2. **提交时自动翻译** — 预提交钩子检测对英文文件的更改，并通过项目的快速 LLM 进行翻译。翻译是增量的：仅处理新增、修改或删除的内容。
    3. **切勿手动编辑翻译文件** — `messages/zh/`、`messages/ja/`、`docs/zh/`、`docs/ja/` 等中的文件都是自动生成的，将被覆盖。

    克隆后设置翻译钩子：
    ```bash
    bash scripts/setup-hooks.sh
    ```

    强制完全重新翻译：
    ```bash
    uv run scripts/translate.py --all
    ```
  </Accordion>
</AccordionGroup>

    | **LLM 集成** | OpenAI 兼容 API（提供商无关） |

    | **包管理器** | uv（Python）、pnpm（Node.js） |
    | **部署** | Docker Compose、单进程脚本 |

    代码库遵循异步优先、协议优先的架构，零供应商锁定。
