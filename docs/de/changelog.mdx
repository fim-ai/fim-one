## [Unreleased]

### Hinzugefügt

- **GPT-5.x-Agenten behalten ihr Reasoning über Tool-Aufrufe hinweg.** FIM One kommuniziert jetzt direkt mit der OpenAI Responses API für GPT-5.x-Modelle und überträgt das verschlüsselte Reasoning jeder Runde in die nächste, sodass ein mehrstufiger Agent auf bereits erarbeiteten Ergebnissen aufbaut, anstatt sie bei jeder Tool-Runde neu abzuleiten. Reasoning-Token-Zählungen erscheinen in der Nutzung, und das Thinking-Panel zeigt die eigene Zusammenfassung des Modells. Setzen Sie `FIM_GPT5_RESPONSES_MODE=bridge` (oder `off`), um zum vorherigen Verhalten zurückzukehren; Endpoints ohne eine `/v1/responses`-Route fallen automatisch auf Chat Completions zurück.

- **Reine Transformationsschritte in DAG-Plänen laufen als einzelner direkter LLM-Aufruf.** Der Planner markiert Merge-/Rewrite-/Zusammenfassungsschritte, die nur Upstream-Ausgaben verbrauchen, als direkte Schritte und überspringt die Tool-Schleife, die sie nie verwenden würden, was Kosten und Latenz senkt; jedes Schritt-Ergebnis erfasst nun auch, wie es ausgeführt wurde (direkter Aufruf oder Agent-Schleife, Iterationen, verwendete Tools).

- **Agenten können während der Ausführung klärende Multiple-Choice-Fragen stellen.** Wenn eine Aufgabe in wesentlich unterschiedliche Richtungen gehen könnte, pausiert der Agent und präsentiert bis zu vier strukturierte Fragen im Chat, jeweils mit 2–4 Optionen plus einem Freitextfeld „Sonstiges"; die Antwort setzt die Ausführung an Ort und Stelle fort, und das Überspringen oder ein Timeout lässt ihn nach eigenem Ermessen fortfahren.

- **Agent-Schritte tragen Live-Einzeilentitel.** Während ein Agent arbeitet, erhält jede Iteration ein kurz generiertes Label („Preisdaten werden überprüft…"), das in einem einzelnen eingeklappten Header angezeigt wird, der zum neuesten Schritt wechselt; das Erweitern zeigt die vollständige Schritt-Chronologie, und die Labels bleiben in der Gesprächshistorie erhalten.

- **Modelle eines Providers können in Bulk gelöscht werden.** Jede Modellzeile in Admin → Models trägt ein Kontrollkästchen, der Header wählt die gesamte Liste aus, und das Halten von Shift beim Klicken erweitert die Auswahl über einen Bereich von Zeilen. Das Löschen der Auswahl entfernt jedes ausgewählte Modell in einer Anfrage, nach einer Bestätigung mit der Anzahl.

- **Kleine Vergleichstabellen in Chat-Antworten werden jetzt als Card-ähnliche Layouts gerendert.** Eine Tabelle mit 2–3 Spalten, deren erste Spalte Attributbezeichnungen enthält, zeigt jedes Attribut in seiner Wertzelle an (entsprechend dem Vergleichskarten-Stil, der von KI-Chat-UIs popularisiert wurde); größere Tabellen behalten das klassische Raster.

- **Chat-Antworten rendern jetzt Mermaid-Diagramme und SVG-Abbildungen.** Ein `mermaid`-Codeblock wird zu einem Diagramm mit Design und ein `svg`-Block zu einem Bild mit Quellen-Toggle und Download; beide fallen auf einfachen Code zurück, wenn die Quelle unvollständig ist oder nicht geparst wird, sodass ein halb-gestreamtes Diagramm nie einen Fehler anzeigt.

- **Antworten, Codeblöcke und Tabellen können kopiert werden.** Jede Antwort hat eine Copy-as-Markdown-Aktion, Codeblöcke tragen einen Header mit ihrer Sprache, und Tabellen bieten Copy-as-Markdown plus einen CSV-Download (UTF-8, öffnet sich sauber in Excel).

- **Zitate zeigen, aus welchem Dokument sie stammen.** Ein Zitat-Marker wird jetzt als Pill mit dem Dokumentnamen der Quelle gerendert, wobei benachbarte Marker in einer Pill zusammengefasst und gezählt werden; das Popover listet jede Quelle dahinter auf.

- **`/clear` funktioniert in der Chat-Eingabe.** Die Eingabe von `/clear` startet ein neues Gespräch, identisch mit dem Klick auf „Neuer Chat"; eine laufende Runde wird zuerst gestoppt.

- **Diagramme und Codeblöcke können heruntergeladen werden, nicht nur kopiert.** Mermaid-Diagramme exportieren das gerenderte SVG, und jeder Codeblock wird mit einem Dateinamen heruntergeladen, der seiner Sprache entspricht; ein `csv`-Block wird als UTF-8-Datei heruntergeladen, die sich sauber in Excel öffnet.

### Behoben

- **Exa-Dokumentation nennt Exa nicht mehr den Standard-Suchanbieter.** Integrations- und Umgebungsvariablen-Seiten beschreiben Exa jetzt als optionales Backend, das Sie mit `WEB_SEARCH_PROVIDER=exa` aktivieren; der Standard-Suchpfad bleibt Jina.

- **Sidebar-Logo ist wieder ein echter Link.** Mittlerer Klick und Cmd/Strg-Klick öffnen das Dashboard in einem neuen Tab; Linksklick navigiert weiterhin und behält die kurze Bounce-Animation bei.

### Geändert

- **Die Seitenleiste stellt Navigation an erste Stelle.** Die Modulnavigation sitzt über der Gesprächsliste als kompakte durchgehende Liste (ohne Build / Resources / Operate Abschnittsbeschriftungen), mit engerer Abstände bei Navigationselementen, Neuer Chat / Suche und Gesprächszeilen, anstatt in einem Dock am unteren Ende der Seitenleiste versteckt zu sein.

- **Gestreamte Antworten werden gleichmäßig gerendert statt zu flackern.** Eine wachsende Antwort wird nun Block für Block gerendert: fertige Blöcke bleiben stabil, anstatt bei jedem Frame neu zu rendern, und unvollständige Formatierung (Fettdruck, Links, Mathematik) wird abgeschlossen oder gehalten, bis sie vollständig gestreamt ist.

- **Endgültige Antworten werden gestreamt, während sie geschrieben werden.** Der Agent signalisiert nun, wenn er mit dem Sammeln fertig ist, und schreibt die Antwort als Live-gestreamten Turn, sodass lange Antworten Token für Token mit vollständigen Details ankommen, anstatt nach einer Wartezeit erneut abgespielt zu werden. `REACT_FINISH_SIGNAL=false` stellt das vorherige Verhalten wieder her.

- **Architektur-Docs ordnen Graph-Engineering FIM One zu.** [Planning Landscape](/architecture/planning-landscape) erklärt Loop- vs. Graph-Engineering, wie sich das von klassischen visuellen Workflows unterscheidet, wie es sich auf Workflow / DAG / ReAct abbildet, und was für jede Engine übernommen werden sollte. Es besagt auch die aktuelle Tatsache, dass jeder DAG-Schritt bereits ein vollständiger ReAct-Agent ist (kein One-Shot-LLM-Aufruf). ReAct- und DAG-Engine-Seiten verlinken darauf.

- **Einfache Chats bieten immer Folgefragen an.** Gespräche ohne gebundenen Agent erhalten nach jeder Antwort vorgeschlagene nächste Fragen; an Agents gebundene Chats erfordern weiterhin den Pro-Agent-Schalter Folgefragen (standardmäßig aus). Abschluss-Turns wie Grüße oder Dankbarkeit können keine Chips zurückgeben.

- **Eine neu gesendete Nachricht startet oben auf dem Bildschirm.** Das Transkript behält gerade genug Platz unter dem aktuellen Turn, damit seine erste Zeile die Oberseite erreicht, sodass die Frage in Sicht bleibt und die Antwort in den Platz darunter wächst, anstatt dass der gesamte Turn an der unteren Kante klebt. Der Platz verschwindet, sobald der Turn einen Bildschirm übersteigt.

- **Reasoning-Blöcke bleiben während eines Turns eingeklappt.** Reasoning in sowohl ReAct- als auch DAG-Ausgabe zeigt nun standardmäßig eine einzeilige Vorschau, anstatt beim Streamen zu erweitern, wodurch das Ergebnis in Sicht bleibt; klicken Sie auf einen beliebigen Block, um die vollständige Trace zu lesen.

- **Exportierte PDF- und Word-Dateien sind ordnungsgemäß für Chinesisch gesetzt.** Der PDF-Export bettet nun eine echte CJK-Schriftart ein, anstatt auf eine zu verweisen, was den zusammengefallenen Abstand in englischem Text und Aufzählungszeichen behebt, die als nicht verwandte chinesische Zeichen gerendert wurden, und Fettdruck funktioniert nun. Word-Exporte deklarieren eine ostasiatische Schriftart, sodass gemischter chinesisch/englischer Fetttext nicht mehr halb-fett herauskommt, und beide Formate verwenden eine fünfstufige Größenskala, die Überschriften in einer Antwort der Struktur des Transkripts selbst unterordnet.

- **Agents bleiben bei langen Aufgaben im Plan.** Der Agent wird nun daran erinnert, seinen Ansatz zu ändern, wenn er dasselbe Tool fruchtlos wiederholt, wird angestoßen, einen Plan zu schreiben, wenn er ohne einen arbeitet, und kann keine endgültige Antwort liefern, während noch Planelemente offen sind, ohne einen expliziten Verifikationsdurchlauf.

- **Gestreamte Antworten fahren sanft ein, anstatt zu erscheinen.** Neu angekommene Blöcke verblassen kurz, während sie streamen, unter Beachtung der Einstellung für reduzierte Bewegung des Lesers. Lange Tabellen heben auch die Zeile unter dem Cursor hervor, und Listenaufzählungszeichen sitzen hinter dem Text, anstatt damit zu konkurrieren.

- **Block-Aktionen bleiben aus dem Weg, bis Sie danach greifen.** Kopieren und Herunterladen auf Antworten, Code-Blöcken, Diagrammen und Tabellen sind nur Symbole mit Tooltips (Herunterladen immer ganz rechts), sichtbar beim Hovern, und bleiben über die Tastatur erreichbar.

- **Die Seitenleiste hält nun Chats zusammen.** Die Gesprächsliste sitzt direkt unter Neuer Chat und Suche, und die Modulnavigation wurde in ein kompaktes getöntes Dock über dem Benutzerbereich verschoben, was der Liste mehr Platz gibt und der Seitenleiste eine klare von oben nach unten Hierarchie verleiht.

- **Reasoning ist standardmäßig eingeklappt.** Thinking-Abschnitte in sowohl Live-Läufen als auch vergangenen Gesprächen klappen zu einer einzeiligen Vorschau zusammen und erweitern sich beim Klicken; Reasoning streamt weiterhin offen, während es generiert wird, klappt dann zusammen, wenn der Schritt abgeschlossen ist.

- **Listenseiten fahren ihre Karten sanft ein.** Agents, Connectors, Knowledge Bases, Skills, Workflows, Tools, Conversations, Artifacts und der Markt staffeln ihre Karten beim ersten Laden ein, anstatt alle auf einmal zu erscheinen. Filtern und Paging bleiben sofort, sodass das Tippen in ein Suchfeld die Eingabe nie erneut abspielt.

### Sicherheit

- **Rohes HTML in gerendertem Markdown wird jetzt bereinigt.** Modellausgaben und hochgeladene Markdown-Dateien werden vor der Anzeige bereinigt, sodass injizierte Skripte, Event-Handler, iframes, Formulare und Style-Overrides nicht mehr auf die Seite gelangen können. Mathematik, Syntax-Highlighting, Tabellen, Task-Listen und Disclosure-Blöcke sind nicht betroffen. Rohes Inline-`<svg>` wird nicht mehr gerendert; verwenden Sie stattdessen einen `svg`-Code-Block.

### Behoben

- **GPT-5.x-Agenten führen Tools mit aktiviertem Reasoning aus, statt einen Fehler zu werfen.** GPT-5.x-Modelle durchlaufen jetzt zuerst die Responses API, wo Function Tools und Reasoning zusammenarbeiten; Endpunkte ohne eine `/v1/responses`-Route fallen automatisch auf Chat Completions zurück, wobei GPT-5.x-Tool-Aufrufe explizit Reasoning deaktivieren, da diese API dies erfordert. Andere Modellfamilien auf OpenAI-kompatiblen Endpunkten behalten ihren bestehenden Chat-Completions-Pfad.

- **Ask-first-Anfragen werden im Planner-Modus in einer Runde abgeschlossen.** Ein Ziel, das den Agenten explizit auffordert, Anforderungen mit Multiple-Choice-Fragen zu klären, bevor er liefert, erzeugt jetzt einen sauberen Fragebogen als Ergebnis der Runde, anstatt Planungsschritte, die auf Antworten warten, durch Neuplanungen zu schleifen und mit „Ziel nicht erreicht" plus wiederholten Fragenlisten zu enden. Der Auto-Modus leitet solche Anfragen an den Standard-Modus weiter.

- **Follow-up-Chips ziehen das Transkript nicht mehr über die Antwort hinaus.** Nachdem eine Runde beim Ergebnis parkt, bleibt das spätere Layout-Wachstum (Vorschläge, Titel) an Ort und Stelle, und das Falten der Live-Runde in die Historie parkt wieder am Anfang der Antwort für dieselbe Konversation, statt zum Ende zu springen.

- **Das Öffnen einer bestehenden Konversation landet bei den neuesten Nachrichten.** Das Aktualisieren einer Chat-URL scrollt jetzt nach unten wie beim Wechsel aus der Seitenleiste, statt oben im Thread zu beginnen.

- **Schnelle Antworten sehen nicht mehr fest auf „Verarbeitung…" aus.** Eine abgeschlossene Runde ohne generierten Schrittitel zeigt das Gedankenprozess-Label statt des Live-Verarbeitungs-Shimmer-Textes.

- **Animation folgt jetzt der Systemeinstellung „Bewegung reduzieren".** Der driftende Gradient des Login-Hintergrunds, der Hero-Eingang, der atmende injizierte Nachrichtentext und die Streaming-Einfügemarke bewegten sich weiter, unabhängig von der Betriebssystemeinstellung. Sie bleiben jetzt stehen, während die Indikatoren, die laufende Arbeiten melden, sichtbar bleiben, damit die Oberfläche nie steckengeblieben aussieht.

- **Der Ausführungsmodus-Selector bleibt geschlossen, während eine Runde läuft.** Der Chip war ausgegraut, öffnete aber sein Menü trotzdem beim Klick, anders als der Agenten-Selector daneben; beide sind jetzt inaktiv, bis der Durchlauf beendet ist.

- **Reasoning-Streams funktionieren wieder bei neueren Modellen.** Live Reasoning war aus einer hartcodierten Liste von Modellnamen verdrahtet, also zeigte alles, das nach dieser Liste veröffentlicht wurde, einen Spinner und dann den ganzen Reasoning-Block auf einmal. Jedes Modell, das Reasoning ausgibt, streamt es jetzt.

- **Die Chat-Ansicht hält mit schneller Ausgabe Schritt und landet bei der Antwort.** Sie steckt nicht mehr mitten im Reasoning fest und meldet falsch neue Inhalte darunter, sie folgt Inhalten, die ohne neue Events wachsen, und wenn eine Runde beendet ist, bleibt sie oben im Ergebnis statt unten. Wegscrolling gibt die Kontrolle immer noch zurück, und die Rückkehr nach unten setzt das Folgen fort.

- **Eine kurze Antwort bleibt dort, wo Sie sie nach Ende der Runde gelesen haben.** Sobald eine Runde beendet war, rutschte das Transkript nach unten, sodass Frage und Antwort die Eingabebox umarmten; die Antwort behält jetzt ihre Position oben in der Ansicht, bis die nächste Nachricht gesendet wird.

- **Das Anmelden wendet die bevorzugte Sprache des Kontos sofort an.** Das Locale-Cookie wird jetzt während der Anmeldung und des OAuth-Callbacks synchronisiert, und die Startseite wird neu geladen, wenn sich die Sprache des Kontos von der unterscheidet, in der die Anmeldeseite gerendert wurde, sodass das Ziel nicht mehr bis zur nächsten Neuladung in der vorherigen Sprache angezeigt wird.

- **Cmd+K öffnet die Suche auch, wenn die Seitenleiste eingeklappt ist.** Der Shortcut-Listener blieb aktiv, aber sein Dialog wurde im eingeklappten Zustand nie bereitgestellt, sodass der Shortcut stillschweigend nichts tat.

- **Zitate nennen wieder das Dokument, aus dem sie stammen.** Im einfachen Abrufmodus war jede Quelle mit „Knowledge Base" gekennzeichnet, weil das Abruftool den Ursprungsdateinamen fallen ließ; es meldet jetzt die Quelle und entspricht dem, was die Grounding-Pipeline bereits tat.

- **Lange Konversationen treffen weniger wahrscheinlich auf harte Kontextüberlauffehler.** Komprimierung wird jetzt mit einem Sicherheitsabstand unter dem Eingabelimit des Modells ausgelöst, statt genau darauf, und der Start protokolliert eine Warnung, wenn das Fenster des schnellen Modells zu klein ist, um das Kontextbudget des allgemeinen Modells zu halten.

- **SVG-Abbildungen bleiben im dunklen Modus lesbar.** Von Modellen erstellte SVGs gehen von einer hellen Leinwand aus, daher werden Abbildungen auf einer festen hellen Oberfläche gezeichnet, statt dunkel-auf-dunkel zu werden.

- **Der Browser-Tab-Beschäftigungsindikator verschwindet nicht mehr mitten in einer Runde.** Während eine Runde läuft, behält das Tab-Symbol die App-Markierung und pulsiert sie zwischen voller Farbe und Grau, hält während des gesamten Durchlaufs und stellt das echte Symbol zuverlässig wieder her, wenn die Runde endet, auch nach In-App-Navigation. Mit reduzierter Bewegung hält es eine statische graue Markierung statt zu animieren.

- **Agenten rufen einen Endpunkt nicht mehr Dutzende Male nach einem abgeschnittenen Ergebnis ab.** Abschneidungshinweise führen jetzt mit einem imperativen Zeiger auf die gespeicherte vollständige Kopie an, und ein Agent, der denselben Endpunkt immer wieder mit unterschiedlichen Parametern hämmert, wird gewarnt und dann hart gestoppt.

- **Ein abgestürzter Durchlauf meldet jetzt einen Fehler statt eines grünen „Fertig".** Wenn der Agent wegen eines internen Fehlers stoppte, wurde der rohe Ausnahmtext als Antwort unter einem Erfolgs-Häkchen geliefert; Fehler durchlaufen jetzt den Fehlerkanal und erscheinen als Fehlerbenachrichtigung.

- **Das Wiederverbinden mit einem Stream spielt Ausgaben, die Sie bereits gesehen haben, nicht mehr ab.** Der Live-Stream trägt jetzt denselben Positionscursor wie der Resume-Endpunkt, sodass nach einer unterbrochenen Verbindung nur die verpassten Events statt des gesamten Durchlaufs abgespielt werden.

- **Gestreamte Events, die über Netzwerk-Chunks aufgeteilt sind, gehen nicht mehr verloren.** Ein fortgesetzter Stream konnte ein Event verlieren, dessen Frame in zwei Teilen ankam; beide Stream-Pfade teilen sich jetzt einen Parser, der beliebige Chunk-Grenzen verarbeitet.

- **Das Aufrufen eines anderen Agenten gibt seine tatsächliche Antwort zurück.** Die Antwort des Sub-Agenten kam früher in einer rohen Ausführungsverfolgung begraben an, was den Kontext des aufrufenden Agenten überschwemmte; er erhält jetzt nur die Antwort.

- **Ein hängender Tool kann einen Durchlauf nicht mehr unbegrenzt steckenbleiben lassen.** Jeder Tool-Aufruf hat jetzt ein Wanduhrzeitlimit (Standard 180s), sodass ein steckengebliebener Connector oder nicht reagierender Server den Schritt mit einer klaren Nachricht beendet, statt die Runde zu verkeilen.

- **Ein Agent, der denselben Tool-Aufruf wiederholt, wird jetzt früh gestoppt.** Identische wiederholte Aufrufe werden nach ein paar Versuchen verweigert, statt das gesamte Iterationsbudget zu verbrennen.

- **Lange Konversationen verlieren ihren früheren Kontext nach Komprimierung nicht mehr.** Die Zusammenfassung, die ältere Runden verdichtet, wurde beim nächsten Durchlauf stillschweigend gelöscht; sie wird jetzt weitergeleitet, sodass der Agent behält, was vorher besprochen wurde.

- **Große Tool-Ergebnisse behalten ihr Ende sowie ihren Anfang.** Wenn ein langes Ergebnis gekürzt wird, um in das Kontextfenster zu passen, werden jetzt beide Enden beibehalten (das Ende einer Befehlsausgabe ist normalerweise am wichtigsten), die Kürzung berücksichtigt korrekt nicht-lateinischen Text, und spätere Ergebnisse erhalten ein Mindestfenster statt vollständig gelöscht zu werden.

- **Dieselbe generierte Datei wird nicht mehr als zwei Downloads angezeigt.** Eine gerenderte HTML-Ausgabe, die später unter einem echten Dateinamen gespeichert wurde, erzeugte früher zwei Lieferkarten mit identischem Inhalt; Duplikate werden jetzt nach Inhalt erkannt und in die speziell benannte Datei zusammengefasst.

- **Interne Offload-Dateien können nicht mehr als herunterladbare Liefergüter angezeigt werden.** Mit Tools, die ein Dateisystem teilen, konnte eine große Tool-Ausgabe, die während eines Code-Ausführungsdurchlaufs offloaded wurde, vom Artefakt-Scan aufgegriffen und als gefälschte Download-Karte angezeigt werden. Runtime-Buchführungsdateien werden jetzt von der Artefakt-Erkennung ausgeschlossen.

- **Jedes Tool in einer Konversation funktioniert jetzt auf einem gemeinsamen Dateisystem.** Offloadete große Ausgaben landeten früher in einem Verzeichnis, das nur die Workspace-Lese-Tools sehen konnten, während `file_ops`, `shell_exec` und `python_exec` anderswo operierten — der Agent würde eine Datei auflisten, dann wird ihm gesagt, dass sie nicht existiert, und verbrennt sein Iterationsbudget bei der Suche danach. Offloadete Dateien befinden sich jetzt in der Konversations-Sandbox, die jedes Tool (einschließlich Exec-Container) bereitstellt; Dateien aus älteren Konversationen bleiben lesbar.

- **Das Lesen einer großen offloadeten Datei erzeugt nicht mehr eine endlose Kette von Zeigerdateien.** Die Ausgabe eines Workspace-Lesevorgangs konnte selbst die Offload-Schwelle überschreiten und als neue Datei gespeichert werden, die auf Inhalte zeigt, die bereits auf der Festplatte waren, was den Agenten in Kreise schickt. Workspace-Lesevorgänge werden jetzt mit einer exakten Resume-Zeile begrenzt, statt erneut offloaded zu werden.

- **DeepSeeks improvisierter Tool-Call-Text leckt nicht mehr in Antworten.** Wenn ein DeepSeek-Modell einen Tool-Aufruf als einfachen `<｜｜DSML｜｜Tool call: ...`-Text schrieb, statt den Function-Calling-Kanal zu verwenden, erreichte das rohe Markup den Chat wörtlich. Es wird jetzt wie andere Tool-Call-Pseudo-Protokolle entfernt.

- **Ein Tool-Aufruf, der durch das Ausgabelimit des Modells abgeschnitten wird, wird nicht mehr als abgeschlossene Arbeit übergeben.** Wenn eine lange Nutzlast (z. B. das Schreiben einer vollständigen HTML-Seite) das Ausgabebudget mitten im Aufruf erschöpfte, wurde der halb geschriebene Aufruf stillschweigend gelöscht und der einleitende Text des Agenten — „jetzt speichere ich die Datei" — wurde zum Schrittergebnis, sodass ein Schritt, der nichts produzierte, als abgeschlossen gemeldet wurde. Die Kürzung wird jetzt erkannt, und dem Agenten wird mitgeteilt, dass er es mit aufgeteilter Arbeit in kleinere Aufrufe erneut versuchen soll.

- **Ein Ziel, das der Agent sicher verpasst hat, wird jetzt erneut versucht, statt den Durchlauf zu beenden.** Die Neuplanung stoppte, wann immer der Analyzer sicher war, was ein sicheres „die Liefergut fehlt" als Grund zum Aufgeben las — genau der Fall, für den die Neuplanung existiert. Durchläufe stoppen jetzt früh nur, wenn das Ziel als wirklich unerreichbar beurteilt wird, und `DAG_MAX_REPLAN_ROUNDS` begrenzt den Rest.

- **Die Selbstprüfung des Agenten wird nicht mehr als Antwort angezeigt.** Nach der Verwendung mehrerer Tools führt der Agent eine einmalige interne Überprüfung durch, bevor er antwortet; diese Überprüfung wurde wörtlich zu Ihnen gestreamt, sodass Antworten als „Lassen Sie mich überprüfen: 1. Vollständig adressiert? ✅ …" statt der Antwort selbst ankamen. Die Überprüfung ist jetzt intern, und die Antwort, die Sie sehen, wird als eigener Schritt geschrieben.

- **Die Refresh-Token-Rotation invalidiert jetzt tatsächlich den vorherigen Token.** JWT `exp` hat nur Sekundengenauigkeit, sodass zwei Refresh-Tokens, die für denselben Benutzer in derselben Sekunde ausgegeben wurden, früher identisch codiert wurden — die Rotation schrieb dann den gespeicherten Hash mit demselben Wert um, und ein gestohlener Refresh-Token konnte für immer erneuert werden. Jeder Refresh-Token trägt jetzt eine eindeutige `jti`, sodass sich der rotierte Token unterscheidet und der alte sofort nicht mehr funktioniert.

- **Approval Gates halten jetzt, wenn ein Agent über einen anderen Agenten oder einen Workflow erreicht wird.** Ein sensibler Connector-Aufruf, der in Chat um Bestätigung fragen würde, lief früher ungeprüft, sob

### Entfernt

- **README Star History-Diagramm und sein Aktualisierungs-Workflow.** Nachdem GitHub die Stargazers-API eingeschränkt hat (Jul 2026), erforderte die Verwaltung eines eigenen Diagramms ein langlebiges Admin-PAT, das ständig ablief und den geplanten Job zum Fehlschlag brachte. Das Diagramm, SVG-Assets, Generator-Skript und der `Star History` GitHub Actions-Workflow sind entfernt.

- **Wissensdatenbanken, die zuvor für eine Organisation freigegeben waren, werden bei einem Upgrade zurückgerufen.** Die v0.8.9-Ausnahmeregelung, die bereits veröffentlichte KBs für ihre Abonnenten erreichbar hielt, ist entfernt: Jede freigegebene KB wird auf persönlich zurückgesetzt, ihre Abonnements werden entfernt, und die verbleibende Unpublish-Aktion und die KB-Badges für Abonnenten verschwinden. Eine Wissensdatenbank erreicht andere Benutzer jetzt nur noch über einen freigegebenen Agent, der den Inhalt des Eigentümers zur Laufzeit delegiert.

## [v0.8.9] - 2026-07-08

### Hinzugefügt

- **Skills und Workflows sind jetzt optionale Module, standardmäßig deaktiviert.** Eine neue Installation startet nur mit dem Kern (Chat, Agents, Knowledge Bases, Connectors); ein Admin aktiviert Skills und/oder Workflows über Admin → Settings → Modules. Während ein Modul deaktiviert ist, ist es in der Navigation und seinen Seiten verborgen, seine APIs, Market-Einträge und Trigger sind nicht verfügbar — nichts wird gelöscht, und alles wird wiederhergestellt, wenn es wieder aktiviert wird.

- **DAG-Neuplanungen wiederholen keine abgeschlossenen Arbeiten mehr, und unterbrochene Läufe werden dort fortgesetzt, wo sie unterbrochen wurden.** Wenn ein Plan überarbeitet werden muss, werden bereits abgeschlossene Schritte mit ihren Ergebnissen in den neuen Plan übernommen — nur die verbleibende Arbeit wird neu geplant und ausgeführt. Der Schrittfortschritt wird auch während der Ausführung gespeichert, sodass bei einer Unterbrechung während der Ausführung (Absturz, Bereitstellung, unterbrochene Verbindung) das erneute Versuchen derselben Anfrage bei den abgeschlossenen Schritten fortgesetzt wird, anstatt von vorne zu beginnen.

- **Langsame Tools können jetzt im Hintergrund ausgeführt werden, ohne den Agent zu blockieren.** Die Sandbox-Code-Ausführung (Python/Shell/Node) bietet eine `run_in_background`-Option: Der Agent erhält sofort eine Task-ID, arbeitet an anderen Schritten weiter und erhält das Ergebnis als Benachrichtigung, wenn das Tool fertig ist. Wenn der Agent versucht, abzuschließen, während noch Tasks ausgeführt werden, wartet er darauf (begrenzt) und berücksichtigt ihre Ergebnisse vor der Antwort.

- **Konversationsverlauf wird vor der Komprimierung gespeichert, und durch das Budget gekürzte Tool-Ergebnisse werden im Workspace gespeichert.** Bevor die Komprimierung langer Konversationen den Verlauf durch eine Zusammenfassung ersetzt, wird das vollständige Transkript als JSONL-Datei in den Konversations-Workspace geschrieben; ebenso wird ein Tool-Ergebnis, das durch das aggregierte Token-Budget gekürzt wird, vollständig im Workspace gespeichert, mit einem Zeiger an Ort und Stelle — in beiden Fällen können der Agent (und Sie) das Original zurücklesen, anstatt es zu verlieren.

- **Antworten enden nicht mehr mitten im Satz, wenn das Modell sein Ausgabelimit erreicht.** Wenn eine Antwort durch das Output-Token-Limit des Providers gekürzt wird, fragt der Agent das Modell automatisch auf, wo es aufgehört hat (bis zu 3 Runden), und verbindet die Segmente zu einer nahtlosen Antwort — sowohl in der Reasoning-Schleife als auch in der gestreamten endgültigen Antwort.

- **LLM-Aufrufe werden jetzt bei Provider-Überlastung (HTTP 529) und Gateway-Timeout (504) erneut versucht und beachten `Retry-After`.** Zuvor führte ein 529 von Anthropic sofort zum Fehler der Anfrage, es sei denn, ein Fallback-Modell war konfiguriert; jetzt wird es zurückgefahren und erneut versucht wie 429/5xx, und wartet genau so lange, wie der Provider fragt, wenn ein `Retry-After`-Header vorhanden ist.

- **Agents behalten jetzt während mehrstufiger Aufgaben einen sichtbaren Plan.** ReAct-Agents erhalten ein `update_plan`-Tool, um ihren Plan als Todo-Checkliste aufzuschreiben und ihn während des Fortschritts zu aktualisieren; wenn der Plan nach mehreren Tool-Aufrufen veraltet wird, wird die vollständige Checkliste als Erinnerung erneut eingefügt — damit lange Aufgaben auch nach Kontext-Komprimierung zielgerichtet bleiben. Standardmäßig aktiviert (`REACT_PLAN_TOOL_ENABLED`); DAG-Unterschritte und Tool-lose Agents überspringen dies.

- **Agents können jetzt einen Workflow während einer Konversation ausführen.** Aktive, genehmigungsfreie Workflows, die Sie besitzen oder abonniert haben, werden dem Agent als `run_workflow`-Tool angeboten — im normalen Chat und mit ausgewähltem Agent gleichermaßen — sodass eine Aufgabe einen deterministischen, wiederholbaren Unterprozess an einen Workflow übergeben und seine Ausgaben zurückbekommen kann. Jeder solche Lauf wird in der Laufhistorie des Workflows aufgezeichnet, und seine Token-Nutzung wird gegen das Kontingent des Workflow-Eigentümers angerechnet (der Lauf wird abgelehnt, wenn der Eigentümer bereits über Kontingent ist). Workflows mit einem Human Intervention-Schritt bleiben nur auslösbar (von der Workflows-Seite oder ihrem API-Schlüssel), da sie lange blockieren können.

- **Zwei neue Workflow-Starter-Vorlagen: Connector Action und MCP Tool Call.** Der Katalog "Create from Template" präsentiert jetzt die Connector- und MCP-Knoten — rufen Sie ein externes System oder ein MCP-Tool auf, fassen Sie das Ergebnis dann mit einem LLM zusammen. Wählen Sie den spezifischen Connector/Server nach der Erstellung aus.

### Geändert

- **Wissensdatenbanken sind nicht mehr freigegeben.** Das Veröffentlichen einer Wissensdatenbank für eine Organisation oder den Marktplatz wurde entfernt; eine KB erreicht andere Personen nur, indem sie an einen freigegebenen Agent gebunden wird, der den Inhalt des Eigentümers zur Laufzeit delegiert. Jede bereits veröffentlichte Wissensdatenbank bleibt für ihre aktuellen Abonnenten erreichbar und kann über das Menü auf persönlich zurückgesetzt werden.
- **Connectors und MCP-Server geben die Anmeldedaten des Eigentümers standardmäßig nicht mehr frei (Breaking Change).** "Fallback auf die Anmeldedaten des Eigentümers zulassen" ist jetzt optional: neue Connectors/MCP-Server werden damit deaktiviert erstellt, und alle vorhandenen wurden ebenfalls deaktiviert. Ein Abonnent, der sich auf das Token des Eigentümers verlassen hat, um einen freigegebenen Connector oder MCP-Server zu nutzen, muss jetzt seine eigenen Anmeldedaten hinzufügen, oder der Eigentümer muss den Fallback für diese Ressource erneut aktivieren. Eigentümer können immer ihre eigenen Anmeldedaten verwenden, unabhängig von dieser Einstellung. Infolgedessen ist ein Connector, dessen Fallback deaktiviert ist und für den Sie keine Anmeldedaten haben, jetzt aus dem Toolset des Agenten ausgeblendet (wie MCP-Server bereits verhalten), anstatt angeboten zu werden und dann beim Aufrufen fehlzuschlagen.
- **Neue Agenten verwenden standardmäßig ReAct-Ausführung statt Auto.** Der Auto-Modus führte einen zusätzlichen schnellen Modellklassifizierungsaufruf pro Anfrage durch, um zwischen ReAct und DAG zu entscheiden; neue Agenten (und die integrierten/Marketplace-Vorlagen) verwenden jetzt standardmäßig ReAct, wodurch diese Pro-Nachricht-Latenz und Kosten entfallen. Auto und DAG bleiben pro Agent wählbar; vorhandene Agenten behalten ihren aktuellen Modus.
- **KI-Agent-Erstellung erholt sich von einem schwachen schnellen Modell.** Das Erstellen oder Verfeinern eines Agenten aus einer natürlichsprachigen Anweisung wird auf dem schnellen Modell ausgeführt; wenn es keine gültige Konfiguration erzeugen kann, wird die Anfrage jetzt einmal auf dem stärkeren allgemeinen Modell wiederholt, bevor ein Fehler auftritt, sodass ein zu schwaches schnelles Modell nicht mehr als Fehler für den Benutzer angezeigt wird.

### Entfernt

- **Der visuelle Workflow-Builder wurde auf 9 Kernknotentypen reduziert.** Sechzehn selten verwendete Utility- und Kontrollfluss-Knoten — Umgebungsvariablen, HTTP-Anfrage, Code-Ausführung, Iterator/Schleife, Sub-Workflow, Template/List/Transform-Helfer sowie Parameter/Frage-Extraktoren und Klassifizierer — wurden entfernt, damit sich der Builder auf die Orchestrierung von Agenten, Konnektoren, MCP-Servern und Knowledge Bases konzentriert. Als Nebeneffekt enthält ein freigegebener Workflow keine eingebetteten Geheimnisse mehr: Er ist nun rein ein Graph von Referenzen, und jede referenzierte Ressource erzwingt ihren eigenen Benutzerzugriff zur Laufzeit. Bestehende Workflows, die auf einem entfernten Knoten basieren, müssen mit dem verbleibenden Satz neu erstellt werden.

### Sicherheit

- **API-Schlüssel-Bereiche werden nun pro Anfrage übertragen statt an das Benutzerobjekt angehängt.** Dies schließt einen latenten Scope-Verwechslungspfad, bei dem ein gecachter oder in einer Identity-Map geteilter Benutzer den Scope-Satz eines anderen Auth-Kontexts erben könnte.
- **Eine automatisch erstellte `.env`-Datei mit dem generierten JWT-Secret wird nun mit Nur-Eigentümer-Berechtigungen (0600) geschrieben.** Bereits vorhandene `.env`-Dateien behalten ihre Berechtigungen.
- **Die Kosten für Passwort-Hashing sind nun über `FIM_BCRYPT_COST`** (Standard 12, begrenzt auf bcrypts Bereich 4–31) abstimmbar, damit Operatoren zwischen Hardware und Härtung abwägen können.
- **Datenbankverbindungen können nicht mehr geteilt werden, und ihr Raw-SQL-Tool ist nur für den Eigentümer.** Das Veröffentlichen eines Datenbankverbinders für eine Organisation oder global wird nun abgelehnt, und das Tool für beliebige SQL-Datenbanken wird nur dem Eigentümer des Verbinders angeboten — niemals einem Abonnenten, unabhängig von der Einstellung für das Fallback der Eigentümer-Anmeldedaten. Zuvor exponierte ein geteilter Datenbankverbinder uneingeschränktes SQL über das (typischerweise hochprivilegierte) Datenbankkonto des Eigentümers für jeden, der sich abonnierte, ohne Scoping pro Aufrufer. Der Zugriff auf Datenbanken mit Benutzer-Scoping wird durch eine zukünftige deklarative Aktionsebene zurückkehren.
- **Webhook- und Cron-ausgelöste Workflows werden nun gegen das Token-Kontingent des Eigentümers angerechnet.** Ein unbeaufsichtigter Workflow-Lauf — ausgelöst durch seinen öffentlichen API-Schlüssel oder nach einem Zeitplan — führte früher LLM- und Agent-Schritte aus, ohne die Token-Nutzung zu prüfen oder zu erfassen, ein ungemessener kostenloser LLM-Pfad, der Kontingente vollständig umging. Solche Läufe werden nun vorab gegen das Kontingent des Workflow-Eigentümers gated (ein öffentlicher Trigger wird abgelehnt und ein geplanter Lauf übersprungen, wenn der Eigentümer bereits über Kontingent ist) und ihre Token-Nutzung wird pro Lauf erfasst und gegen das gleiche monatliche Kontingent wie Chat angerechnet.
- **Feishu-Genehmigungskarten erzwingen nun, wer genehmigen darf.** Ein Kartenklik wird nur berücksichtigt, wenn der Klicker sein Feishu-Konto mit einem FIM One-Benutzer verknüpft hat, dem tatsächlich erlaubt ist, unter der Approver-Scope-Einstellung des Agenten zu genehmigen (der Initiator, der Agent-Eigentümer oder ein Organisationsmitglied) — die gleiche Regel, die die In-Portal-Genehmigung bereits anwendete. Zuvor konnte jeder in der Feishu-Gruppe eine ausstehende Aktion genehmigen oder ablehnen, und die Entscheidung wurde ohne Identität erfasst.
- **Feishu-Kanäle erfordern nun einen Verschlüsselungsschlüssel, und Callbacks ohne gültige Signatur werden abgelehnt.** Die Callback-Signaturverifizierung schlägt fehl, wenn kein Verschlüsselungsschlüssel konfiguriert ist (zuvor akzeptierte sie unsignierte Callbacks, sodass jeder, der die Callback-URL eines Kanals erfuhr, eine Genehmigung fälschen konnte), und die verschlüsselte Event-Umschlag, die Feishu sendet, wenn Verschlüsselung aktiviert ist, wird nun entschlüsselt. Neue und bearbeitete Feishu-Kanäle müssen den Verschlüsselungsschlüssel angeben.
- **Genehmigungsanfragen werden nicht mehr an einen unbeabsichtigten Chat weitergeleitet.** Wenn ein Agent keinen Genehmigungskanal explizit konfiguriert hatte, konnte eine ausstehende Genehmigung an den Abschlussbenachrichtigungskanal des Agenten oder, falls nicht vorhanden, an den ersten Kanal der Organisation gepusht werden — wodurch eine Karte mit sensiblen Aktionen einer Gruppe angezeigt wurde, die nie als Genehmiger gewählt wurde. Genehmigungen gehen nun nur an den explizit konfigurierten Genehmigungskanal des Agenten und fallen andernfalls auf In-Portal-Genehmigung zurück.
- **Geteilte MCP-Server und Wissensdatenbanken werden zur Laufzeit erneut auf Zugriff überprüft, nicht nur bei der Bindung.** Ein Workflow-MCP-Schritt, ein gebundener MCP-Server eines Agenten oder eine gebundene Wissensdatenbank eines Agenten wird nun bei jedem Lauf gegen den aktuellen Abonnementstatus verifiziert, sodass der durch Verlassen einer Organisation widerrufene Zugriff sofort wirksam wird, statt durch eine veraltete Bindung bestehen zu bleiben.

### Behoben

- **OAuth-Anmeldung schlägt jetzt schnell mit einer klaren Meldung "Provider hat zu lange gedauert" fehl, wenn GitHub/Google/Discord/Feishu langsam sind**, anstatt bei Standard-Timeouts der Bibliothek zu hängen und einen generischen Fehler anzuzeigen.
- **Der Agent generiert nicht mehr fälschlicherweise ein Bild, wenn er aufgefordert wird, ein HTML-Deliverable umzugestalten, und behauptet niemals, dass eine Datei erstellt wurde, ohne sie tatsächlich in den Workspace zu schreiben.** Die Bildgenerierung ist jetzt explizit auf Rasterbilder beschränkt, und Datei-Deliverables müssen über einen Tool-Aufruf geschrieben werden — das Einfügen von Inhalten im Chat zählt nicht mehr als "Generieren einer Datei".
- **Generierte HTML-Seiten verwenden jetzt standardmäßig eine warme, von Claude inspirierte Farbpalette anstelle des generischen Purple-Gradient-Looks.** Wenn Sie keinen Stil angeben, verwendet der Agent eine warme minimale Grundlage; Ihr eigener Stil gewinnt immer, wenn er angegeben ist.
- **Lange Tool-intensive Konversationen brechen nicht mehr ab, wenn der Verlauf komprimiert wird.** Die Kontext-Komprimierung konnte das beibehaltene Fenster zwischen einem Tool-Aufruf und seinen Ergebnissen unterbrechen und eine Nachrichtensequenz erzeugen, die der LLM-Provider ablehnt (HTTP 400) — genau bei den langen Läufen, die Komprimierung am meisten brauchen. Der Kompressor behält jetzt jeden Tool-Aufruf zusammen mit seinen Ergebnissen auf der beibehaltenen Seite.
- **Hintergrund-Tool-Ergebnisse werden jetzt im Step-Stream und in DAG-Evidenz angezeigt.** Ein Tool-Lauf im Hintergrund lieferte seine echte Ausgabe nur in der internen Benachrichtigungsmeldung des Agenten — die UI-Step-Timeline und die DAG-Antwort-Verifizierungsevidenz sahen nur den Dispatch-Platzhalter. Das geleerte Ergebnis wird jetzt als normales Tool-Completion-Event unter dem echten Tool-Namen ausgegeben.
- **Eine seltene Planner-Ausgabe mit doppelten Step-IDs bricht nicht mehr den gesamten DAG-Turn ab.** Doppelte IDs wurden früher als "Zirkelabhängigkeit"-Fehler fehldiagnostiziert; sie werden jetzt deterministisch umbenannt und der Plan wird fortgesetzt.
- **Mehrere ReAct-Loop-Korrekturen.** Ein Tool, das leere Ausgabe zurückgibt, behielt seine "mit leerer Ausgabe abgeschlossen"-Notiz anstelle eines leeren Ergebnisses, wenn der Workspace aktiviert ist; DAG-Steps, die durch eine nicht erfüllbare Abhängigkeit blockiert sind, geben jetzt ein ordnungsgemäßes Terminal-Event aus, anstatt die UI hängen zu lassen; und für Modelle ohne natives Tool-Calling sieht die Fallback-Antwort-Synthese jetzt die Tool-Ergebnisse, nicht nur die Tool-Aufrufe.
- **Der Conversation-Workspace ist jetzt tatsächlich in den Chat integriert — übergroße Tool-Ergebnisse sind wiederherstellbar anstatt stillschweigend verloren.** Die Workspace-Recovery-Pfade der Agent-Schicht (großer Output-Offload mit einem `workspace://`-Pointer, vollständige Rettung von Budget-gekürzten Tool-Ergebnissen, Pre-Compaction-Transkript-Snapshots) existierten, aber die Chat-Endpoints erstellten niemals einen Workspace, daher liefen sie nie: Sobald das Tool-Result-Budget erschöpft war, erhielt das Modell leere Beobachtungen ohne Möglichkeit, die Daten zurückzulesen, und antwortete aus Vermutungen. ReAct- und DAG-Step-Agenten erhalten jetzt einen Pro-Konversations-Workspace, und das Löschen einer Konversation bereinigt ihre Workspace-Dateien und alle verbleibenden Crash-Resume-Checkpoints.
- **Wiederaufgenommene DAG-Läufe verlieren nicht mehr das Ende langer Step-Ausgaben.** Step-Evidenz, die im Crash-Resume-Checkpoint gespeichert ist, wurde nur am Anfang bei der Größenbegrenzung gekürzt und ließ stillschweigend alles am Ende der Ausgabe fallen — genau dort, wo Schlussfolgerungen, Checksummen und letzte Zeilen zu finden sind. Begrenzte Evidenz behält jetzt sowohl den Anfang als auch das Ende mit einem expliziten Auslassungsmarker dazwischen.
- **Agenten "funktionieren" nicht mehr, indem sie ihre eigenen Notizen durch Python drucken.** Die Effizienzanleitung, die das Schreiben eines umfassenden Scripts pro Tool-Aufruf förderte, ist jetzt auf Aufgaben beschränkt, die echte Code-Ausführung benötigen — Wissensfragen, Vergleiche und Analysen, die das Modell direkt produzieren kann, werden direkt beantwortet, anstatt durch sinnlose Sandbox-Scripts geleitet zu werden.
- **Ein Agent-Step in einem Workflow führt jetzt den vollständigen Agent aus, nicht nur seinen Prompt.** Der Agent-Node eines Workflows wurde früher nur mit den Agent-Anweisungen auf einem generischen Modell und Standard-Toolset ausgeführt — die Connectors, Knowledge Bases, MCP-Server und konfigurierten Modelle des Agenten wurden stillschweigend gelöscht. Er führt jetzt den Agent genau wie im Chat aus, mit allen gebundenen Ressourcen und Modellen, und nur wenn dieser Agent für den Workflow-Besitzer sichtbar ist.
- **Das Verlassen (oder Entfernen aus) einer Organisation widerruft jetzt ihren gemeinsamen Zugriff.** Ressourcen, auf die Sie nur über diese Organisation zugreifen konnten, werden abgemeldet, und die Pro-Benutzer-Connector/MCP-Anmeldedaten, die Sie dafür gespeichert haben, werden gelöscht — sodass Sie diese Ressourcen nicht mehr verwenden oder auf die Anmeldedaten des Besitzers zurückgreifen können. Ressourcen, die Sie über den Market abonniert haben, sind nicht betroffen.
- **Das Löschen eines Kontos entfernt jetzt konsistent alles.** Die Admin-Pfade "Benutzer löschen" und Self-Service "Mein Konto löschen" unterschieden sich früher — jeder bereinigt eine andere Menge von Dateien auf der Festplatte (und beide berechneten ihre Dateipfade falsch, daher verpasste jeder stillschweigend einige), und der Admin-Pfad hinterließ API-Schlüssel, Login-Verlauf, Eval-Daten, Call-Logs und Abonnements. Beide laufen jetzt durch eine Routine, die jeden Datensatz und jede Datei entfernt, und das Löschen schlägt nicht mehr auf Datenbanken fehl, die Fremdschlüssel erzwingen.
- **Ein Benutzer, der immer noch eine Organisation besitzt, kann nicht mehr gelöscht werden.** Die Anfrage wird jetzt mit einer klaren Meldung abgelehnt, um zuerst den Besitz zu übertragen (oder die Organisation zu löschen), anstatt unerwartet zu fehlschlagen oder die Organisation verwaist zu hinterlassen.
- **Das Löschen eines Agenten bricht nicht mehr vergangene Konversationen ab.** Konversationen, die auf den Agenten verwiesen, werden als historische Datensätze beibehalten und haben einfach den Agent-Link gelöscht, anstatt das Löschen zu blockieren.
- **Bestätigungspflichtige Connector-Aktionen können nicht mehr unbeaufsichtigt in einem Workflow ausgeführt werden.** Eine Connector-Aktion, die als Bestätigung erforderlich gekennzeichnet ist, wurde früher in einem Workflow mit der Approval-Gate stillschweigend umgangen ausgeführt. Der Step schlägt jetzt geschlossen fehl mit einer Meldung, einen Human Intervention-Node davor zu platzieren (die Workflow-native Approval-Gate) oder eine Aktion zu verwenden, die keine Bestätigung erfordert.
- **Workflow-Steps leihen sich nicht mehr die MCP-Anmeldedaten des Besitzers.** Wenn ein Workflow's MCP-Server das Fallback für Besitzer-Anmeldedaten deaktiviert hatte, griff ein Nicht-Besitzer, der diesen Workflow ausführte, stillschweigend auf die Server-Anmeldedaten des Besitzers zurück, anstatt gestoppt zu werden. Der Step schlägt jetzt mit einer klaren Meldung fehl, um Ihre eigenen Anmeldedaten zu konfigurieren, was dem Chat-Pfad entspricht.
- **Connector-Aufrufe aus Workflows werden jetzt audit-protokolliert.** Ein Connector-Action, der in einem Workflow ausgeführt wird, hinterließ keinen Eintrag im Connector-Call-Log (nur Chat-initiierte Aufrufe wurden aufgezeichnet); Workflow-Aufrufe schreiben jetzt die gleiche Audit-Trail.
- **Sie können jetzt einen abonnierten Connector, eine Knowledge Base oder einen MCP-Server an einen Agenten anhängen.** Die Bindung erforderte früher, dass Sie die Ressource *besitzen*, daher wurde ein Connector, den Sie legitim abonniert hatten (Org-freigegeben oder Market-installiert), als "nicht besessen" abgelehnt. Die Bindung folgt jetzt der gleichen Sichtbarkeitsregel, die der Rest der App verwendet — alles, was Sie besitzen oder abonniert haben, ist bindbar.
- **Workflow-Steps können nur Connectors aufrufen, auf die Sie tatsächlich Zugriff haben.** Ein Connector-Step eines Workflows konnte früher jeden Connector aufrufen, dessen ID er referenzierte, solange dieser Connector existierte; er erzwingt jetzt die Sichtbarkeit des Ausführenden (besessen oder abonniert), sodass ein gemeinsamer Workflow keinen Connector erreichen kann, auf den Sie keinen Zugriff haben, nur indem er seine ID referenziert.
- **Knowledge-Base-Suche funktioniert jetzt gegen KBs, die Sie abonniert haben, nicht nur solche, die Sie besitzen.** Die Daten einer KB befinden sich unter dem Speicher ihres Besitzers, aber ein Workflow-Knowledge-Base-Step (und Knowledge-Base-Chat ohne Agent) suchte früher unter dem eigenen Speicher des Aufrufers — daher gab die Suche einer mit Ihnen geteilten KB stillschweigend nichts zurück. Der Besitzer wird jetzt aus der KB selbst aufgelöst und die Suche wird zugriffsgeprüft (Besitzer oder Abonnent), daher geben gemeinsame KBs Ergebnisse zurück und KBs, die Sie nicht sehen können, geben nichts zurück, anstatt eines verwirrenden leeren Treffers.
- **Hintergrund-Jobs verschwinden nicht mehr zufällig.** Dokument-Erfassung, Webhook-Zustellung, Eval-Läufe und Post-Response-Benachrichtigungen wurden als Fire-and-Forget-Tasks gestartet, auf die die Runtime nur schwach verwiesen, daher konnten sie unter Last während des Fluges Garbage-collected werden und stillschweigend stoppen. Sie werden jetzt bis zur Fertigstellung gehalten (und ihre Fehler protokolliert), daher beenden sie sich zuverlässig.
- **Große Datei-Uploads blockieren nicht mehr andere Anfragen.** Die Textextraktion aus einem hochgeladenen PDF/DOCX lief synchron auf der Haupt-Event-Loop und fror kurzzeitig alle gleichzeitigen Anfragen ein, während eine große Datei geparst wurde. Die Extraktion wird jetzt auf einen Worker-Thread ausgelagert.
- **Multi-Step (DAG) Antworten misrepräsentieren ihre Quellen nicht mehr.** Wenn ein Plan's Research-Step eine Seite abrief und zusammenfasste, floss nur diese Zusammenfassung weiter — daher konnte eine Quelle, die 11 Elemente auflistete, in der endgültigen Antwort als 6 auftauchen, oder die Schweregrad eines Elements konnte falsch gekennzeichnet werden, und der Goal-Evaluation-Step konnte es nicht fangen, weil er die ursprüngliche Quelle nie sah. Jeder Step behält jetzt seine rohe Tool-Ausgabe als autoritative Quellen-Evidenz, die die endgültige Synthese und der Evaluator gegen die Antwort prüfen, daher stimmen Summen, Aufzählungen und Attribute mit dem überein, was die Quellen tatsächlich sagten (und das Vertrauen sinkt mit einer benannten Diskrepanz, wenn sie nicht übereinstimmen).
- **Der Workflow-LLM-Node zeigt nicht mehr Modell-Steuerelemente an, die nicht das bedeuteten, was sie implizierten.** Er hatte ein hardcodiertes Modell-Dropdown, dessen Auswahl zur Laufzeit ignoriert wurde, plus einen Fast/Main-Tier-Toggle, der ein internes (Auto-Degrading-)Konzept offenlegte. Beide werden entfernt — der Node führt jetzt immer Ihr System-konfiguriertes Modell aus (Model Provider, Fallback auf `.env`), auf die gleiche Weise wie der Playground es auflöst, mit einer einzeiligen Notiz, die darauf verweist, wo das Modell konfiguriert ist.
- **Der Agent-Editor warnt nicht mehr vor ungespeicherten Änderungen, wenn nichts bearbeitet wurde, und das Speichern schlägt nicht mehr mit einem Approver-Scope-Fehler fehl.** Das Öffnen eines Agenten und das Verlassen konnte einen Phantom-Dialog "ungespeicherte Änderungen" auslösen, und das Speichern eines Agenten mit einem Legacy-Approver-Scope-Wert konnte direkt abgelehnt werden — beide verfolgten das gleiche Feld, das inkonsistent gelesen wurde. Der Editor normalisiert diese Felder jetzt beim Laden, daher ist die Dirty-Prüfung genau und ein veralteter gespeicherter Wert wird korrigiert, anstatt zurückgeworfen zu werden.

## [v0.8.8] - 2026-06-22

### Geändert

- **Agents übernehmen Fehler jetzt sauberer.** Wenn ein Tool-Ergebnis etwas widerspricht, das ein Agent gesagt hat, erkennt er es an und korrigiert es in derselben Runde, ohne sich zu viel zu entschuldigen oder die Antwort mit Selbstkritik zu füllen.

### Sicherheit

- **SSRF-Umgehung über IPv4-mapped IPv6-Adressen blockiert.** Eine URL mit einem IPv4-mapped IPv6-Literal als Host (z. B. `http://[::ffff:169.254.169.254]/`) umging die Blocklist für private IPs und konnte auf Dual-Stack-Hosts auf interne Services — einschließlich Cloud-Instanz-Metadaten — zugreifen. Diese Adressen werden nun entpackt und gegen die IPv4-Blocklist geprüft, wodurch die Lücke in allen SSRF-geschützten Pfaden geschlossen wird (Web Fetch, HTTP Tool, Connectors, RAG Importer).
- **MCP SSE / Streamable-HTTP Server-URLs werden nun SSRF-validiert.** Ein authentifizierter Benutzer konnte einen MCP-Server auf eine interne Adresse verweisen und eine Anfrage an ihn auslösen, wenn der Server getestet oder verbunden wurde. Server-URLs werden nun bei der Erstellung/Aktualisierung und erneut beim Verbinden validiert.
- **Docker Compose PostgreSQL-Anmeldedaten sind nun über `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` überschreibbar.** Der zuvor hartcodierte Standard `fim:fim` ist einfach strukturiert (die Verbindungszeichenfolge wird aus denselben Variablen abgeleitet) und dokumentiert mit einer Warnung, ihn vor dem Freigeben der Datenbank zu ändern, sodass Operatoren nicht versehentlich Standard-Admin-Anmeldedaten ausliefern.

### Behoben

- **LLM-Zugriff funktioniert nach Ruhepausen nicht mehr.** Der gemeinsame HTTP-Verbindungspool wurde beim Start installiert und für jeden Modellaufruf wiederverwendet. Nach einer Leerlaufphase konnte der zugrunde liegende Client von außen geschlossen werden, woraufhin jeder LLM-Aufruf mit einem Verbindungsfehler fehlschlug, bis der Dienst neu gestartet wurde. Der Pool wird nun vor jedem Aufruf neu validiert und transparent neu erstellt, sodass sich der Dienst selbst erholt, ohne einen Neustart zu erfordern.
- **Das Senden einer Nachricht in einem Chat wird nun sofort gestreamt, statt zu stocken.** Jeder Versand blockierte zuvor auf einem vollständigen Neuladen des Gesprächsverlaufs, bevor die Antwort beginnen konnte. Bei längeren Chats wirkte das System einen Moment lang eingefroren und lud die gesamte Abschrift bei jedem Durchgang neu. Ein abgeschlossener Durchgang wird nun im Hintergrund in den Verlauf integriert, sodass Versände sofort gestreamt werden und das redundante Neuladen übersprungen wird.
- **Extended Thinking funktioniert nun auf neueren Anthropic-Modellen (Opus 4.6+, Sonnet 4.6, Fable 5).** Diese Modelle haben den alten Parameter für festes Thinking-Budget entfernt — Opus 4.7/4.8 und Fable 5 lehnen ihn mit einem 400-Fehler ab — sodass das Konfigurieren des Reasoning-Aufwands entweder zu Fehlern führte oder stillschweigend nichts tat. Wir senden nun das Adaptive-Thinking-Protokoll für diese Modelle (und verwerfen die Sampling-Parameter, die sie nicht mehr akzeptieren), sodass der Reasoning-Aufwand korrekt wirksam wird. Ein Modell, das Adaptive Thinking nutzt, aber über einen generischen OpenAI-kompatiblen Proxy verbunden ist (wo Thinking nicht aktiviert werden kann), protokolliert nun eine klare Warnung, statt stillschweigend zu fehlschlagen — konfigurieren Sie es als Anthropic-Provider, um Thinking zu aktivieren.
- **Force-Logout vergleicht Zeitstempel nun korrekt auf PostgreSQL.** Die Session-Invalidierungsprüfung nahm an, dass die gespeicherte Invalidierungszeit naiv UTC war, und erzwang sie als solche, was Vergleiche gegen tz-aware Non-UTC-Werte, die PostgreSQL zurückgeben kann, stillschweigend beschädigte. Zeitstempel werden nun durch Konvertierung normalisiert, nicht durch Überschreibung, sodass widerrufene Token auf jedem Backend zuverlässig abgelehnt werden.
- **Enforcement Hooks schlagen nun geschlossen fehl, wenn sie abstürzen.** Ein `PRE_TOOL_USE` Hook (z. B. ein Approval Gate), der eine Ausnahme auslöste, gab zuvor `allow=True` zurück, sodass der blockierte Tool-Aufruf trotzdem fortgesetzt wurde — ein abgestürztes Gate wurde stillschweigend zu einem Bypass. PRE Hooks verweigern nun standardmäßig bei Fehlern; Non-Enforcement Hooks (Rate Limiter, Logger) behalten das alte Fail-Open-Verhalten über ein neues `fail_open` Flag bei.
- **Agent-Antworten verlieren nun nicht mehr die Schlussfolgerungen des Reasoning.** Wenn ein Reasoning-Modell bereits eine endgültige Antwort produziert hatte, führte die Pipeline einen zweiten, verlustbehafteten Syntheseaufruf durch, der die Schlussfolgerungen des Modells verwerfen konnte — und Reasoning-Details gingen weiter verloren, wenn Gespräche komprimiert, gegen das Kontextlimit geschützt oder durch mehrstufige Pläne geroutet wurden. Die Schleife streamt nun ihre echte endgültige Antwort wörtlich, und Reasoning wird durch Komprimierung, Kontextwiederaufbau und Sub-Agent-Schritte beibehalten, sodass die Antwort, die Sie sehen, die vollständige Gedankenkette widerspiegelt, statt einer verwässerten Umformulierung.

Bezahlte Nutzer konnten am 20. abgerechnet werden, mussten aber bis zum 1. auf ein neues Kontingent warten – und ein Abonnement, das spät im Monat begonnen wurde, gewährte effektiv wenige Tage später ein zweites volles Kontingent. Das Kontingent wird jetzt am monatlichen Jahrestag jedes Abonnements zurückgesetzt (kostenlose Nutzer werden weiterhin am Kalendermonat zurückgesetzt). Jährlich abgerechnete Pläne werden korrekt jeden Monat aufgefüllt, nicht nur einmal im Jahr. Die Registerkarte „Plan & Abrechnung", die Nutzungskarte und der Dialog „Kontingent überschritten" messen die Nutzung und zeigen das Zurücksetzdatum über dieses gleiche Zeitfenster an, sodass die angezeigte „Nutzung in diesem Zeitraum" dem Punkt entspricht, an dem der Chat Sie tatsächlich stoppt.
- **Abonnementverlängerungen verschieben jetzt den Abrechnungszeitraum.** Bei der automatischen Verlängerung blieb das angezeigte Enddatum des Zeitraums beim vorherigen Zyklus stehen, obwohl Stripe abgerechnet und das Abonnement vorwärts gerollt hatte – der Verlängerungshandler las den neuen Zeitraum nur aus der Rechnungs-Payload, wo er unzuverlässig ist. Er ruft jetzt die maßgeblichen Zeitraumgrenzen von Stripe ab, sodass das Zyklus-Enddatum (und das Kontingent-Zurücksetzen) bei jeder Verlängerung vorwärts rücken. Dies beseitigt auch ein latentes Risiko, bei dem das Kündigen eines solchen Abonnements das Konto sofort statt am echten Zeitraumende herabstufen könnte.
- **Rohes Tool-Call-Protokoll leckt nicht mehr in Agent-Antworten.** Wenn ein Modell einen Tool-Call als Klartext improvisiert (z. B. durch Ausgabe von `<tool_call>`/`<tool_response>` Blöcken – häufig, wenn es nach einem nicht verfügbaren Tool greift), konnte dieser Text – einschließlich aller Base64/Datei-Dumps darin – wörtlich in der Antwort auftauchen. Alle Antwortpfade entfernen jetzt dieses Pseudo-Protokoll, und der Parser erkennt zusätzlich den `{"name","arguments"}` Dialekt als echten Tool-Call statt ihn zu lecken.
- **Intermittierende `APIConnectionError: Connection error` Ausbrüche während Agent-Durchläufen.** Der gemeinsame HTTP-Verbindungspool behielt Idle-Keep-Alive-Verbindungen bis zu 30 s; wenn ein vorgelagertes Relay oder NAT eine Idle-Verbindung stillschweigend aufräumte, wiederverwendete die nächste Anfrage den halb-toten Socket und schlug fehl. Die Keep-Alive-Ablaufzeit beträgt jetzt standardmäßig kurz 5 s (warme Verbindungen innerhalb eines Durchlaufs werden weiterhin wiederverwendet), und der Pool ist über `LLM_HTTP_MAX_CONNECTIONS` / `LLM_HTTP_MAX_KEEPALIVE` / `LLM_HTTP_KEEPALIVE_EXPIRY` abstimmbar – setzen Sie `LLM_HTTP_MAX_KEEPALIVE=0`, um die Verbindungswiederverwendung hinter einem unzuverlässigen vorgelagerten System vollständig zu deaktivieren.
- **API-Schlüssel-Nutzungsstatistiken (`total_requests`, `last_used_at`) werden jetzt bei jeder Anfrage beibehalten.** Zuvor wurde die Erhöhung in der Datenbanksitzung der Anfrage geschrieben, die nur von Endpunkten committed wird, die ihre eigenen Schreibvorgänge durchführen – sodass schreibgeschützte API-Schlüssel-Aufrufe (Dashboard, Dateien, Modelle, Exporte, …) den Zähler stillschweigend zurückrollten. Die Nutzung wird jetzt in einer unabhängigen, selbst-committenden Sitzung aufgezeichnet, entkoppelt vom Anfrageerfolg.

- **Vorgefertigte Lösungsvorlagen (Market Seed Content)** — 8 vertikale Lösungsvorlagen werden beim ersten Benutzer-Registrierungsereignis idempotent bootstrapped: Financial Audit, Contract Review, Data Reporting, IT Helpdesk, HR Onboarding, Sales Assistant, Content Writer, Meeting Summary. Jede bündelt einen Agent + Skill mit chinesischen SOPs. Veröffentlicht auf Market-Organisation (`visibility=org`, `publish_status=approved`) für sofortige Marketplace-Verfügbarkeit. 4 Tests.
- **ReAct-Zyklenerkennung** — Deterministische Erkennung wiederholter identischer Werkzeugaufrufe. Injiziert eine Warnung nach 3 aufeinanderfolgenden Aufrufen mit denselben Argumenten und verhindert, dass Agenten bei fehlgeschlagenen Tools in Schleifen geraten. Konfigurierbar über `REACT_CYCLE_DETECTION_THRESHOLD`.
- **ReAct-Abschluss-Checkliste** — Einmalige Verifizierungsaufforderung vor der Annahme endgültiger Antworten, wenn Tools verwendet wurden, um vorzeitige oder unvollständige Antworten zu reduzieren. Umschaltbar pro Agent-Instanz.

### Geändert

- **Completion Checklist Min-Tools Threshold** — Die Checkliste wird jetzt nur ausgelöst, wenn der Agent 3+ Werkzeugaufrufe getätigt hat (konfigurierbar über `REACT_COMPLETION_CHECK_MIN_TOOLS`). Einfache 1-2 Werkzeug-Aufgaben überspringen die Verifizierung, um unnötige Latenz zu vermeiden.
- **Dynamische System-Prompt-Budgetierung** — Die feste `SYSTEM_PROMPT_RESERVE` (4K Token) wurde aus der Kontextbudgetberechnung entfernt. ContextGuard berücksichtigt den System-Prompt jetzt dynamisch und gibt jeder Iteration ~4K mehr nutzbaren Kontext.
- **Zentralisierte Werkzeugtrunkierung** — Alle Werkzeugtypen delegieren die Trunkierung jetzt an ein gemeinsames Modul. Standardwerte konfigurierbar über `TOOL_OUTPUT_MAX_CHARS`, `TOOL_OUTPUT_MAX_ITEMS`, `TOOL_OUTPUT_MAX_BYTES` Umgebungsvariablen.
- **Domänenerkennung entkoppelt** — Die Domänenklassifizierung läuft unabhängig in jedem Endpunkt, nicht mehr mit Auto-Routing gebündelt. Domänen-SOP-Anweisungen wurden gelockert, um eher zu leiten als zu mandatieren, Websuche.
- **`AUTO_ROUTING` Umgebungsvariable entfernt** — Auto-Endpunkt klassifiziert Abfragen immer.

### Behoben

- **Duplizierte Nachrichtenübermittlung** — Die Chat-Eingabe verwendet nun einen synchronen Guard, um zu verhindern, dass dieselbe Nachricht bei schnellen Klicks mehrfach eingereicht wird.
- **Structured Output Degradation Chain** — Die 3-stufige Fallback-Logik (native FC → JSON mode → plain text) durchläuft nun korrekt alle Ebenen.
- **`json_mode_enabled` DB-Wert ignoriert** — Modelle, die über Admin konfiguriert werden, verwenden nun korrekt ihre modellspezifische Einstellung statt immer auf die Umgebungsvariable zurückzugreifen.
- **DAG-Planungsfehler-Nachricht** — Zeigt nun benutzerfreundliche zweisprachige Nachricht statt rohem Pipeline-Fehler.
- **MCP Server Owner Bypass für allow_fallback** — Der Server Owner wird nicht länger durch `allow_fallback=False` blockiert.
