이 프로젝트의 모든 주목할 만한 변경 사항은 여기에 기록됩니다.

형식은 [Keep a Changelog](https://keepachangelog.com/)를 따릅니다. 버전은 [Roadmap](/roadmap) 마일스톤에 해당합니다.

## [미출시]

### 추가됨

- **청구를 위한 인스턴스 액세스 모델.** 관리자는 세 가지 방식 중 하나를 선택합니다: 구독 없음(소프트웨어 기본값, 월간 할당량 `0` = 무제한), 포함 + 유료, 또는 유료만. 포함된 기본 요금제는 삭제할 수 없으며, 유료 템플릿은 더 이상 FIM Stripe Price ID와 함께 제공되지 않습니다.

- **GPT-5.x 에이전트는 도구 호출 전반에 걸쳐 추론을 유지합니다.** FIM One은 이제 GPT-5.x 모델에 대해 OpenAI Responses API와 직접 통신하며 각 턴의 암호화된 추론을 다음 턴으로 전달하므로, 다단계 에이전트는 매 도구 라운드마다 다시 유도하는 대신 이미 작업한 내용을 바탕으로 진행합니다. 추론 토큰 수는 사용량에 표시되며, 사고 패널에는 모델의 자체 요약이 표시됩니다. `FIM_GPT5_RESPONSES_MODE=bridge`(또는 `off`)를 설정하여 이전 동작으로 돌아갈 수 있습니다. `/v1/responses` 경로가 없는 엔드포인트는 여전히 자체적으로 채팅 완료로 폴백합니다.

- **DAG 계획의 순수 변환 단계는 단일 직접 LLM 호출로 실행됩니다.** 플래너는 업스트림 출력만 소비하는 병합/재작성/요약 단계를 직접 단계로 태그하여, 절대 사용하지 않을 도구 루프를 건너뛰므로 비용과 지연 시간을 줄입니다. 모든 단계 결과는 이제 실행 방식(직접 호출 또는 에이전트 루프, 반복 횟수, 사용된 도구)도 기록합니다.

- **에이전트는 실행 중 명확히 하는 객관식 질문을 할 수 있습니다.** 작업이 실질적으로 다른 방향으로 진행될 수 있을 때, 에이전트는 일시 중지하고 채팅에 최대 4개의 구조화된 질문을 표시하며, 각 질문에는 2-4개의 옵션과 자유 텍스트 "기타"가 있습니다. 답변하면 해당 위치에서 실행이 재개되며, 건너뛰거나 시간 초과가 되면 자체 판단으로 계속 진행됩니다.

- **에이전트 단계는 실시간 한 줄 제목을 포함합니다.** 에이전트가 작동하는 동안 각 반복은 짧은 생성된 레이블("가격 데이터 확인 중…")을 받으며, 최신 단계로 순환하는 단일 접힌 헤더에 표시됩니다. 이를 확장하면 전체 단계 타임라인이 표시되며, 레이블은 대화 기록에 유지됩니다.

- **제공자의 모델을 일괄 삭제할 수 있습니다.** 관리자 → 모델의 각 모델 행에는 체크박스가 있고, 헤더는 전체 목록을 선택하며, Shift를 누른 상태에서 클릭하면 행 범위에 걸쳐 선택이 확장됩니다. 선택 항목을 삭제하면 선택한 모든 모델이 한 번의 요청으로 제거되며, 개수를 명시하는 확인 후 진행됩니다.

- **채팅 답변의 작은 비교 표는 이제 카드 스타일 레이아웃으로 렌더링됩니다.** 첫 번째 열에 속성 레이블이 있는 2-3열 표는 각 속성을 해당 값 셀 내에 표시합니다(AI 채팅 UI에서 대중화된 비교 카드 스타일과 일치). 더 큰 표는 기본 그리드를 유지합니다.

- **채팅 답변은 이제 Mermaid 다이어그램과 SVG 그림을 렌더링합니다.** `mermaid` 코드 블록은 테마 다이어그램이 되고 `svg` 블록은 소스 토글 및 다운로드가 있는 이미지가 됩니다. 소스가 불완전하거나 파싱되지 않으면 둘 다 일반 코드로 폴백되므로, 반쯤 스트리밍된 다이어그램은 절대 오류를 표시하지 않습니다.

- **답변, 코드 블록 및 표를 복사할 수 있습니다.** 모든 답변에는 Markdown으로 복사 작업이 있고, 코드 블록에는 언어를 명시하는 헤더가 있으며, 표는 Markdown으로 복사 및 CSV 다운로드(UTF-8, Excel에서 깔끔하게 열림)를 제공합니다.

- **인용은 어느 문서에서 나왔는지 표시합니다.** 인용 마커는 이제 소스의 문서 이름을 포함하는 약정으로 렌더링되며, 인접한 마커는 하나의 약정과 개수로 축소됩니다. 팝오버는 그 뒤의 모든 소스를 나열합니다.

- **`/clear`는 채팅 입력에서 작동합니다.** `/clear`를 입력하면 새 대화를 시작하며, 새 채팅을 클릭하는 것과 동일합니다. 실행 중인 턴은 먼저 중지됩니다.

- **다이어그램과 코드 블록을 복사할 수 있을 뿐만 아니라 다운로드할 수 있습니다.** Mermaid 다이어그램은 렌더링된 SVG를 내보내고, 모든 코드 블록은 해당 언어와 일치하는 파일명으로 다운로드됩니다. `csv` 블록은 Excel에서 깔끔하게 열리는 UTF-8 파일로 다운로드됩니다.

- **작성기는 이미지가 텍스트 전용 모델로 전송되기 전에 경고합니다.** 활성 모델이 이미지를 읽을 수 없는 경우 이미지를 첨부하면 모델이 파일 이름만 수신하며, 해당 턴에서 실제로 사용할 모델에서 확인된다는 메모가 표시됩니다.

- **전송되지 않은 입력이 유지됩니다.** 전송되지 않은 텍스트, 붙여넣은 클립 및 완료된 첨부 파일은 대화별로 기억되며, 새 채팅의 경우 별도로 기억되므로 새로 고침, 다른 대화로 전환 및 만료된 세션을 견딜 수 있습니다. 메시지가 전송되거나 해당 대화가 삭제되면 초안이 지워집니다.

- **채팅 답변은 LaTeX 수학 구분 기호를 허용합니다.** `\[...\]` 또는 `\(...\)`로 작성된 공식은 수학으로 렌더링되며, 기존 달러 기호 구문과 일치합니다. 코드 펜스 내의 구분 기호는 텍스트로 유지됩니다.

### 수정됨

- **관리자 결제 및 액세스 모델 설정이 인터페이스 언어로 다시 표시됩니다.** Admin → Settings의 결제 방식, 액세스 모델, 토큰 할당량 문자열과 관련 구독 오류 및 계정 사용량 패널이 중국어, 일본어, 한국어, 독일어, 프랑스어에서 영어 텍스트 또는 원시 키로 표시되던 문제를 수정했습니다.

- **Feishu 채널의 콜백 URL이 이제 Feishu 인증을 통과할 수 있습니다.** Feishu는 일회성 URL 인증 핸드셰이크 시 서명 헤더를 생략하는데, 콜백 엔드포인트가 서명되지 않은 요청을 모두 거부하여 요청 주소 저장이 항상 "Challenge code not returned" 오류와 함께 실패하고 채널의 카드 버튼이 작동하지 않았습니다. 이제 서명되지 않은 푸시는 다른 공유 시크릿으로 인증됩니다. 암호화된 봉투는 채널의 Encrypt Key로 열려야 하며, Verification Token이 설정된 경우 토큰이 일치해야 합니다. 서명도 없고 암호화도 되지 않은 본문은 여전히 거부됩니다.

- **소셜 로그인이 미인증 이메일 주소를 보유한 계정에 의해 탈취될 수 없습니다.** 소셜 로그인을 기존 계정에 연결하려면 이제 수신 제공업체뿐만 아니라 양쪽 모두에서 주소가 인증되어야 합니다. 주소를 확인하지 않은 제공업체로 로그인하면 계정이 생성되지만, 이후 인증된 로그인이 해당 계정과 매칭될 수 없습니다.

- **출력 한도로 잘린 응답이 더 이상 도구 호출을 절반만 실행하지 않습니다.** 모델이 메시지 중간에 토큰 한도에 도달하면, 해당 응답의 모든 도구 호출이 폐기되고 모델에게 더 작게 재발행하도록 요청합니다. 이전에는 인수가 완전한 호출이 실행되어, 모델이 하나의 단위로 계획한 배치가 절반만 실행되면서 전체가 실행된 것처럼 기록에 표시되었습니다.

- **첨부 파일이 업로드 중일 때 전송해도 파일이 누락되지 않습니다.** 이제 전송이 업로드 완료를 기다린 후 파일을 포함하며, 대기 중에는 전송 버튼에 스피너가 표시됩니다. 이전에는 이미지나 문서 없이 메시지가 전송되었고 경고도 없었습니다.

- **전송 실패한 메시지가 입력창에 다시 표시됩니다.** 대화 생성에 실패하면(세션 만료, 네트워크 오류 등) 입력한 텍스트가 오류 토스트와 함께 작성창으로 돌아옵니다. 이전에는 텍스트가 사라졌습니다.

- **후속 제안 칩이 사용자의 어투를 유지합니다.** 제안된 다음 질문은 "어느 것을 선호하시나요…?"와 같은 역방향 선호도 설문이 아니라, 사용자가 어시스턴트에게 보낼 요청이나 질문 형태로 구성됩니다.

- **Exa 문서에서 더 이상 Exa를 기본 검색 제공업체로 설명하지 않습니다.** 통합 및 환경 변수 페이지에서 이제 Exa를 `WEB_SEARCH_PROVIDER=exa`로 활성화하는 선택적 백엔드로 설명합니다. 기본 검색 경로는 Jina로 유지됩니다.

- **사이드바 로고가 다시 실제 링크로 작동합니다.** 가운데 클릭 및 cmd/ctrl 클릭으로 대시보드를 새 탭에서 열 수 있으며, 왼쪽 클릭은 기존과 동일하게 탐색하며 짧은 바운스 애니메이션을 유지합니다.

### 변경 사항

- **관리자 패널이 새 탭에서 열립니다.** 사용자 메뉴에서 관리자 패널을 선택하면 현재 워크스페이스가 뒤에 그대로 유지되며, 해당 메뉴의 다른 외부 링크와 동일한 방식으로 동작합니다.

- **사이드바에서 탐색이 우선입니다.** 모듈 탐색이 대화 목록 위에 간결한 연속 목록으로 배치됩니다(Build / Resources / Operate 섹션 레이블 없음). 탐색 항목, 새 채팅 / 검색, 대화 행의 간격이 더 촘촘해졌으며, 이전처럼 사이드바 하단 독에 숨겨지지 않습니다.

- **스트리밍 응답이 깜빡임 없이 안정적으로 렌더링됩니다.** 생성 중인 답변이 이제 블록 단위로 렌더링됩니다. 완성된 블록은 매 프레임마다 다시 렌더링되지 않고 안정적으로 유지되며, 절반만 도착한 서식(굵게, 링크, 수식)은 스트리밍이 완료될 때까지 완성되거나 보류됩니다.

- **최종 답변이 작성되는 동시에 스트리밍됩니다.** 에이전트가 정보 수집 완료 시점을 신호로 알리고 답변을 실시간 스트리밍 턴으로 작성하므로, 긴 답변도 대기 후 재생되는 대신 토큰 단위로 전체 내용이 도착합니다. `REACT_FINISH_SIGNAL=false`로 이전 동작을 복원할 수 있습니다.

- **아키텍처 문서가 그래프 엔지니어링을 FIM One에 매핑합니다.** [Planning Landscape](/architecture/planning-landscape)에서는 루프 엔지니어링과 그래프 엔지니어링의 차이, 기존 시각적 워크플로우와의 차이점, Workflow / DAG / ReAct에 대한 매핑 방식, 각 엔진에서 참고할 사항을 설명합니다. 또한 모든 DAG 단계가 이미 단순 LLM 호출이 아닌 완전한 ReAct 에이전트라는 현재 사실도 명시합니다. ReAct 및 DAG 엔진 페이지에서 해당 문서로 링크됩니다.

- **일반 채팅에서 항상 후속 질문을 제안합니다.** 에이전트가 연결되지 않은 대화에서는 각 답변 후 다음 질문을 제안하며, 에이전트가 연결된 채팅은 에이전트별 후속 질문 제안 토글(기본값: 꺼짐)이 필요합니다. 인사말이나 감사 인사 같은 종결 턴에서는 제안 칩이 표시되지 않을 수 있습니다.

- **새로 전송된 메시지가 화면 상단에서 시작됩니다.** 현재 턴의 첫 번째 줄이 상단에 닿을 만큼의 여백만 남기므로, 질문이 화면에 유지되고 답변이 아래 공간으로 펼쳐집니다. 이전처럼 전체 턴이 하단에 붙어 있지 않습니다. 턴이 화면 하나를 초과하면 여백은 사라집니다.

- **추론 블록이 턴 실행 중 접힌 상태를 유지합니다.** ReAct 및 DAG 출력의 추론이 이제 스트리밍 중 펼쳐지는 대신 기본적으로 한 줄 미리보기로 표시되어 결과가 화면에 유지됩니다. 블록을 클릭하면 전체 추적을 확인할 수 있습니다.

- **내보낸 PDF 및 Word 파일이 중국어에 맞게 올바르게 조판됩니다.** PDF 내보내기 시 실제 CJK 폰트가 참조 대신 임베드되어, 영문 텍스트의 간격 붕괴 및 글머리 기호가 관련 없는 한자로 렌더링되는 문제가 수정되었으며 굵게도 정상 작동합니다. Word 내보내기 시 동아시아 폰트가 선언되어 중국어/영어 혼합 굵은 텍스트가 절반만 굵게 표시되는 문제가 해결되었으며, 두 형식 모두 대화 내 제목이 전체 구조에 종속되도록 5단계 크기 체계를 사용합니다.

- **에이전트가 긴 작업에서도 계획을 유지합니다.** 에이전트가 동일한 도구를 반복적으로 헛되이 사용할 때 접근 방식을 바꾸도록 알림을 받고, 계획 없이 작업할 때 계획을 작성하도록 유도하며, 계획 항목이 남아 있는 상태에서 명시적인 검증 단계 없이 최종 답변을 제공할 수 없습니다.

- **스트리밍 답변이 갑자기 나타나지 않고 부드럽게 등장합니다.** 새로 도착한 블록이 스트리밍되는 동안 잠깐 페이드 인되며, 사용자의 모션 감소 설정을 준수합니다. 긴 표에서는 커서 아래 행이 강조 표시되고, 목록 글머리 기호가 텍스트와 경쟁하지 않고 뒤에 배치됩니다.

- **블록 액션이 필요할 때만 표시됩니다.** 답변, 코드 블록, 다이어그램, 표의 복사 및 다운로드 버튼은 툴팁이 있는 아이콘 전용으로 표시되며(다운로드는 항상 맨 오른쪽), 호버 시 나타나고 키보드로도 접근할 수 있습니다.

- **사이드바가 이제 채팅을 한데 모읍니다.** 대화 목록이 새 채팅 및 검색 바로 아래에 위치하고, 모듈 탐색이 사용자 영역 위의 간결한 색조 독으로 이동하여 목록에 더 많은 공간을 제공하고 사이드바에 명확한 위아래 계층 구조를 부여합니다.

- **추론이 기본적으로 접혀 있습니다.** 실시간 실행 및 과거 대화 모두에서 생각 섹션이 한 줄 미리보기로 접혀 있으며 클릭 시 펼쳐집니다. 추론은 생성 중에는 펼쳐진 상태로 스트리밍되다가 단계가 완료되면 접힙니다.

- **목록 페이지의 카드가 부드럽게 등장합니다.** 에이전트, 커넥터, 지식 베이스, 스킬, 워크플로우, 도구, 대화, 아티팩트 및 마켓의 카드가 첫 로드 시 한꺼번에 나타나지 않고 순차적으로 등장합니다. 필터링과 페이징은 즉시 반응하므로 검색창에 입력해도 등장 애니메이션이 다시 재생되지 않습니다.

### 보안

- **렌더링된 마크다운의 원본 HTML이 이제 새니타이제이션됩니다.** 모델 출력 및 업로드된 마크다운 파일은 표시 전에 정제되므로 주입된 스크립트, 이벤트 핸들러, iframe, 폼 및 스타일 오버라이드가 더 이상 페이지에 도달할 수 없습니다. 수학, 구문 강조, 표, 작업 목록 및 공개 블록은 영향을 받지 않습니다. 원본 인라인 `<svg>`는 더 이상 렌더링되지 않습니다. 대신 `svg` 코드 블록을 사용하세요.

### 수정됨

- **GPT-5.x 에이전트가 추론을 활성화한 상태로 도구를 실행합니다.** GPT-5.x 모델은 이제 Responses API를 먼저 거쳐서 함수 도구와 추론이 함께 작동하고, `/v1/responses` 경로가 없는 엔드포인트는 자동으로 채팅 완성으로 폴백되며, 여기서 GPT-5.x 도구 호출은 해당 API가 요구하므로 추론을 명시적으로 비활성화합니다. OpenAI 호환 엔드포인트의 다른 모델 제품군은 기존 채팅 완성 경로를 유지합니다.

- **Ask-first 요청이 Planner 모드에서 한 라운드로 완료됩니다.** 에이전트에게 여러 선택지 질문으로 요구사항을 명확히 한 후 답변을 제공하도록 명시적으로 요청하는 목표("问清楚我再出方案")는 이제 계획 단계를 기다리고 재계획을 반복하며 "목표 달성 안 됨"과 반복된 질문 목록으로 끝나는 대신 깔끔한 설문지 하나를 턴의 결과로 생성합니다. Auto 모드는 이러한 요청을 Standard 모드로 라우팅합니다.

- **Follow-up 칩이 더 이상 답변 이후의 기록을 끌어당기지 않습니다.** 턴이 결과에 주차된 후, 나중의 레이아웃 성장(제안, 제목)은 제자리에 유지되고, 라이브 턴을 기록으로 접으면 같은 대화에서 답변 헤드에 다시 주차되며 맨 아래로 점프하지 않습니다.

- **기존 대화를 열면 최신 메시지에 도착합니다.** 채팅 URL을 새로고침하면 사이드바에서 전환하는 것처럼 맨 아래로 스크롤되며, 스레드 맨 위에서 시작하지 않습니다.

- **빠른 답변이 더 이상 "처리 중…"에 갇혀 보이지 않습니다.** 생성된 단계 제목이 없는 완료된 턴은 라이브 처리 shimmer 텍스트 대신 사고 과정 레이블을 표시합니다.

- **애니메이션이 이제 시스템 "동작 감소" 설정을 따릅니다.** 로그인 배경의 표류하는 그래디언트, 히어로 진입, 호흡하는 주입된 메시지 텍스트 및 스트리밍 캐럿은 운영 체제 환경설정이 무엇이든 계속 움직였습니다. 이제 정지하며, 진행 중인 작업을 보고하는 표시기는 인터페이스가 정지된 것처럼 보이지 않도록 표시 상태를 유지합니다.

- **실행 모드 선택기가 턴 실행 중에 닫혀 있습니다.** 칩은 회색으로 표시되었지만 클릭 시 메뉴를 열었으며, 옆의 에이전트 선택기와 달랐습니다. 이제 둘 다 실행이 완료될 때까지 비활성 상태입니다.

- **추론 스트림이 최신 모델에서 다시 라이브됩니다.** 라이브 추론은 하드코딩된 모델 이름 목록에서 연결되었으므로 해당 목록이 작성된 후 출시된 모든 항목은 스피너를 표시한 후 전체 추론 블록을 한 번에 덤프했습니다. 이제 추론을 내보내는 모든 모델이 스트림합니다.

- **채팅 보기가 빠른 출력을 따라가고 답변에 도착합니다.** 더 이상 추론 중간에 정지하고 거짓으로 아래에 새 콘텐츠를 보고하지 않으며, 새 이벤트 없이 성장하는 콘텐츠를 따르고, 턴이 완료되면 맨 아래 대신 결과 맨 위에 정착합니다. 스크롤을 벗어나면 여전히 제어를 반환하고, 맨 아래로 돌아가면 추적을 재개합니다.

- **짧은 답변이 턴 종료 후 읽던 위치에 유지됩니다.** 턴이 완료되면 기록이 아래로 슬라이드되어 질문과 답변이 입력 상자에 달라붙었습니다. 이제 답변은 다음 메시지가 전송될 때까지 보기 맨 위에 위치를 유지합니다.

- **로그인이 계정의 선호 언어를 즉시 적용합니다.** 로케일 쿠키는 이제 로그인 및 OAuth 콜백 중에 동기화되고, 계정의 언어가 로그인 페이지가 렌더링된 언어와 다르면 랜딩 페이지가 새로 로드되므로 다음 새로고침까지 대상이 이전 언어로 나타나지 않습니다.

- **Cmd+K가 사이드바가 축소되었을 때도 검색을 엽니다.** 단축키 리스너는 활성 상태였지만 축소된 상태에서 대화 상자가 마운트되지 않았으므로 단축키는 조용히 아무것도 하지 않았습니다.

- **인용이 다시 출처 문서의 이름을 지정합니다.** 간단한 검색 모드에서 모든 소스는 "Knowledge Base"로 레이블이 지정되었습니다. 검색 도구가 원본 파일명을 삭제했기 때문입니다. 이제 소스를 보고하며, grounding 파이프라인이 이미 수행한 작업과 일치합니다.

- **긴 대화는 하드 컨텍스트 오버플로우 오류에 덜 걸리기 쉽습니다.** 압축은 이제 정확히 모델의 입력 제한에서가 아니라 그 아래의 안전 마진으로 트리거되며, 빠른 모델의 창이 일반 모델의 컨텍스트 예산을 보유하기에 너무 작으면 시작 로그가 경고를 기록합니다.

- **SVG 그림이 다크 모드에서 읽을 수 있습니다.** 모델 작성 SVG는 밝은 캔버스를 가정하므로 그림은 고정된 밝은 표면에 그려지며 어두운 배경에 어두운 색으로 변하지 않습니다.

- **브라우저 탭 바쁜 표시기가 더 이상 턴 중간에 사라지지 않습니다.** 턴이 실행되는 동안 탭 아이콘은 앱 마크를 유지하고 전체 색상과 회색 사이를 펄스하며 전체 실행 동안 유지되고 앱 내 탐색 후에도 턴이 끝날 때 실제 아이콘을 안정적으로 복원합니다. 동작 감소가 활성화되면 애니메이션 대신 정적 회색 마크를 유지합니다.

- **에이전트가 더 이상 잘린 결과 후에 엔드포인트를 수십 번 다시 가져오지 않습니다.** 잘림 알림은 이제 저장된 전체 복사본에 대한 명령형 포인터로 시작하고, 같은 엔드포인트를 다양한 매개변수로 계속 해머하는 에이전트는 경고를 받은 후 하드 중지됩니다.

- **충돌한 실행이 이제 녹색 "완료" 대신 오류를 보고합니다.** 에이전트가 내부 오류로 인해 중지되었을 때, 원본 예외 텍스트는 성공 체크마크 아래 답변으로 전달되었습니다. 이제 오류는 오류 채널을 통과하고 오류 알림으로 표시됩니다.

- **스트림에 다시 연결해도 이미 본 출력을 더 이상 재생하지 않습니다.** 라이브 스트림은 이제 재개 엔드포인트와 동일한 위치 커서를 전달하므로 연결이 끊긴 후 전체 턴 대신 누락된 이벤트만 재생됩니다.

- **네트워크 청크로 분할된 스트림 이벤트가 더 이상 손실되지 않습니다.** 재개된 스트림은 프레임이 두 부분으로 도착한 이벤트를 삭제할 수 있었습니다. 이제 두 스트림 경로 모두 임의의 청크 경계를 처리하는 하나의 파서를 공유합니다.

- **다른 에이전트를 호출하면 실제 답변을 반환합니다.** 하위 에이전트의 답변은 원본 실행 추적 내에 묻혀 호출 에이전트의 컨텍스트를 넘쳤습니다. 이제 답변만 받습니다.

- **중단된 도구가 더 이상 실행을 무한정 정지할 수 없습니다.** 모든 도구 호출에는 이제 벽시계 시간 제한(기본값 180초)이 있으므로 정지된 커넥터 또는 응답하지 않는 서버는 턴을 정지시키는 대신 명확한 메시지로 단계를 종료합니다.

- **같은 도구 호출을 반복하는 에이전트가 이제 조기에 중지됩니다.** 동일한 반복 호출은 전체 반복 예산을 소모하는 대신 몇 번의 시도 후 거부됩니다.

- **긴 대화는 더 이상 압축 후 이전 컨텍스트를 잃지 않습니다.** 이전 턴을 압축하는 요약은 다음 실행에서 조용히 삭제되었습니다. 이제 전달되므로 에이전트는 이전에 논의한 내용을 유지합니다.

- **큰 도구 결과가 시작뿐만 아니라 끝도 유지합니다.** 긴 결과가 컨텍스트 창에 맞도록 잘릴 때, 이제 양쪽 끝이 유지되고(명령 출력의 결론이 보통 가장 중요함), 잘림은 비라틴 텍스트에 대해 올바르게 계산되고, 나중의 결과는 완전히 공백이 되는 대신 최소 창이 보장됩니다.

- **같은 생성 파일이 더 이상 두 개의 다운로드로 표시되지 않습니다.** 렌더링된 HTML 출력이 실제 파일명으로 다시 저장되면 동일한 콘텐츠를 가진 두 개의 전달 가능 카드를 생성했습니다. 이제 중복이 콘텐츠로 감지되고 특정 이름의 파일로 축소됩니다.

- **내부 오프로드 파일이 더 이상 다운로드 가능한 전달물로 나타날 수 없습니다.** 도구가 하나의 파일 시스템을 공유하면서 코드 실행 중에 오프로드된 큰 도구 출력은 아티팩트 스캔에 의해 선택되어 거짓 다운로드 카드로 표시될 수 있었습니다. 이제 런타임 부기 파일은 아티팩트 감지에서 제외됩니다.

- **대화의 모든 도구가 이제 하나의 공유 파일 시스템에서 작동합니다.** 오프로드된 큰 출력은 워크스페이스 읽기 도구만 볼 수 있는 디렉토리에 도착했으며, `file_ops`, `shell_exec` 및 `python_exec`는 다른 곳에서 작동했습니다. 에이전트는 파일을 나열한 후 존재하지 않는다고 말해지고 반복 예산을 소모하며 찾아다녔습니다. 이제 오프로드된 파일은 모든 도구(실행 컨테이너 포함)가 마운트하는 대화 샌

### 추가됨

- **Skills와 Workflows는 이제 선택적 모듈이며 기본적으로 비활성화됩니다.** 새로운 설치는 핵심(채팅, 에이전트, 지식 베이스, 커넥터)만으로 시작되며, 관리자가 Admin → Settings → Modules에서 Skills 및/또는 Workflows를 활성화합니다. 모듈이 비활성화되어 있는 동안 네비게이션과 페이지에서 숨겨지며, API, Market 항목 및 트리거를 사용할 수 없습니다. 아무것도 삭제되지 않으며, 다시 활성화하면 모든 것이 복원됩니다.
- **DAG 재계획은 더 이상 완료된 작업을 다시 수행하지 않으며, 중단된 실행은 중단된 지점에서 재개됩니다.** 계획을 수정해야 할 때, 이미 완료된 단계는 결과와 함께 새 계획으로 이월됩니다. 남은 작업만 다시 계획되고 실행됩니다. 단계 진행 상황도 발생할 때마다 체크포인트되므로, 실행 중에 중단되면(충돌, 배포, 연결 끊김), 같은 요청을 재시도할 때 완료된 단계에서 시작하지 않고 처음부터 시작합니다.
- **느린 도구는 이제 에이전트를 차단하지 않고 백그라운드에서 실행할 수 있습니다.** 샌드박스 코드 실행(Python/Shell/Node)은 `run_in_background` 옵션을 제공합니다. 에이전트는 즉시 작업 ID를 받고 다른 단계를 계속 진행하며, 도구가 완료되면 알림으로 결과를 받습니다. 에이전트가 작업이 여전히 실행 중인 상태에서 완료하려고 하면, 작업을 기다렸다가(제한됨) 결과를 통합한 후 답변합니다.
- **대화 기록은 압축 전에 스냅샷되며, 예산 제한된 도구 결과는 워크스페이스에 저장됩니다.** 긴 대화 압축이 기록을 요약으로 바꾸기 전에, 전체 기록이 JSONL 파일로 대화 워크스페이스에 기록됩니다. 마찬가지로, 집계 토큰 예산으로 잘린 도구 결과는 워크스페이스에 전체로 저장되고 포인터가 남겨집니다. 두 경우 모두 에이전트(및 사용자)가 원본을 다시 읽을 수 있으므로 손실되지 않습니다.
- **모델이 출력 제한에 도달해도 답변이 더 이상 중간에 끝나지 않습니다.** 응답이 제공자의 출력 토큰 상한으로 잘릴 때, 에이전트는 자동으로 모델에 중단된 지점에서 재개하도록 요청하고(최대 3회), 세그먼트를 하나의 매끄러운 답변으로 연결합니다. 추론 루프와 스트리밍된 최종 답변 모두에서 작동합니다.
- **LLM 호출은 이제 제공자 과부하(HTTP 529) 및 게이트웨이 타임아웃(504)에서 재시도하며, `Retry-After`를 준수합니다.** 이전에는 Anthropic의 529가 폴백 모델이 구성되지 않으면 요청을 즉시 실패했습니다. 이제는 429/5xx처럼 백오프하고 재시도하며, `Retry-After` 헤더가 있을 때 제공자가 요청한 시간만큼 정확히 대기합니다.
- **에이전트는 이제 다단계 작업 중에 표시되는 계획을 유지합니다.** ReAct 에이전트는 `update_plan` 도구를 사용하여 계획을 할 일 체크리스트로 작성하고 진행하면서 업데이트합니다. 계획이 여러 도구 호출 동안 오래되면, 전체 체크리스트가 미리 알림으로 다시 주입됩니다. 긴 작업도 컨텍스트 압축 후에도 목표를 유지합니다. 기본적으로 활성화됨(`REACT_PLAN_TOOL_ENABLED`). DAG 하위 단계 및 도구 없는 에이전트는 건너뜁니다.

- **에이전트는 이제 대화 중에 워크플로우를 실행할 수 있습니다.** 활성이고 인간 승인이 필요 없는 워크플로우(소유하거나 구독한)는 에이전트에 `run_workflow` 도구로 제공됩니다. 일반 채팅 및 에이전트 선택 시 모두 가능합니다. 작업이 결정론적이고 반복 가능한 하위 프로세스를 워크플로우에 넘기고 출력을 받을 수 있습니다. 각 실행은 워크플로우의 실행 기록에 기록되며, 토큰 사용량은 워크플로우 소유자의 할당량에 계산됩니다(소유자가 이미 할당량을 초과하면 실행이 거부됩니다). Human Intervention 단계가 있는 워크플로우는 오래 차단될 수 있으므로 트리거 전용입니다(Workflows 페이지 또는 API 키에서).
- **두 가지 새로운 워크플로우 시작 템플릿: Connector Action과 MCP Tool Call.** "Create from Template" 갤러리는 이제 커넥터 및 MCP 노드를 보여줍니다. 외부 시스템 또는 MCP 도구를 호출한 다음 LLM으로 결과를 요약합니다. 생성 후 특정 커넥터/서버를 선택합니다.

### 변경 사항

- **지식 베이스는 더 이상 공유할 수 없습니다.** 지식 베이스를 조직이나 마켓에 게시하는 기능이 제거되었습니다. KB는 공유된 에이전트에 바인딩되어 런타임에 소유자의 콘텐츠를 위임할 때만 다른 사람에게 도달합니다. 이미 게시된 지식 베이스는 현재 구독자에게 계속 접근 가능하며 메뉴에서 개인용으로 되돌릴 수 있습니다.
- **커넥터와 MCP 서버는 더 이상 기본적으로 소유자의 자격증명을 공유하지 않습니다(주요 변경).** "소유자의 자격증명으로 폴백 허용"은 이제 선택 사항입니다. 새로운 커넥터/MCP 서버는 이 기능이 꺼진 상태로 생성되며, 기존의 모든 커넥터/MCP 서버도 꺼진 상태로 전환되었습니다. 공유된 커넥터나 MCP 서버를 사용하기 위해 소유자의 토큰에 의존하던 구독자는 이제 자신의 자격증명을 추가하거나, 소유자가 해당 리소스에서 폴백을 다시 활성화해야 합니다. 소유자는 설정과 관계없이 항상 자신의 자격증명을 사용할 수 있습니다. 결과적으로 폴백이 꺼져 있고 자격증명이 없는 커넥터는 이제 에이전트의 도구 집합에서 숨겨집니다(MCP 서버가 이미 그렇게 동작하는 것과 일치). 이전에는 제공되었다가 호출될 때 실패했습니다.
- **새로운 에이전트는 기본적으로 Auto 대신 ReAct 실행으로 설정됩니다.** Auto 모드는 요청당 ReAct와 DAG 중 하나를 결정하기 위해 추가 빠른 모델 분류 호출을 수행했습니다. 새로운 에이전트(및 기본 제공/마켓플레이스 템플릿)는 이제 ReAct로 기본 설정되어 메시지당 지연 시간과 비용을 제거합니다. Auto와 DAG는 에이전트별로 선택 가능하게 유지되며, 기존 에이전트는 현재 모드를 유지합니다.
- **AI 에이전트 생성이 약한 빠른 모델에서 복구됩니다.** 자연어 명령어에서 에이전트를 구축하거나 개선하는 작업은 빠른 모델에서 실행됩니다. 유효한 구성을 생성할 수 없으면 요청은 이제 오류가 발생하기 전에 더 강력한 일반 모델에서 한 번 재시도되므로, 너무 약한 빠른 모델은 더 이상 사용자에게 실패로 표시되지 않습니다.

### 제거됨

- **시각적 워크플로우 빌더를 9개의 핵심 노드 타입으로 축소했습니다.** 환경 변수, HTTP 요청, 코드 실행, 반복자/루프, 하위 워크플로우, 템플릿/리스트/변환 헬퍼, 그리고 매개변수/질문 추출기 및 분류기 등 거의 사용되지 않는 16개의 유틸리티 및 제어 흐름 노드가 제거되었습니다. 이를 통해 빌더는 에이전트, 커넥터, MCP 서버, 그리고 지식 베이스 오케스트레이션에 집중할 수 있게 되었습니다. 부수적으로 공유 워크플로우는 더 이상 내장된 시크릿을 포함하지 않습니다. 이제 순수하게 참조의 그래프이며, 각 참조된 리소스는 런타임에 사용자별 접근 제어를 강제합니다. 제거된 노드로 구축된 기존 워크플로우는 남은 노드 세트로 다시 구축해야 합니다.

### 보안

- **API 키 범위는 이제 사용자 객체에 첨부되지 않고 요청별로 전달됩니다.** 캐시되거나 ID 맵에서 공유된 사용자가 다른 인증 컨텍스트의 범위 집합을 상속받을 수 있는 잠재적 범위 혼동 경로를 닫습니다.
- **자동 생성된 `.env`는 이제 소유자 전용(0600) 권한으로 작성됩니다.** 기존 `.env` 파일은 해당 권한을 유지합니다.
- **비밀번호 해싱 비용은 이제 `FIM_BCRYPT_COST`를 통해 조정 가능합니다**(기본값 12, bcrypt의 4–31 범위로 제한). 운영자가 하드웨어와 보안 강화 사이의 균형을 맞출 수 있습니다.
- **데이터베이스 커넥터는 더 이상 공유할 수 없으며, 원본 SQL 도구는 소유자 전용입니다.** 데이터베이스 커넥터를 조직이나 전역으로 게시하는 것은 이제 거부되며, 임의 SQL 데이터베이스 도구는 커넥터의 소유자에게만 제공됩니다. 소유자 자격증명 폴백 설정에 관계없이 구독자에게는 절대 제공되지 않습니다. 이전에는 공유 데이터베이스 커넥터가 소유자(일반적으로 높은 권한)의 데이터베이스 계정에 대한 제한 없는 SQL을 구독자에게 노출했으며, 호출자별 범위 지정이 없었습니다. 사용자별 범위 지정 데이터베이스 액세스는 향후 선언적 작업 계층을 통해 반환될 예정입니다.
- **웹훅 및 크론 트리거 워크플로우는 이제 소유자의 토큰 할당량에 포함됩니다.** 공개 API 키 또는 일정을 통해 트리거된 무인 워크플로우 실행은 이전에 토큰 사용을 확인하거나 기록하지 않고 LLM 및 에이전트 단계를 실행했으며, 할당량을 완전히 우회하는 무료 LLM 경로였습니다. 이러한 실행은 이제 워크플로우 소유자의 할당량에 대해 사전에 제어됩니다(공개 트리거는 거부되고, 소유자가 이미 할당량을 초과한 경우 예약된 실행은 건너뜁니다). 토큰 사용은 실행별로 기록되고 채팅과 동일한 월간 할당량에 포함됩니다.
- **Feishu 승인 카드는 이제 누가 승인할 수 있는지 강제합니다.** 카드 클릭은 클릭한 사용자의 Feishu 계정이 에이전트의 승인자 범위 설정(개시자, 에이전트 소유자 또는 조직 구성원) 하에서 실제로 승인할 수 있는 FIM One 사용자에게 연결된 경우에만 인정됩니다. 이는 포털 내 승인이 이미 적용한 것과 동일한 규칙입니다. 이전에는 Feishu 그룹의 누구나 보류 중인 작업을 승인하거나 거부할 수 있었으며, 결정은 신원 없이 기록되었습니다.
- **Feishu 채널은 이제 암호화 키가 필요하며, 유효한 서명이 없는 콜백은 거부됩니다.** 암호화 키가 구성되지 않은 경우 콜백 서명 검증이 실패로 닫힙니다(이전에는 서명되지 않은 콜백을 수락했으므로 채널의 콜백 URL을 알아낸 누구나 승인을 위조할 수 있었습니다). 암호화가 활성화된 경우 Feishu가 전송하는 암호화된 이벤트 봉투는 이제 복호화됩니다. 새로운 또는 편집된 Feishu 채널은 암호화 키를 제공해야 합니다.
- **승인 요청은 더 이상 의도하지 않은 채팅으로 라우팅되지 않습니다.** 에이전트에 명시적으로 구성된 승인 채널이 없는 경우, 보류 중인 승인이 에이전트의 완료 알림 채널로 푸시되거나, 실패할 경우 조직의 첫 번째 채널로 푸시될 수 있었습니다. 이는 승인자로 선택되지 않은 그룹에 민감한 작업 카드를 노출했습니다. 승인은 이제 에이전트의 명시적으로 구성된 승인 채널로만 이동하며, 그렇지 않으면 포털 내 승인으로 폴백됩니다.
- **공유 MCP 서버 및 지식 기반은 바인딩할 때뿐만 아니라 런타임에 액세스를 다시 확인합니다.** 워크플로우 MCP 단계, 에이전트의 바인딩된 MCP 서버 또는 에이전트의 바인딩된 지식 기반은 실행할 때마다 현재 구독 상태에 대해 검증되므로, 조직을 떠나서 취소된 액세스는 오래된 바인딩을 통해 지속되지 않고 즉시 적용됩니다.

### 수정됨

- **OAuth 로그인이 GitHub/Google/Discord/Feishu가 느릴 때 라이브러리 기본 타임아웃에서 멈추고 일반적인 오류를 표시하는 대신, 명확한 "provider took too long" 메시지로 빠르게 실패합니다.**
- **에이전트가 HTML 결과물을 다시 스타일링하도록 요청받을 때 더 이상 불필요한 이미지를 생성하지 않으며, 실제로 작업 공간에 작성하지 않고 파일이 생성되었다고 주장하지 않습니다.** 이미지 생성은 이제 래스터 이미지로 명시적으로 범위가 지정되며, 파일 결과물은 도구 호출을 통해 작성되어야 합니다. 채팅에 콘텐츠를 붙여넣는 것은 더 이상 "파일 생성"으로 간주되지 않습니다.
- **생성된 HTML 페이지는 이제 일반적인 보라색 그래디언트 모양 대신 따뜻한 Claude 영감 팔레트를 기본값으로 사용합니다.** 스타일을 지정하지 않으면 에이전트는 따뜻한 최소 기본값을 사용하고, 지정된 경우 사용자의 스타일이 항상 우선합니다.
- **도구가 많은 긴 대화는 더 이상 히스토리가 압축될 때 중단되지 않습니다.** 컨텍스트 압축이 도구 호출과 그 결과 사이의 유지된 윈도우를 자를 수 있어서 LLM 제공자가 거부하는 메시지 시퀀스(HTTP 400)를 생성했습니다. 특히 압축이 가장 필요한 긴 실행에서 그랬습니다. 압축기는 이제 각 도구 호출을 유지된 쪽의 결과와 함께 유지합니다.
- **백그라운드 도구 결과가 이제 단계 스트림과 DAG 증거에 표시됩니다.** 백그라운드에서 실행된 도구는 실제 출력을 에이전트의 내부 알림 메시지 내에서만 전달했습니다. UI의 단계 타임라인과 DAG 답변 검증 증거는 디스패치 플레이스홀더만 보았습니다. 드레인된 결과는 이제 실제 도구 이름 아래의 일반 도구 완료 이벤트로 내보내집니다.
- **중복된 단계 ID를 가진 드문 플래너 출력이 더 이상 전체 DAG 턴을 실패시키지 않습니다.** 중복 ID는 이전에 "순환 종속성" 오류로 잘못 진단되었습니다. 이제 결정론적으로 이름이 변경되고 계획이 진행됩니다.
- **여러 ReAct 루프 정확성 수정.** 빈 출력을 반환하는 도구는 작업 공간이 활성화되었을 때 "출력 없이 완료됨" 메모를 유지했습니다. 만족할 수 없는 종속성으로 차단된 DAG 단계는 이제 UI를 멈추게 하는 대신 적절한 터미널 이벤트를 내보냅니다. 기본 도구 호출이 없는 모델의 경우 폴백 답변 합성이 도구 호출뿐만 아니라 도구 결과를 봅니다.
- **대화 작업 공간이 이제 실제로 채팅에 연결되었습니다. 크기가 큰 도구 결과를 자동으로 손실되지 않고 복구할 수 있습니다.** 에이전트 계층의 작업 공간 복구 경로(큰 출력 오프로드 및 `workspace://` 포인터, 예산 잘린 도구 결과의 전체 복사 복구, 압축 전 트랜스크립트 스냅샷)가 존재했지만 채팅 엔드포인트는 작업 공간을 생성하지 않았으므로 실행되지 않았습니다. 도구 결과 예산이 소진되면 모델은 데이터를 다시 읽을 방법이 없는 빈 관찰을 받았고 추측으로 답변했습니다. ReAct 및 DAG 단계 에이전트는 이제 대화별 작업 공간을 얻으며, 대화를 삭제하면 작업 공간 파일과 남은 충돌 복구 체크포인트를 정리합니다.
- **재개된 DAG 실행이 더 이상 긴 단계 출력의 끝을 잃지 않습니다.** 충돌 복구 체크포인트에 저장된 단계 증거는 크기 상한에서 헤드만 잘렸으며, 출력 끝에 있는 모든 것을 자동으로 삭제했습니다. 결론, 체크섬, 최종 행이 있는 곳이 정확히 그곳입니다. 제한된 증거는 이제 명시적 생략 마커와 함께 헤드와 테일을 모두 유지합니다.
- **에이전트가 더 이상 Python을 통해 자신의 메모를 인쇄하여 "작동"하지 않습니다.** 도구 호출당 하나의 포괄적인 스크립트 작성을 권장하는 효율성 지침은 이제 실제로 코드 실행이 필요한 작업으로 범위가 지정됩니다. 지식 질문, 비교, 모델이 직접 생성할 수 있는 분석은 무의미한 샌드박스 스크립트를 통해 라우팅되는 대신 직접 답변됩니다.
- **워크플로우 내의 에이전트 단계는 이제 프롬프트뿐만 아니라 전체 에이전트를 실행합니다.** 워크플로우의 Agent 노드는 이전에 일반 모델과 기본 도구 세트에서만 에이전트의 지침으로 실행되었습니다. 에이전트의 커넥터, 지식 기반, MCP 서버, 구성된 모델을 자동으로 삭제했습니다. 이제 채팅에서와 정확히 같이 에이전트를 실행하며, 바인딩된 모든 리소스와 모델을 사용하고, 해당 에이전트가 워크플로우 소유자에게 표시되는 경우에만 실행됩니다.
- **조직을 떠나거나(또는 제거되면) 이제 공유 액세스가 취소됩니다.** 해당 조직을 통해서만 도달할 수 있는 리소스는 구독 취소되며, 저장한 커넥터/MCP 자격 증명은 삭제됩니다. 따라서 더 이상 해당 리소스를 사용하거나 떠난 후 소유자의 자격 증명으로 폴백할 수 없습니다. Market을 통해 구독한 리소스는 영향을 받지 않습니다.
- **계정을 삭제하면 이제 일관되게 모든 것을 제거합니다.** 관리자 "사용자 삭제" 및 셀프 서비스 "내 계정 삭제" 경로는 이전에 달랐습니다. 각각 다른 온디스크 파일 세트를 정리했고(둘 다 파일 경로를 잘못 계산했으므로 각각 일부를 자동으로 놓쳤습니다), 관리자 경로는 API 키, 로그인 히스토리, 평가 데이터, 호출 로그, 구독을 남겼습니다. 둘 다 이제 모든 레코드와 파일을 제거하는 하나의 루틴을 통해 실행되며, 삭제는 더 이상 외래 키를 적용하는 데이터베이스에서 실패하지 않습니다.
- **조직을 여전히 소유한 사용자는 더 이상 삭제할 수 없습니다.** 요청은 이제 명확한 메시지로 거부되어 소유권을 이전하거나(또는 조직을 삭제) 먼저 진행하도록 합니다. 모호하게 실패하거나 조직을 고아로 남기는 대신입니다.
- **에이전트를 삭제해도 더 이상 과거 대화가 중단되지 않습니다.** 에이전트를 참조한 대화는 역사적 기록으로 유지되며 단순히 에이전트 링크가 지워집니다. 삭제를 차단하는 대신입니다.
- **확인이 필요한 커넥터 작업은 더 이상 워크플로우에서 무인으로 실행될 수 없습니다.** 확인이 필요한 것으로 표시된 커넥터 작업은 이전에 승인 게이트가 자동으로 우회된 워크플로우 내에서 실행되었습니다. 단계는 이제 닫힌 상태로 실패하며 메시지가 표시되어 Human Intervention 노드(워크플로우 기본 승인 게이트)를 앞에 배치하거나 확인이 필요하지 않은 작업을 사용하도록 합니다.
- **워크플로우 단계는 더 이상 소유자의 MCP 자격 증명을 차용하지 않습니다.** 워크플로우의 MCP 서버에 소유자 자격 증명 폴백이 비활성화되었을 때, 소유자가 아닌 사용자가 해당 워크플로우를 실행하면 중지되는 대신 자동으로 소유자의 서버 자격 증명으로 폴백했습니다. 단계는 이제 명확한 메시지로 실패하여 자신의 자격 증명을 구성하도록 하며, 채팅 경로와 일치합니다.
- **워크플로우에서 수행된 커넥터 호출이 이제 감사 로깅됩니다.** 워크플로우 내에서 실행된 커넥터 작업은 커넥터 호출 로그에 항목을 남기지 않았습니다(채팅 시작 호출만 기록됨). 워크플로우 호출은 이제 동일한 감사 추적을 작성합니다.
- **이제 구독한 커넥터, 지식 기반 또는 MCP 서버를 에이전트에 연결할 수 있습니다.** 바인딩은 이전에 리소스를 *소유*해야 했으므로 합법적으로 구독한 커넥터(조직 공유 또는 Market 설치)는 "소유하지 않음"으로 거부되었습니다. 바인딩은 이제 앱의 나머지 부분이 사용하는 동일한 가시성 규칙을 따릅니다. 소유하거나 구독한 모든 것은 바인딩 가능합니다.
- **워크플로우 단계는 실제로 액세스 권한이 있는 커넥터만 호출할 수 있습니다.** 워크플로우의 커넥터 단계는 이전에 해당 커넥터가 존재하는 한 ID를 참조하는 모든 커넥터를 실행했습니다. 이제 실행자의 가시성(소유 또는 구독)을 적용하므로 공유 워크플로우는 액세스 권한이 없는 커넥터에 ID로 참조하여 도달할 수 없습니다.
- **지식 기반 검색이 이제 소유한 것뿐만 아니라 구독한 KB에 대해 작동합니다.** KB의 데이터는 소유자의 스토리지 아래에 있지만, 워크플로우 지식 기반 단계(및 에이전트 없는 지식 기반 채팅)는 이전에 호출자 자신의 스토리지 아래를 보았습니다. 따라서 공유된 KB를 검색하면 자동으로 아무것도 반환되지 않았습니다. 소유자는 이제 KB 자체에서 해결되며 검색은 액세스 확인됩니다(소유자 또는 구독자). 따라서 공유 KB는 결과를 반환하고 볼 수 없는 KB는 혼동스러운 빈 히트 대신 아무것도 반환하지 않습니다.

- **IPv4 매핑 IPv6 주소를 통한 SSRF 우회 차단.** IPv4 매핑 IPv6 리터럴(예: `http://[::ffff:169.254.169.254]/`)을 호스트로 하는 URL이 프라이빗 IP 차단 목록을 우회하여 듀얼 스택 호스트의 클라우드 인스턴스 메타데이터를 포함한 내부 서비스에 접근할 수 있었습니다. 이제 이러한 주소는 언래핑되어 IPv4 차단 목록에 대해 검사되므로, 모든 SSRF 보호 경로(웹 페치, HTTP 도구, 커넥터, RAG 임포터)에서 이 취약점이 해결됩니다.
- **MCP SSE / Streamable-HTTP 서버 URL이 이제 SSRF 검증됩니다.** 인증된 사용자가 MCP 서버를 내부 주소로 지정하고 서버를 테스트하거나 연결할 때 요청을 트리거할 수 있었습니다. 서버 URL은 이제 생성/업데이트 시 그리고 연결 시점에 다시 검증됩니다.
- **Docker Compose PostgreSQL 자격증명이 이제 `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB`를 통해 재정의 가능합니다.** 이전의 하드코딩된 `fim:fim` 기본값은 단일 소스(연결 문자열이 동일한 변수에서 파생됨)이며, 데이터베이스를 노출하기 전에 변경하도록 경고와 함께 문서화되어 있으므로, 운영자가 더 이상 실수로 기본 관리자 자격증명을 배포하지 않습니다.

### 수정됨

- **LLM 액세스가 더 이상 조용한 기간 후에 중단되지 않습니다.** 공유 HTTP 연결 풀이 시작 시 한 번 설치되고 모든 모델 호출에 재사용되었습니다. 시스템이 유휴 상태에 있으면 기본 클라이언트가 앱에서 닫힐 수 있으며, 그 후 모든 LLM 호출이 연결 오류로 실패하고 서비스를 다시 시작할 때까지 계속 실패했습니다. 이제 풀이 각 호출 전에 재검증되고 투명하게 재생성되므로 서비스가 재시작 없이 자동으로 복구됩니다.
- **채팅에서 메시지를 보낼 때 이제 지연 없이 즉시 스트리밍됩니다.** 이전에는 각 전송이 답변을 시작하기 전에 대화 기록의 전체 재로드에서 차단되었으므로 긴 채팅이 잠시 동안 멈춘 것처럼 느껴지고 매 턴마다 전체 기록을 다시 가져왔습니다. 완료된 턴이 이제 백그라운드에서 기록에 통합되므로 전송이 즉시 스트리밍되고 중복 재로드를 건너뜁니다.
- **확장된 추론이 이제 최신 Anthropic 모델(Opus 4.6+, Sonnet 4.6, Fable 5)에서 작동합니다.** 이러한 모델은 이전의 고정 예산 추론 매개변수를 제거했습니다. Opus 4.7/4.8 및 Fable 5는 400으로 거부하므로 추론 노력을 구성하면 오류가 발생하거나 조용히 아무것도 하지 않았습니다. 이제 이러한 모델에 대해 적응형 추론 프로토콜을 전송하고(더 이상 허용하지 않는 샘플링 매개변수 제거) 추론 노력이 올바르게 적용됩니다. 적응형 추론을 사용하지만 추론을 활성화할 수 없는 일반 OpenAI 호환 프록시를 통해 연결된 모델은 이제 조용히 실패하는 대신 명확한 경고를 기록합니다. Anthropic 제공자로 구성하여 추론을 활성화하세요.
- **강제 로그아웃이 이제 PostgreSQL에서 타임스탬프를 올바르게 비교합니다.** 세션 무효화 확인은 저장된 무효화 시간이 순진한 UTC라고 가정하고 이를 강제했으므로 PostgreSQL이 반환할 수 있는 시간대 인식 비-UTC 값에 대한 비교를 조용히 손상시켰습니다. 타임스탬프는 이제 재정의가 아닌 변환으로 UTC로 정규화되므로 취소된 토큰이 모든 백엔드에서 안정적으로 거부됩니다.
- **적용 훅이 이제 충돌할 때 닫힌 상태로 실패합니다.** 예외를 발생시킨 `PRE_TOOL_USE` 훅(예: 승인 게이트)은 이전에 `allow=True`를 반환했으므로 차단된 도구 호출이 어쨌든 진행되었습니다. 충돌하는 게이트가 조용히 우회가 되었습니다. PRE 훅은 이제 오류 시 기본적으로 거부합니다. 비적용 훅(속도 제한기, 로거)은 새로운 `fail_open` 플래그를 통해 이전의 실패 개방 동작을 유지합니다.
- **에이전트 답변이 더 이상 추론의 결론을 버리지 않습니다.** 추론 모델이 이미 최종 답변을 생성했을 때 파이프라인은 모델의 결론을 버릴 수 있는 두 번째의 손실이 많은 합성 호출을 했습니다. 그리고 대화가 압축되거나 컨텍스트 제한에 대해 보호되거나 다단계 계획을 통해 라우팅될 때 추론 세부 정보가 추가로 손실되었습니다. 루프는 이제 진정한 최종 답변을 그대로 스트리밍하고 추론은 압축, 컨텍스트 재구성 및 하위 에이전트 단계를 통해 전달되므로 표시되는 답변은 약화된 재설명 대신 전체 사고 체인을 반영합니다.

- **구독 갱신이 이제 청구 기간을 진행시킵니다.** 자동 갱신 시 표시된 기간 종료 날짜는 Stripe가 청구하고 구독을 앞으로 이동했음에도 불구하고 이전 주기에서 고정되어 있었습니다. 갱신 핸들러는 신뢰할 수 없는 송장 페이로드에서만 새 기간을 읽었습니다. 이제 Stripe에서 신뢰할 수 있는 기간 범위를 검색하므로, 주기 종료 날짜(및 할당량 리셋)가 모든 갱신 시 앞으로 이동합니다. 또한 이러한 구독을 취소하면 실제 기간 종료 시점이 아닌 즉시 계정을 다운그레이드할 수 있는 잠재적 위험을 제거합니다.
- **원본 도구 호출 프로토콜이 더 이상 에이전트 답변으로 유출되지 않습니다.** 모델이 일반 텍스트로 도구 호출을 즉흥적으로 생성할 때(예: `<tool_call>`/`<tool_response>` 블록 방출 — 사용 불가능한 도구에 도달할 때 일반적), 그 텍스트(내부의 모든 base64/파일 덤프 포함)가 회신에 그대로 표시될 수 있었습니다. 모든 답변 경로는 이제 이 의사 프로토콜을 제거하며, 파서는 추가로 `{"name","arguments"}` 방언을 유출되지 않는 진정한 도구 호출로 인식합니다.
- **에이전트 턴 중 간헐적인 `APIConnectionError: Connection error` 버스트.** 공유 HTTP 연결 풀은 최대 30초 동안 유휴 keep-alive 연결을 유지했습니다. 업스트림 릴레이 또는 NAT이 유휴 연결을 자동으로 회수하면, 다음 요청은 반쯤 죽은 소켓을 재사용하고 실패했습니다. Keep-alive 만료는 이제 기본적으로 짧은 5초입니다(턴 내의 따뜻한 연결은 여전히 재사용됨). 풀은 `LLM_HTTP_MAX_CONNECTIONS` / `LLM_HTTP_MAX_KEEPALIVE` / `LLM_HTTP_KEEPALIVE_EXPIRY`를 통해 조정 가능합니다. 신뢰할 수 없는 업스트림 뒤에서 연결 재사용을 완전히 비활성화하려면 `LLM_HTTP_MAX_KEEPALIVE=0`을 설정하세요.
- **API 키 사용 통계(`total_requests`, `last_used_at`)가 이제 모든 요청에서 유지됩니다.** 이전에는 증분이 요청의 데이터베이스 세션에 기록되었으며, 이는 자체 쓰기를 수행하는 엔드포인트에서만 커밋됩니다. 따라서 읽기 전용 API 키 호출(대시보드, 파일, 모델, 내보내기, …)은 카운터를 자동으로 롤백했습니다. 이제 사용량은 독립적이고 자체 커밋하는 세션에 기록되며, 요청 성공과 분리됩니다.

- **ReAct 에이전트가 이제 운영자가 승인 요청을 거부한 후 승인을 인정하고 중지합니다** — 다시 표현된 도구 호출을 재시도하는 대신.
- **연습장 "제안된 후속 질문"이 반환되고 이제 에이전트별로 선택 사항입니다**(기본값 꺼짐; 에이전트 설정의 새로운 `Follow-up Suggestions` 토글).

### 변경 사항

- Playground 로딩 표시기가 이제 미묘한 텍스트 shimmer를 사용합니다. 기존의 8초 후 가짜 진행률로 멈추는 진행 표시줄을 대체했습니다. 기존의 두 가지 shimmer 구현(`.shiny-text`와 `.text-shimmer`)을 단일 테마 인식 primitive로 통합했으며, 선택적 warm preset을 지원합니다.

### 수정됨

- `allow_fallback=false`이고 기본 자격증명만 있는(사용자별 자격증명 없음) 커넥터의 소유자가 만든 커넥터 호출이 더 이상 "Requires authentication" 401 오류를 반환하지 않습니다. 소유자는 이제 폴백 게이트에서 제외됩니다 — 해당 플래그는 *다른* 사용자가 소유자의 기본 자격증명을 빌릴 수 있는지만 제어합니다. 이전에는 소유자의 에이전트가 자동으로 인증되지 않은 요청을 보내고 있었으며, 같은 문제가 워크플로우 `connector_action` 노드에도 영향을 미쳤습니다.
- 대화 내보내기가 이제 자동 라우팅된 DAG 대화에 대해 올바른 모드 레이블("Planner" / "规划")을 표시합니다. 이전에는 항상 "Standard"로 표시되었습니다.
- 내보내기 타임스탬프가 이제 사용자가 설정한 시간대를 따릅니다. 원시 UTC를 표시하지 않습니다.

## [v0.8.3] - 2026-04-16

### 추가됨

- **`convert_to_markdown` 기본 제공 도구** — 모든 파일, URL, YouTube 링크 또는 데이터 URI를 Microsoft의 MarkItDown을 사용하여 깔끔한 Markdown으로 변환하는 새로운 범용 Agent 도구입니다. PDF, Word (.docx), Excel (.xlsx/.xls), PowerPoint (.pptx), HTML, JSON, CSV, XML, ZIP, EPUB, Outlook .msg, 이미지, 오디오(음성 → 텍스트) 및 YouTube 자막을 지원합니다. 모든 agent에서 기본적으로 사용 가능하며 `web_fetch`와 동일한 계층입니다. 비전 기능이 있는 LLM이 구성되면 공식 `markitdown-ocr` 플러그인을 통해 임베드된 이미지와 스캔된 PDF 페이지가 자동으로 OCR됩니다. 이전에는 이 기능이 백그라운드 RAG 수집 파이프라인 내에 숨겨져 있었으며, 이제 agent는 대화형 경로에서 사용할 수 있습니다.
- **`markitdown-ocr`을 통한 문서 OCR** — DOCX / XLSX / PPTX의 임베드된 이미지와 스캔된 PDF 페이지는 이제 FIM One의 나머지 부분이 라우팅하는 동일한 비전 기능이 있는 LLM을 사용하여 OCR됩니다. 기본 제공 `convert_to_markdown` 도구와 RAG 수집 파이프라인 모두에 적용되므로 채팅 시간 변환과 지식 기반 수집이 동일한 입력에 대해 바이트 동일의 Markdown을 생성합니다.
- **문서 OCR을 위한 범용 비전 제공자 지원** — 새로운 `LiteLLMOpenAIShim` 덕 타입은 모든 FIM One `OpenAICompatibleLLM`을 openai SDK의 `.chat.completions.create(...)` API 형태로 래핑한 다음 `litellm.completion()`을 통해 디스패치합니다. MarkItDown(openai SDK 표면을 하드코딩함)은 이제 Anthropic Claude, Google Gemini, Azure, Bedrock 및 LiteLLM이 지원하는 다른 모든 제공자를 사용할 수 있습니다 — FIM One에서 제공자별 어댑터 코드가 필요 없습니다.
- **비전 인식 RAG 수집** — Office 문서 및 스캔된 PDF의 지식 기반 업로드는 이제 워크스페이스의 기본 비전 LLM(DB 우선, ENV 폴백)을 확인하고 수집 중 OCR을 위해 MarkItDown으로 전달합니다. 제로 회귀: 비전 기능이 있는 모델을 사용할 수 없을 때 수집은 자동으로 텍스트 전용 모드로 폴백됩니다 — 정확히 기능 이전 동작입니다.
- **확장된 MarkItDown 형식 커버리지** — RAG는 이제 MarkItDown의 오디오 전사 및 outlook 추가 기능을 통해 `.pdf`, `.msg`(Outlook), `.epub`, `.mp3`, `.wav` 및 `.m4a`를 기본적으로 수집합니다. YouTube URL은 `markitdown[youtube-transcription]`을 통해 `convert_to_markdown`으로 흐릅니다.
- **`LLM_SUPPORTS_VISION` 환경 변수** — ENV 모드 문서 OCR 폴백에 대한 선택적 옵트아웃(`=false`). 기본 동작은 낙관적(`true`)이며, 일반적인 ENV 설정(`gpt-4o`, `claude-3-5-sonnet`, `gemini-1.5-pro/flash`)을 포함합니다. ENV로 구성된 `LLM_MODEL`이 비전을 지원하지 않을 때만 `false`로 설정하십시오(예: `deepseek-v3`, `qwen-chat`, `llama-3.1`, `gpt-3.5-turbo`, `o1-mini`). 모든 문서 업로드에서 실패한 비전 호출을 건너뛰려면 `false`로 설정하십시오. 관리자가 선별한 ModelGroup이 활성화되면 완전히 무시됩니다 — DB 모드는 사용 가능할 때 항상 신뢰할 수 있는 소스입니다.
- **턴 수준 프로파일러** — 각 ReAct 턴은 이제 단계 수준 타이밍(`memory_load`, `compact`, `tool_schema_build`, `llm_first_token`, `llm_total`, `tool_exec`)을 턴당 단일 구조화된 로그 라인에 기록합니다. `REACT_TURN_PROFILE_ENABLED`를 통해 토글 가능합니다(기본값: 켜짐; 제로 오버헤드 no-op의 경우 `false`로 설정).
- **구조화된 컴팩트 작업 카드** — 대화 컴팩션은 이제 자체 9섹션 마크다운 출력을 입력된 `WorkCard`로 파싱하고 새로운 컴팩트를 이전 카드에 병합하므로 긴 세션 초반의 오류 및 보류 중인 작업이 처음부터 다시 요약되는 대신 여러 컴팩션 라운드에서 유지됩니다.

- **사용자별 속도 제한** — LLM 계층 속도 제한기가 이제 단일 프로세스 전역 버킷 대신 사용자별로 별도의 버킷을 유지합니다. 한 명의 시끄러운 사용자가 같은 워커의 다른 모든 사용자를 제한하는 것을 방지합니다. `LLM_RATE_LIMIT_PER_USER`를 통해 토글 가능합니다(기본값: 켜짐).

### 수정됨

- **중단된 tool_use 복구** — 도구 실행 중 중단된 대화(사용자 Stop, SSE 연결 해제, 충돌)는 이전에 `tool_use` 블록이 있지만 일치하는 `tool_result`가 없는 어시스턴트 메시지를 남겨두어 다음 턴에서 LLM API로부터 불명확한 HTTP 400 오류가 발생했습니다. `DbMemory.get_messages()`는 이제 읽기 경로에서 이러한 중단된 블록을 감지하고 합성된 `[interrupted]` tool_result로 복구합니다. 원본 DB 로그는 변경되지 않습니다.
- **tool_calls가 있는 빈 콘텐츠 어시스턴트 메시지가 더 이상 삭제되지 않음** — DbMemory 로드 경로 필터는 이전에 빈 텍스트 콘텐츠가 있는 어시스턴트 행을 자동으로 삭제했습니다. 네이티브 함수 호출 중간 단계(텍스트 없이 `tool_calls`만 포함)가 제거되고 있었습니다. 필터는 이제 빈 콘텐츠와 `tool_calls` 없음을 모두 요구합니다.
