## [v0.8.7] - 2026-06-10

### 보안

- **2단계 인증 우회 보안 취약점을 해결했습니다.** API 및 채팅/SSE 인증은 이제 정상적인 액세스 토큰이 필요하며(SSE 스트리밍도 단기 티켓 수락), 2FA 임시 토큰, 새로고침 토큰, 바인드/SSE 티켓(모두 동일한 키로 서명됨)은 더 이상 인증을 위해 재사용될 수 없으므로, 도용된 비밀번호만으로는 2단계 요소를 건너뛸 수 없습니다.
- **OAuth 로그인은 더 이상 확인되지 않은 이메일의 기존 계정을 자동으로 연결하지 않습니다.** 타사 계정은 공급자가 해당 이메일을 확인됨으로 표시할 때만 이메일로 로컬 계정과 일치하므로, 공격자가 제어하는 확인되지 않은 주소를 통한 탈취를 방지합니다.

### 추가됨

- **`file_ops.apply_patch` — V4A 형식 diff 패치를 파일에 적용합니다.** 에이전트가 라인 기반 청크와 퍼지 공백 매칭을 사용하여 여러 줄 편집을 수행할 수 있도록 하며, 정확한 부분 문자열 매칭이 취약한 경우를 보완하는 기존 `find_replace`를 보완합니다.
- **입출력 검증을 위한 컨텐츠 가드레일.** 새로운 `core/agent/guardrail` 레이어가 기존 도구 권한 게이트 및 보안 검사와 함께(대체하지 않음) 실행됩니다. 입력 가드레일(기본값: 탈옥 구문 탐지기)은 모든 LLM 호출 전에 실행되며 트리거되면 턴을 중단하여 토큰을 절약하고 채팅에 명확한 "차단됨" 공지를 표시합니다. 출력 가드레일은 최종 답변 후에 실행됩니다. `FIM_GUARDRAILS_INPUT` / `FIM_GUARDRAILS_OUTPUT` 환경 변수를 통해 구성 가능하며, 에이전트별 UI 구성은 향후 릴리스에서 제공될 예정입니다.

### Changed

- **`/settings?tab=billing`은 이제 전체 너비로 렌더링되며 나머지 Settings 탭과 시각적으로 일치합니다.** `max-w-4xl` 너비 제한과 중복된 외부 스크롤 컨테이너를 제거했습니다. 페이지 제목 아이콘을 삭제하고, 플랜/사용량/구독/플랜 비교 카드를 Usage 탭과 동일한 lean bordered-div 패턴(간결한 레이블 + `tabular-nums` 숫자)을 사용하도록 재작성했습니다. 이전 레이아웃은 settings 프레임에 실수로 끼워진 독립적인 페이지처럼 보였습니다.

### 수정됨

- **토큰 할당량이 이제 매월 1일이 아닌 청구 날짜에 리셋됩니다.** 사용량은 항상 구독 시기와 관계없이 달력 월 단위로 계산되었으므로, 유료 사용자는 20일에 청구되지만 1일까지 새로운 할당량을 기다려야 했습니다. 월말에 시작한 구독은 며칠 후 사실상 두 번째 전체 할당량을 받았습니다. 이제 할당량은 각 구독의 월간 기념일에 리셋되며(무료 사용자는 여전히 달력 월에 리셋됨), 연간 청구 플랜은 연 1회가 아닌 매월 올바르게 충전됩니다. 플랜 및 청구 탭, 사용량 카드, 할당량 초과 대화상자는 이제 모두 동일한 기간 동안 사용량을 측정하고 리셋 날짜를 표시하므로, 표시된 "이 기간의 사용량"이 채팅이 실제로 중단되는 시점과 일치합니다.
- **구독 갱신이 이제 청구 기간을 진행시킵니다.** 자동 갱신 시 표시된 기간 종료 날짜는 Stripe가 청구하고 구독을 앞으로 이동했음에도 불구하고 이전 주기에서 고정되어 있었습니다. 갱신 핸들러는 신뢰할 수 없는 송장 페이로드에서만 새 기간을 읽었습니다. 이제 Stripe에서 권한 있는 기간 범위를 검색하므로, 주기 종료 날짜(및 할당량 리셋)는 모든 갱신 시 앞으로 이동합니다. 이는 또한 이러한 구독을 취소하면 실제 기간 종료 대신 계정이 즉시 다운그레이드될 수 있는 잠재적 위험을 제거합니다.
- **원본 도구 호출 프로토콜이 더 이상 에이전트 답변으로 유출되지 않습니다.** 모델이 일반 텍스트로 도구 호출을 즉흥적으로 생성할 때(예: `<tool_call>`/`<tool_response>` 블록 방출 — 사용 불가능한 도구에 도달할 때 일반적임), 그 텍스트(내부의 base64/파일 덤프 포함)가 회신에 그대로 표시될 수 있었습니다. 모든 답변 경로는 이제 이 의사 프로토콜을 제거하며, 파서는 추가로 `{"name","arguments"}` 방언을 유출되지 않는 진정한 도구 호출로 인식합니다.
- **에이전트 턴 중 간헐적인 `APIConnectionError: Connection error` 버스트.** 공유 HTTP 연결 풀은 유휴 keep-alive 연결을 최대 30초 동안 유지했습니다. 업스트림 릴레이 또는 NAT이 유휴 연결을 자동으로 회수하면, 다음 요청은 반쯤 죽은 소켓을 재사용하고 실패했습니다. Keep-alive 만료는 이제 기본적으로 짧은 5초입니다(턴 내 따뜻한 연결은 여전히 재사용됨). 풀은 `LLM_HTTP_MAX_CONNECTIONS` / `LLM_HTTP_MAX_KEEPALIVE` / `LLM_HTTP_KEEPALIVE_EXPIRY`를 통해 조정 가능합니다. 신뢰할 수 없는 업스트림 뒤에서 연결 재사용을 완전히 비활성화하려면 `LLM_HTTP_MAX_KEEPALIVE=0`을 설정하세요.
- **API 키 사용량 통계(`total_requests`, `last_used_at`)가 이제 모든 요청에서 유지됩니다.** 이전에는 증분이 요청의 데이터베이스 세션에 기록되었으며, 이는 자체 쓰기를 수행하는 엔드포인트에서만 커밋됩니다. 따라서 읽기 전용 API 키 호출(대시보드, 파일, 모델, 내보내기, …)은 카운터를 자동으로 롤백했습니다. 이제 사용량은 독립적이고 자체 커밋하는 세션에 기록되어 요청 성공과 분리됩니다.

## [v0.8.6] - 2026-05-08

### 추가됨

- **Stripe 결제 — Pro 플랜 구독.** `/settings?tab=billing` 하의 새로운 `Plan & Billing` 탭에서 현재 플랜, 월간 토큰 사용량, 기간 리셋, `Upgrade to Pro`(Stripe Checkout) 또는 `Manage subscription`(Customer Portal) 중 하나를 표시합니다. 성공한 체크아웃은 구매한 플랜을 표시하는 축제 모달을 열며, 리다이렉트 파라미터는 해제 후에만 제거되므로 새로고침이 다시 트리거되지 않습니다. 할당량 적용은 각 사용자의 플랜을 존중하고, 취소된 구독은 유료 기간이 끝날 때까지 Pro로 유지되며, 스트림 중 402 할당량 대화상자는 이제 결제 탭에 표시됩니다. 관리자는 Admin Panel → Billing 아래에서 플랜을 관리하고 구독을 검색합니다. Pro는 현재 Stripe **테스트 모드** 가격을 사용하며, 프로덕션 전환 시 가격 ID를 교체합니다.
- **관리자 제어 결제 기능 플래그.** Admin → System Settings의 `Enable Stripe Billing` 토글이 전체 Stripe 파이프라인을 제어합니다 — 사용자 대면 `/api/billing/*`, Stripe 웹훅, 관리자 플랜/구독 CRUD, 그리고 프론트엔드 결제 탭 + 관리자 탐색이 모두 해제되면 숨겨지거나 503이 반환됩니다. 첫 활성화 시 Free + Pro를 시드하고, `default_plan_id` 포인터를 설정하며, `users.plan_id`를 역순 채웁니다. 이후 해제/활성화는 순수 플래그 전환입니다. Stripe 자격증명이 없는 프라이빗 배포는 깔끔하게 유지됩니다. 결제가 해제되었을 때 할당량 체인은 관리자 설정 `Default Monthly Token Quota`로 폴백됩니다.
- **사용자별 무제한 할당량 + Registered 열.** 빈 할당량 필드는 글로벌 제한을 상속받고, `0`은 무제한을 부여합니다. 이전에는 둘 다 동일한 상태로 축소되었습니다. 사용자 테이블에는 Registered 열도 추가됩니다.
- **영어 이외의 문서(`zh` / `ja` / `ko` / `de` / `fr`)에서 이제 완전한 API Reference 및 Channels Configuration 섹션을 표시합니다** — `Endpoints` 그룹과 `Configuration > Channels` 하위 그룹은 이전에 영어 전용이었습니다.

### 변경 사항

- **`Plan & Billing`은 Settings 탭이며, 독립 페이지가 아닙니다.** `/settings/billing`을 `/settings?tab=billing`로 다시 통합하여 사용자가 플랜을 전환할 때 왼쪽 탐색이 표시된 상태로 유지됩니다(GitHub / Linear / Notion과 일치). 독립 경로는 리디렉션되므로 이전 북마크 및 이전 배포 Stripe Checkout 반환 URL이 계속 작동합니다. `Subscriptions` 탭은 플랜 구독과의 구분을 위해 `Marketplace`로 이름이 변경되었습니다.
- **Free 플랜 할당량은 관리자 Plans 페이지에서 읽기 전용입니다.** System Settings → Default Monthly Token Quota에서 가져오며, 거기서 편집하면 자동으로 전파됩니다. 백엔드는 Free 플랜에 대해 PATCH의 `monthly_token_quota`를 무시합니다.
- **Token 할당량은 청구 페이지, 플랜 카드 및 관리자 Plans 테이블 전체에서 `5M` / `100K`로 렌더링됩니다.** 관리자 INPUT 필드는 여전히 원시 숫자를 받습니다.
- **번역 권한이 로케일별 파일에서 단일 용어집으로 이동했습니다.** 규칙은 [`scripts/translation-glossary.md`](https://github.com/fim-ai/fim-one/blob/master/scripts/translation-glossary.md)에 저장되며, 모든 LLM 번역 호출(JSON, MDX, README)에 로드됩니다. 사전 커밋 훅은 생성된 로케일 파일의 수동 편집을 거부합니다. 오역을 수정하려면 용어집을 편집하고 `--force`로 재생성합니다.
- **라이선서 및 준거법.** FIM One Source Available License는 이제 **FIM Labs Pte. Ltd.**(싱가포르)에서 부여됩니다. 준거법은 중국에서 싱가포르로 변경되며, 분쟁은 싱가포르 SIAC 중재로 진행됩니다(중재인 1명, 영어). 새로운 최상위 `NOTICE` 파일은 R&D 기여도, 상표 및 제3자 컴포넌트 정책을 기록합니다. 허용 사용 또는 제한 조건의 변경 사항은 없습니다.

### 수정 사항

- **관리자의 에이전트, 커넥터, 지식 기반 및 MCP 서버 승인/거부가 더 이상 PostgreSQL에서 실패하지 않습니다.** publish-review `reviewed_at` 열이 이제 타임존을 인식하므로 PG에서 승인 쓰기가 성공합니다(이 버그는 SQLite 개발 데이터베이스에서는 눈에 띄지 않았습니다).
- **OAuth 사용자가 다시 세션을 새로고칠 수 있습니다.** OAuth에서 발급한 새로고침 토큰이 새로고침 엔드포인트가 일치시킬 수 없는 형식으로 저장되어 액세스 토큰이 만료되면 재로그인을 강제했습니다. 이제 다른 모든 경로처럼 다이제스트로 저장됩니다.
- **브라우저 탭 제목이 `/settings` 및 `/admin`의 활성 하위 탭을 반영합니다** (예: `Settings · Billing — FIM One`). 따라서 여러 개의 고정된 탭을 구별할 수 있습니다.
- **사용량 페이지가 더 이상 관리자가 기본 토큰 할당량을 설정했을 때 "Unlimited"로 보고하지 않습니다** — 이제 통합 할당량 체인을 통해 해결됩니다(사용자당 재정의 → 요금제 계층 → 시스템 기본값).
- **에이전트 설정: 바운드 리소스가 더 이상 진입 시 "(已删除)"로 깜빡이지 않습니다.** 고아 배지가 인벤토리 가져오기가 정착할 때까지 기다린 후 렌더링됩니다.
- **토스트가 이제 라이트/다크 테마를 따릅니다** (하드코딩된 다크 대신).
- **에이전트별 사용량 분석이 더 이상 삭제된 에이전트와 연결된 대화에 대해 "Direct Chat" 행을 복제하지 않습니다.**
- **자체 호스팅된 `./deploy.sh`이 더 이상 `container name already in use` 오류로 실패하지 않습니다** — `docker compose up` 전에 해시 접두사 좀비 컨테이너 및 DooD 샌드박스 자식을 정소합니다.
- **푸시 후 더 이상 중복 `chore(i18n): sync translations` 커밋이 없습니다** — 사전 커밋 번역 훅이 이제 번역된 파일과 함께 `.translation-cache.json`을 스테이징합니다.
- **에이전트 채팅이 더 이상 바운드되지 않은 에이전트 세션에서 확인이 필요한 도구가 실행될 때 충돌하지 않습니다** — 게이트가 라우팅할 에이전트가 없을 때 우아하게 나옵니다.
- **재시도가 더 이상 중단된 턴의 고아 사용자 메시지를 포함하는 이력이 있을 때 엄격한 교대 제공자(Claude)에서 실패하지 않습니다** — 동일한 역할의 연속 메시지가 디스패치 전에 단일 턴으로 축소됩니다.
- **연습장 재시도가 더 이상 스트림 전 윈도우 중에 쿼리를 잠깐 두 번 표시하지 않습니다.**
- **ReAct 에이전트가 이제 운영자가 승인 요청을 거부한 후 인정하고 중지합니다** (재의용된 도구 호출을 재시도하는 대신).
- **연습장 "제안된 후속 질문"이 반환되며 이제 에이전트당 선택 가능합니다** (기본값: 끄짐, 에이전트 설정의 새로운 `Follow-up Suggestions` 토글).

## [v0.8.5] - 2026-04-23

### Added

- **기여자 친화적 i18n 워크플로우**: 기여자는 더 이상 영어 소스 파일을 수정하는 PR을 제출하기 위해 `LLM_API_KEY`를 구성할 필요가 없습니다. 로컬 pre-commit 번역 단계를 건너뛸 경우(키 없음), 새로운 `.github/workflows/i18n-sync.yml` 워크플로우가 PR 병합 후 `master`에서 EN → ZH/JA/KO/DE/FR로 번역하고 자동으로 커밋합니다. pre-commit 훅은 이제 생성된 로케일 파일의 수동 편집을 거부하며(`ALLOW_LOCALE_EDIT=1` 오버라이드로 정당한 번역 수정 가능), EN 소스와 번역된 출력 간의 무성 드리프트를 방지합니다.
- **i18n CI 폴백 엔드-투-엔드 검증됨**: smoke-test push(EN만, 로컬 translate 훅 건너뜀)로 GitHub Actions 워크플로우가 변경된 소스를 감지하고, 5개 로케일 모두로 번역하며, 재귀를 방지하기 위해 `[skip ci]`로 master에 자동 커밋하는 것을 확인했습니다.
- **Exa 통합 문서 페이지**: 사이드바에 전용 Integrations 섹션이 있고, 첫 번째 클래스의 Exa 페이지가 전체 Exa 검색 표면(neural / fast / deep-reasoning / instant), 필터링, 콘텐츠 검색 및 뉴스 모니터링, 연구 논문 검색 및 심층 추론 에이전트를 위한 3가지 조정된 사전 설정을 다룹니다. 파트너 대면 Exa 통합 디렉토리 랜딩 페이지로 제공됩니다.
- **信创(Xinchuang) 데이터베이스 지원**: 데이터베이스 커넥터는 이제 PostgreSQL/MySQL과 함께 KingbaseES(人大金仓), HighGo(瀚高), DM8(达梦)을 나열합니다. KingbaseES와 HighGo는 PG 호환이며 추가 종속성 없이 `asyncpg`를 재사용합니다. DM8은 공식 `dmPython` 공급업체 wheel을 사용합니다. 독립 실행형 `scripts/test_xinchuang_dbs.py`를 통해 운영자는 CLI에서 실시간 연결을 확인할 수 있습니다.
- **Feishu Channel + 확인 게이트(IM 경유)**: 새로운 `Channel` 리소스 유형(조직 범위, 암호화된 저장 자격증명)을 통해 조직은 아웃바운드 메시징용 Feishu 앱을 연결할 수 있습니다. `requires_confirmation=True`로 플래그된 도구는 이제 포털의 확인 대화 상자에만 표시되는 대신 구성된 Feishu 그룹에 Approve/Reject 대화형 카드를 전송합니다. 그룹의 모든 권한 있는 멤버는 Feishu에서 직접 승인 또는 거부할 수 있습니다. Settings → Channels 관리 UI(목록, 생성/편집 및 더티 상태 보호, 복사 가능한 콜백 URL을 포함한 세부 정보, 테스트 전송), CRUD API(`/api/channels`) 및 서명 검증 및 URL 챌린지 지원을 포함하는 Feishu 이벤트 콜백 엔드포인트(`/api/channels/{id}/callback`)를 다룹니다. v0.9 IM Channel Integration 로드맵 항목의 첫 번째 단계이며, 2026-04-24 로드쇼를 위해 일찍 배포됩니다.
- **Agent Hook System(스켈레톤)**: `src/fim_one/core/hooks/`의 새로운 `PreToolUseHook` / `PostToolUseHook` 추상화를 통해 결정론적 로직이 LLM 루프 외부에서 실행될 수 있습니다. FeishuGateHook이 첫 번째 구체적인 구현이며, 확인 게이트 흐름에 연결됩니다. 전체 hook 라이프사이클과 사용자 정의 YAML 훅은 v0.9 범위로 유지됩니다.
- **Hook System이 이제 ReAct 및 DAG 런타임에서 활성화됨**: `model_config_json`에서 `hooks.class_hooks`를 선언하는 에이전트는 모든 채팅 세션에서 해당 훅이 인스턴스화되고 등록됩니다. 첫 번째 소비자인 `FeishuGateHook`은 에이전트가 커넥터 작업이 `requires_confirmation=True`로 플래그된 도구를 호출할 때 자동으로 실행되고, 조직의 Feishu 그룹에 Approve/Reject 카드를 게시하며, 도구를 차단하고 판정에 따라 재개하거나 중단합니다. 이전에는 훅 추상화가 제자리에 있었지만 웹 레이어의 아무것도 실시간 채팅에 연결하지 않았습니다.
- **Channels 및 Hook System 아키텍처 문서화됨**: 새로운 `docs/architecture/hook-system.mdx`는 3가지 훅 포인트를 설명하고, 훅이 LLM 루프 외부에서 실행되는 이유를 설명하며, FeishuGateHook을 엔드-투-엔드로 진행합니다. 기존 아키텍처 페이지(system-overview, organization, react-engine, philosophy)는 이를 상호 링크합니다. README는 이제 Messaging Channels를 첫 번째 클래스의 v0.8 기능으로 나열하고 Application Layer 다이어그램은 Portal/API/iframe과 함께 IM 타겟을 포함합니다.
- **Hook Approval Playground**: Channels 세부 정보 시트에는 이제 민감한 도구 호출을 시뮬레이션하고, 실제 확인 카드를 연결된 Feishu 그룹에 푸시하며, 검토자의 결정을 실시간으로 폴링하는 "Test Approval Flow" 작업이 있습니다. 기존 미리보기 버튼과 달리 전체 프로덕션 경로(진정한 `ConfirmationRequest` 행, 실제 Feishu 콜백, 상태 전환)를 실행하므로 데모와 출시 전 리허설은 프로덕션 훅이 사용할 동일한 코드 경로를 사용합니다.

- **에이전트당 작업 완료 알림**: 에이전트는 이제 장기 실행 ReAct 또는 DAG 작업이 완료되면 조직의 채널(현재 Feishu)에 요약 카드를 푸시할 수 있습니다. Settings → Agent → Notifications에서 에이전트당 구성 가능합니다. 일반 아웃바운드 알림 패턴의 첫 번째 소비자입니다.
- **구성 가능한 확인 게이트 — 인라인 *또는* 채널**: 모든 에이전트는 이제 Settings에 "Approval" 섹션이 있으며 3가지 라우팅 모드(Auto / Inline only / Channel only), 승인자 범위 선택기(initiator / agent owner / 조직의 누구나), "모든 도구 호출에 대해 확인 필요" 오버라이드 및 명시적 승인 채널 선택기를 포함합니다. Auto 모드는 연결된 채널이 있으면 그것을 사용하고 그렇지 않으면 채팅 스트림의 인라인 승인 카드로 정상적으로 폴백합니다. 따라서 채널이 없는 에이전트는 자동으로 실패하는 대신 실제 승인 UX를 가집니다. 새로운 `POST /api/confirmations/{id}/respond` 엔드포인트는 Feishu 웹훅과 단일 결정 기록 경로를 공유하므로 모든 승인(채팅에서 클릭하든 Feishu 그룹에서 클릭하든)이 동일한 `approver_user_id` 및 `decided_at` 감사 필드를 기록합니다.

### 변경됨

- Playground 로딩 지표가 이제 8초 후 가짜처럼 보이는 진행률 표시줄 대신 세밀한 텍스트 shimmer를 사용합니다. 기존의 두 가지 shimmer 구현(`.shiny-text`와 `.text-shimmer`)을 선택적 warm 프리셋이 있는 단일 테마 인식 primitive로 통합했습니다.
- Connector 카드는 이제 connector에서 `allow_fallback`이 비활성화되었을 때 "Private default" 배지(tooltip 포함)를 표시하므로 소유자가 한눈에 모든 사용자가 자신의 자격증명을 가져와야 하는 connector를 확인할 수 있습니다. connector 설정 양식의 Allow-Fallback 토글 아래 도움말 텍스트도 플래그가 다른 사용자와의 공유만 제한한다는 점을 명확히 합니다 — 소유자는 항상 자신의 기본 자격증명을 사용할 수 있습니다.

### 수정됨

- `allow_fallback=false`이고 기본 자격증명만 있는(사용자별 자격증명 없는) 커넥터 소유자가 만든 커넥터 호출이 더 이상 "Requires authentication" 401 오류를 반환하지 않습니다. 소유자는 이제 폴백 게이트에서 제외됩니다——해당 플래그는 *다른* 사용자가 소유자의 기본 자격증명을 빌려갈 수 있는지만 제어합니다. 이전에는 소유자의 에이전트가 자동으로 인증되지 않은 요청을 보내고 있었으며, 동일한 문제가 워크플로우 `connector_action` 노드에도 영향을 미쳤습니다.
- 대화 내보내기가 항상 "Standard"를 표시하는 대신 자동 라우팅된 DAG 대화에 대해 올바른 모드 레이블("Planner" / "规划")을 표시합니다.
- 내보내기 타임스탬프가 이제 원시 UTC를 표시하는 대신 사용자가 구성한 시간대를 반영합니다.
- 업로드된 파일 내용이 더 이상 내보낸 대화에 유출되지 않으며, 사용자의 메시지 텍스트만 포함됩니다.
- 병렬 도구 호출이 더 이상 스트리밍된 도구 호출 델타마다 `index=0`을 재사용하는 제공자와 충돌하지 않습니다. 집계자는 이제 ID 또는 이름 변경을 통해 경계를 감지하고 후속 델타를 올바른 슬롯으로 다시 매핑합니다.
- 설정 → 채널이 현재 사용자의 조직 역할을 반영합니다. 멤버(관리자/소유자가 아닌 사용자)는 비활성화된 "새 채널" 버튼, 숨겨진 편집/활성화-비활성화/삭제 작업, 읽기 전용 배너, 권한 인식 빈 상태를 봅니다——제출 시 "Organization admin access required" 오류로 실패하는 활성화된 CTA 대신입니다.
- 세션 만료 리다이렉트가 이제 쿼리 문자열을 유지하므로, 사용자가 재인증 후 기본 경로 대신 보고 있던 정확한 탭/필터로 돌아갑니다.
- Feishu 채널 양식이 더 이상 대화 위에 계층화된 채팅 선택기와 상호 작용할 때 "저장하지 않은 변경 사항 버리시겠습니까?" 메시지를 표시하지 않습니다.
- Feishu 채널 설정 힌트가 더 이상 UI 자체가 이미 중국어일 때 중국어 레이블을 중복으로 표시하지 않습니다(예: 이전에 "事件与回调 (事件与回调)"로 렌더링됨).
- 스키마 관리자의 "모두 주석 추가"가 더 이상 500 내부 서버 오류를 반환하지 않습니다——전체 주석 백엔드 경로에 모든 호출을 차단했던 바인딩되지 않은 변수 버그가 있었습니다.
- 데이터베이스 커넥터를 편집하면 이제 3점 마스킹된 텍스트 대신 암호 필드에 `********` 자리 표시자를 표시하므로, 필드를 비워두면 저장된 암호가 유지됨을 명확히 합니다.
- 커넥터 작업을 업데이트하면 더 이상 상세 패널이 축소되지 않습니다——편집된 작업이 선택된 상태로 유지되므로 사용자가 계속 반복할 수 있습니다.
- AI 커넥터 편집기가 이제 세 가지에 대해 동일한 "completed" 메시지를 표시하는 대신 성공, 부분 실패, 완전 실패를 구별합니다. 실패 이유가 인라인으로 표시되므로 사용자가 실제로 무엇이 잘못되었는지 볼 수 있습니다.
- AI 커넥터 편집기가 더 이상 한 번에 여러 작업을 자동으로 삭제할 수 없습니다. 대량 삭제(>2개 작업)는 이제 사용자의 지시에 명시적인 파괴적 키워드("rebuild", "全部重建", "wipe" 등)가 필요합니다. 그렇지 않으면 작업이 명확한 오류로 거부되어 `requires_confirmation` / JMESPath 설정을 실수로 손실되지 않도록 보호합니다.
- 포털 채팅의 확인 카드가 이제 요청이 채널(예: Feishu)로 라우팅되었는지 또는 인라인으로 처리되었는지 표시하며, 누가 승인할 수 있는지(개시자, 에이전트 소유자 또는 조직 멤버)에 대한 인간이 읽을 수 있는 힌트와 함께 표시합니다. 채널로 라우팅된 요청은 사용자가 알림이 실제로 전송되었는지 궁금해하지 않도록 인라인 보류 중 카드도 생성합니다.
- Feishu 승인 카드가 이제 첫 번째 결정 후 읽기 전용이 됩니다. `/callback` 웹훅이 승인/거부 버튼이 제거되고 헤더가 녹색(승인됨) 또는 빨간색(거부됨)으로 칠해진 대체 카드를 반환하여 반복된 클릭을 방지합니다. 구식 Feishu 클라이언트에서 여전히 도착하는 중복 클릭은 "This request was already approved/rejected." 토스트와 결정된 카드의 신선한 사본을 받아 구식 보기가 따라잡을 수 있습니다.
- 채널 행과 상세 시트에서 일반 "Send Test Message" 작업을 복원했습니다. 승인 playground는 전체 훅 왕복을 수행하지만, 승인 훅이 연결되지 않은 알림 전용 채널은 여전히 빠른 자격증명/연결 상태 확인이 필요하며, 이를 일반 테스트 전송이 담당합니다.
- 동일한 Feishu 승인 카드에 대한 동시 클릭이 더 이상 모두 성공할 수 없습니다. `/callback` 핸들러가 이제 조건부 `UPDATE ... WHERE status='pending'`를 통해 `ConfirmationRequest` 상태를 전환하고 영향받은 행 수를 사용하여 어느 호출자가 "이겼는지" 결정합니다. 이전에는 두 병렬 요청이 모두 `pending`을 읽고 쓰기 경합을 할 수 있어 잠재적으로 동일한 행에서 승인된 후 거부되는 결과가 나올 수 있었습니다.
- 보류 중인 승인 요청이 이제 배경 청소기를 통해 `CHANNEL_CONFIRMATION_TTL_MINUTES`(기본값 24시간) 후 자동으로 만료됩니다. 며칠 후 구식 클릭이 이미 해제된 에이전트 상태를 전환하는 것을 방지합니다. 만료된 카드에 대한 다음 클릭이 회색 "Expired" 결정 카드와 "no longer active" 토스트를 받습니다.
- Send Test Message가 이제 일반 텍스트 알림(승인/거부 버튼 없음)을 전달하며 행 드롭다운이 아닌 채널 상세 시트에만 있습니다. 승인 훅을 사용할 의도가 없는 사용자는 "test" 메시지의 대화형 버튼으로 인해 혼동되지 않습니다. 승인 왕복 테스트는 승인 Playground 버튼을 통해 계속 사용 가능합니다.
- 채널 상세 시트가 강화됨: "설정을 마치는 방법"이 이제 기본적으로 축소된 축소 가능한 섹션입니다(이미 구성된 채널의 시트를 지배하지 않도록), 외부 패딩이 감소되어 콘텐츠가 시트 가장자리에 더 가깝게 배치됩니다.
- Builder AI가 더 이상 마스킹된(`****`) 자격증명을 누락된 것으로 보고하지 않습니다——이제 이를 구성된 것으로 인식하고 거짓 "credential missing" 지침을 건너뜁니다.
- Playground 에이전트 목록이 이제 게시된 것만 대신 액세스 가능한 모든 에이전트를 표시하므로, 초안 에이전트를 먼저 게시하지 않고 테스트할 수 있습니다.

- **더 똑똑한 완료 확인** — 긴 상세 답변(>200 토큰)에 대해서는 사후 답변 확인 단계를 건너뛰어 불필요한 LLM 왕복을 제거합니다.
- **제공자 중단 시 모델 폴백** — 기본 모델을 사용할 수 없을 때(속도 제한, 과부하 또는 다운), 에이전트는 전체 대화를 실패시키지 않고 자동으로 빠른 모델로 재시도합니다.

### 수정됨

- **읽을 수 없는 파일에 대한 AI 에이전트 환각** — AI 에이전트가 파일을 읽을 수 없을 때(예: 이미지 기반 PDF), 이전에는 관련 없는 다른 파일을 읽고 해당 내용을 대상 파일의 콘텐츠로 제시했습니다. 이제 시스템 프롬프트의 파일 무결성 보호막이 이를 방지합니다.

- **Standalone KB 대화** — 에이전트 바인딩 없이 직접 KB 채팅을 위한 대화의 `kb_ids` 필드.
- **검토 로그 감사 탭** — 시스템 로그 / 검토 로그 토글 및 org/리소스별 필터링 가능한 검토 추적이 포함된 Admin 감사 페이지.
- **synthesis의 Agent directive** — `agent_directive` 매개변수는 최종 답변이 에이전트의 핵심 목적을 준수하도록 보장.

### Changed

- **구독 기반 가시성 모델** — 3계층에서 2계층(own → subscribed)으로 단순화. 자동 마이그레이션으로 기존 접근 권한 유지.
- **Tool cache whitelist** — 블랙리스트를 도구의 명시적 `cacheable` 속성으로 교체. 11개의 읽기 전용 도구가 캐시 가능으로 표시됨.
- **DAG executor cascade failure** — 실패한 단계가 이제 종속 단계를 캐스케이드 차단하며 전이적 전파 수행.
- **DAG planner improvements** — 플래너의 도구 설명, 모든 라운드에 걸친 전체 재계획 이력, 14개 엔진 상수가 환경 변수로 매개변수화됨.
- **stream_answer observation truncation** — 2000자에서 8000자로 증가 (`REACT_TOOL_OBS_TRUNCATION`을 통해 설정 가능).
- **Evidence confidence UI** — 앰버 경고 카드, 호버 팝오버가 있는 `[N]` 인용 배지, 나란히 비교하는 갈등 경고 배너.
- **Workflow version change summaries** — 버전 저장 시 블루프린트 차이로부터 자동 생성된 인간이 읽을 수 있는 요약.
- **Workflow run retention cleanup** — 설정 가능한 나이/개수 한도를 포함한 백그라운드 정리 작업. 환경 변수: `WORKFLOW_RUN_MAX_AGE_DAYS`, `WORKFLOW_RUN_MAX_PER_WORKFLOW`.
- **Connector circuit breaker** — 3상태 머신(closed/open/half-open), 연결기별 실패 추적 및 모니터링 엔드포인트.
- **elkjs를 경량 BFS 자동 레이아웃으로 교체** — `/workflows/[id]` 번들 크기 473 kB에서 43 kB로 감소.

### 고정됨

- **워크플로우 평가 네임스페이스 평탄화** — ConditionBranch 및 VariableAssign에서 단축 변수명 해석 수정.
- **`is_active` 토글 시 재검토 없음** — `is_active`를 토글해도 더 이상 `publish_status`가 `approved`에서 `pending_review`로 되돌아가지 않음.
- **조건 분기에 대한 계단식 건너뛰기** — 건너뛴 노드가 나가는 에지를 올바르게 비활성화함.
- **종속성 분석기** — `skill_ids` 해석 수정, 대소문자 구분 없는 노드 유형 일치.

### 제거됨

- `is_global` 필드 및 모든 글로벌 가시성 개념 제거 — Market org + 구독으로 대체.
- 글로벌 agent/MCP server 관리자 엔드포인트 제거.
