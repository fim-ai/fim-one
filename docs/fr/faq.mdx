## Général

<AccordionGroup>
  <Accordion title="Quels fournisseurs LLM sont pris en charge ?">
    FIM One fonctionne avec **n'importe quel fournisseur LLM compatible OpenAI**. Cela inclut :

    - **APIs commerciales** — OpenAI, DeepSeek, Anthropic (Claude), Alibaba Qwen, Google Gemini, et tout fournisseur qui expose un endpoint `/v1/chat/completions`.
    - **Local/auto-hébergé** — Ollama, vLLM, LocalAI, LM Studio, et tout autre runtime qui sert le format API compatible OpenAI.

    Vous configurez votre fournisseur via trois variables d'environnement dans `.env` :

    ```bash
    LLM_API_KEY=sk-your-key
    LLM_BASE_URL=https://api.openai.com/v1   # change for other providers
    LLM_MODEL=gpt-4o                         # change for other models
    ```

    Consultez le guide [Démarrage rapide](/quickstart) pour des exemples spécifiques à chaque fournisseur.
  </Accordion>

  <Accordion title="Puis-je utiliser des modèles locaux ou auto-hébergés ?">
    Oui. FIM One se connecte à n'importe quel endpoint qui implémente le format API compatible OpenAI. Les options auto-hébergées populaires incluent :

    | Runtime | URL de base | Exemple de modèle |
    |---------|----------|---------------|
    | **Ollama** | `http://localhost:11434/v1` | `qwen2.5:14b` |
    | **vLLM** | `http://localhost:8000/v1` | `Qwen/Qwen2.5-72B-Instruct` |
    | **LocalAI** | `http://localhost:8080/v1` | `llama3` |
    | **LM Studio** | `http://localhost:1234/v1` | (quel que soit le modèle chargé) |

    Définissez `LLM_API_KEY` sur n'importe quelle chaîne non vide (par exemple, `ollama`) quand le fournisseur ne nécessite pas d'authentification. Toutes les fonctionnalités de l'agent — raisonnement ReAct, planification DAG, appels d'outils — fonctionnent de manière identique, que le modèle soit local ou hébergé dans le cloud.
  </Accordion>

  <Accordion title="FIM One est-il open source ?">
    FIM One est publié sous une **Source Available License**. Ce n'est pas une licence open source approuvée par l'OSI, mais elle offre de larges libertés pour la plupart des cas d'usage :

    **Autorisé :**
    - Utilisation interne au sein de votre organisation
    - Modification et développement personnalisé
    - Distribution avec la licence intacte
    - Intégration dans vos propres applications (non concurrentes)

    **Restreint :**
    - Offres SaaS multi-locataires
    - Plateformes d'agents concurrentes
    - White-labeling ou suppression de la marque

    Pour les demandes de licence commerciale, veuillez ouvrir un problème sur [GitHub](https://github.com/fim-ai/fim-one). Consultez la [LICENCE](https://github.com/fim-ai/fim-one/blob/master/LICENSE) complète pour les conditions complètes.
  </Accordion>

  <Accordion title="Puis-je utiliser FIM One pour des projets clients payants ou de conseil ?">
    Oui — facturer de l'argent n'est pas ce que la licence restreint. Vous pouvez livrer une solution basée sur FIM One à un seul client, à condition qu'il s'agisse d'un **déploiement dédié et mono-locataire** pour l'usage interne propre du client et que **la marque FIM One reste intacte**.

    Trois choses nécessitent une [licence commerciale](mailto:license@fim.ai) distincte :

    - **White-labeling** — suppression ou masquage de la marque FIM One pour qu'elle soit livrée sous la marque du client. (C'est le piège le plus courant pour les agences et les intégrateurs.)
    - **Réutilisation multi-locataire** — servir plusieurs clients à partir d'un déploiement partagé, ou toute offre « FIM One-as-a-Service ».
    - **Plateformes concurrentes** — utiliser FIM One pour construire une autre plateforme d'orchestration d'agents, de flux de travail ou de planification de tâches.

    Consultez [Scénarios courants](/license#common-scenarios) sur la page Licence pour le détail complet.
  </Accordion>

  <Accordion title="Comment signaler les vulnérabilités de sécurité ?">
    **N'ouvrez PAS de problème GitHub public pour les vulnérabilités sensibles.**

    - **Rapports sensibles** (exposition de credentials, contournement d'authentification, injection, etc.) — utilisez [GitHub Security Advisories](https://github.com/fim-ai/fim-one/security/advisories/new) ou envoyez un email à **security@fim.ai**.
    - **Problèmes de faible gravité** (en-têtes manquants, divulgations informatives) — ouvrez un problème GitHub régulier avec le label `security`.

    Tous les rapports sont reconnus dans les 48 heures (jours ouvrables). Les problèmes critiques sont corrigés dès que possible ; les autres sont livrés avec la prochaine version.

    Consultez la [Politique de sécurité](https://github.com/fim-ai/fim-one/blob/master/SECURITY.md) complète pour la portée, les délais de réponse et les bonnes pratiques d'auto-hébergement.
  </Accordion>

## Deployment

<AccordionGroup>
  <Accordion title="What are the system requirements?">
    **Minimum requirements:**

    | Resource | Requirement |
    |----------|-------------|
    | **Python** | 3.11+ |
    | **RAM** | 2 GB minimum |
    | **Disk** | 1 GB free (plus space for uploaded documents and vector store) |
    | **Node.js** | 18+ (for local development) |

    **Recommended for production:**

    | Resource | Recommendation |
    |----------|----------------|
    | **RAM** | 4 GB+ (especially if running embedding models locally) |
    | **CPU** | 2+ cores |
    | **Database** | PostgreSQL for multi-worker deployments |

    **Docker alternative:** Docker 20+ and Docker Compose v2. No local Python or Node.js required — everything is built inside the container.
  </Accordion>

  <Accordion title="Does FIM One work on ARM / Apple Silicon?">
    Yes. Both Docker and local development work on ARM architectures, including Apple Silicon (M1/M2/M3/M4) Macs. The Docker image builds natively for `linux/arm64`, and all Python and Node.js dependencies have ARM-compatible wheels or fallbacks.
  </Accordion>

  <Accordion title="What databases are supported?">
    FIM One uses databases in two distinct ways:

    **1. Internal database (FIM One's own data):**
    - **SQLite** — zero-config default, great for development and single-worker deployments.
    - **PostgreSQL** — recommended for production, required for multi-worker setups (`WORKERS > 1`).

    **2. Connector targets (systems you connect to):**

    FIM One can connect to external databases as data sources via Database Connectors:

    | Database | Status |
    |----------|--------|
    | PostgreSQL | Supported |
    | MySQL | Supported |
    | DM (Dameng) | Supported |
    | KingbaseES | Supported |
    | Highgo | Supported |

    Database connectors are exposed to the agent through one `database` tool with `list_tables`, `discover`, and `query` operations (`DATABASE_TOOL_MODE=legacy` restores three tools per connector). Schema introspection and AI-powered annotation are included, and queries are read-only by default. A database connector is private to its owner and cannot be shared.
  </Accordion>

  <Accordion title="Can multiple users share the same instance?">
    Yes. FIM One is built for multi-tenant deployments from the ground up:

    - **JWT authentication** — token-based auth with per-user session isolation.
    - **Organization isolation** — resources (agents, connectors, MCP servers) are scoped to organizations. Knowledge bases stay private to their owner and are never shared directly.
    - **Role-based access** — admin and user roles with appropriate permission boundaries.
    - **Resource ownership** — conversations and configurations are isolated per user.

    For multi-user production deployments, use PostgreSQL as the internal database and set `WORKERS` to match your expected concurrency.
  </Accordion>
</AccordionGroup>

## Features

<AccordionGroup>
  <Accordion title="What is the difference between ReAct and DAG mode?">
    FIM One offers two execution engines, each suited to different task types:

    | | ReAct (Standard) | DAG (Planner) |
    |---|---|---|
    | **How it works** | Single reasoning loop: Reason, Act, Observe, repeat | LLM decomposes the goal into a dependency graph; independent steps run in parallel |
    | **Best for** | Focused queries, single-system lookups, conversational tasks | Multi-step tasks, cross-system orchestration, parallel data gathering |
    | **Concurrency** | Sequential (one tool at a time) | Concurrent (independent steps run simultaneously via asyncio) |
    | **Re-planning** | N/A | Up to 3 rounds in total (the first plan plus 2 automatic re-plans) if goals are not met |

    Chat and new agents start in **Standard** (ReAct) mode. **Auto mode** uses a fast LLM classifier to analyze each incoming query and routes it to the optimal engine automatically. Select the mode via the three-way toggle in the chat UI (Auto / Standard / Planner).

    For a deep dive, see [Execution Modes](/concepts/execution-modes).
  </Accordion>

  <Accordion title="How do I add a new connector?">
    FIM One provides three ways to create connectors — no Python code required:

    **1. Import an OpenAPI spec** — Upload a YAML, JSON, or URL pointing to an OpenAPI specification. FIM One parses the spec and generates connectors with all actions automatically.

    **2. AI chat builder** — Describe the API you want to connect in natural language. The AI generates and iterates on the connector configuration in conversation, using 10 specialized builder tools for settings, actions, testing, and agent wiring.

    **3. MCP protocol** — Connect any MCP (Model Context Protocol) server directly. The third-party MCP ecosystem works out of the box.

    For database connectors, configure the connection details (host, port, credentials) and FIM One auto-generates schema introspection and query tools.

    See the [AI Builder](/concepts/ai-builder) documentation and the [Extension Guide](/extension-guide) for step-by-step instructions.
  </Accordion>

  <Accordion title="Can I embed FIM One into my existing system?">
    Yes, through the API. FIM One's **Copilot mode** means putting the agent inside a host system's UI:

    - **API** — Call the FastAPI backend (`POST /api/react`, `/api/dag`, `/api/auto`, streamed over SSE) from your own page or widget. This is what works today.
    - **iframe / Widget** — A drop-in embed snippet is planned and not shipped yet.

    In Copilot mode, the AI works alongside users in their familiar interface — querying data, generating reports, and orchestrating actions without forcing users to switch applications.

    See [Execution Modes](/concepts/execution-modes) for the Standalone, Copilot, and Hub delivery modes, and the [API Overview](/api/overview) for the streaming endpoints.
  </Accordion>

  <Accordion title="How does the translation system work?">
    FIM One supports 6 languages (English, Chinese, Japanese, Korean, German, French) with a fully automated translation pipeline:

    1. **Only edit English source files** — UI strings in `frontend/messages/en/*.json`, documentation in `docs/*.mdx` (root level), and `README.md`.
    2. **Auto-translate on commit** — A pre-commit hook detects changes to English files and translates them via the project's Fast LLM. Translations are incremental: only new, modified, or deleted content is processed.
    3. **Never manually edit translated files** — Files in `messages/zh/`, `messages/ja/`, `docs/zh/`, `docs/ja/`, etc. are all auto-generated and will be overwritten.

    To set up the translation hook after cloning:
    ```bash
    bash scripts/setup-hooks.sh
    ```

    To force a full retranslation:
    ```bash
    uv run scripts/translate.py --all
    ```
  </Accordion>

## Contribution

<AccordionGroup>
  <Accordion title="Comment puis-je contribuer à FIM One ?">
    FIM One accueille les contributions de toutes sortes — code, documentation, traductions, rapports de bugs et idées de fonctionnalités.

    **Pour commencer :**
    1. Lisez le [Guide de contribution](https://github.com/fim-ai/fim-one/blob/master/CONTRIBUTING.md) pour les instructions de configuration, les conventions de codage et le processus de PR.
    2. Parcourez les [Bons premiers problèmes](https://github.com/fim-ai/fim-one/labels/good%20first%20issue) pour trouver des tâches adaptées aux nouveaux contributeurs.
    3. Consultez les [Problèmes ouverts](https://github.com/fim-ai/fim-one/issues) pour les bugs et les demandes de fonctionnalités.

    **Programme Pioneer :** Les 100 premiers contributeurs dont la PR est fusionnée sont reconnus comme **Contributeurs fondateurs** avec des crédits permanents, un badge de profil et un support prioritaire des problèmes.
  </Accordion>

  <Accordion title="Quelle est la pile technologique ?">
    | Couche | Technologie |
    |-------|-----------|
    | **Backend** | Python 3.11+, FastAPI, SQLAlchemy, Alembic, asyncio |
    | **Frontend** | Next.js, React, TypeScript, Tailwind CSS, shadcn/ui |
    | **Intégration LLM** | API compatible OpenAI (agnostique du fournisseur) |
    | **Recherche vectorielle** | LanceDB + embeddings Jina |
    | **Base de données** | SQLite (dev) / PostgreSQL (production) |
    | **Gestionnaires de paquets** | uv (Python), pnpm (Node.js) |
    | **Déploiement** | Docker Compose, script mono-processus |

    La base de code suit une architecture async-first, protocol-first sans verrouillage fournisseur.
  </Accordion>
