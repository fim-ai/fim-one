## [Unreleased]

### Added

- **DAG replans no longer redo finished work, and interrupted runs resume where they left off.** When a plan needs revision, steps that already completed are carried into the new plan with their results — only the remaining work is re-planned and executed. Step progress is also checkpointed as it happens, so if a run is interrupted mid-execution (crash, deploy, dropped connection), retrying the same request picks up from the completed steps instead of starting over.
- **Slow tools can now run in the background without blocking the agent.** Sandboxed code execution (Python/Shell/Node) offers a `run_in_background` option: the agent gets a task id immediately, keeps working on other steps, and receives the result as a notification when the tool finishes. If the agent tries to finalize while tasks are still running, it waits for them (bounded) and incorporates their results before answering.
- **Conversation history is snapshotted before compaction, and budget-truncated tool results are saved to the workspace.** Before long-conversation compaction replaces history with a summary, the full transcript is written to the conversation workspace as a JSONL file; likewise, a tool result cut by the aggregate token budget is saved in full to the workspace with a pointer left in place — in both cases the agent (and you) can read the original back instead of losing it.
- **Answers no longer end mid-sentence when the model hits its output limit.** When a response is cut off by the provider's output-token cap, the agent automatically asks the model to resume where it stopped (up to 3 rounds) and stitches the segments into one seamless answer — both in the reasoning loop and in the streamed final answer.
- **LLM calls now retry on provider overload (HTTP 529) and gateway timeout (504), and honour `Retry-After`.** Previously a 529 from Anthropic failed the request immediately unless a fallback model was configured; now it backs off and retries like 429/5xx, waiting exactly as long as the provider asks when a `Retry-After` header is present.
- **Agents now keep a visible plan during multi-step tasks.** ReAct agents get an `update_plan` tool to write down their plan as a todo checklist and update it as they progress; if the plan goes stale for several tool calls, the full checklist is re-injected as a reminder — so long tasks stay on-goal even after context compaction. On by default (`REACT_PLAN_TOOL_ENABLED`); DAG sub-steps and tool-less agents skip it.

- **Agents can now run a workflow mid-conversation.** Active, human-approval-free workflows you own or have subscribed to are offered to the agent as a `run_workflow` tool — in normal chat and with an agent selected alike — so a task can hand off a deterministic, repeatable sub-process to a workflow and get its outputs back. Each such run is recorded in the workflow's run history and its token usage counts against the workflow owner's quota (the run is refused if the owner is already over quota). Workflows with a Human Intervention step stay trigger-only (from the Workflows page or their API key), since they can block for a long time.
- **Two new workflow starter templates: Connector Action and MCP Tool Call.** The "Create from Template" gallery now showcases the connector and MCP nodes — call an external system or an MCP tool, then summarize the result with an LLM. Pick the specific connector/server after creating.

### Changed

- **Connectors and MCP servers no longer share the owner's credential by default (breaking).** "Allow fallback to the owner's credential" is now opt-in: new connectors/MCP servers are created with it off, and all existing ones were switched off as well. A subscriber who was relying on the owner's token to use a shared connector or MCP server will now need to add their own credential, or the owner must re-enable fallback on that resource. Owners can always use their own credential regardless of the setting. As a result, a connector whose fallback is off and for which you have no credential is now hidden from the agent's toolset (matching how MCP servers already behaved) instead of being offered and then failing when called.
- **New agents now default to ReAct execution instead of Auto.** Auto mode spent one extra fast-model classification call per request to decide between ReAct and DAG; new agents (and the built-in/marketplace templates) now default to ReAct, removing that per-message latency and cost. Auto and DAG remain selectable per agent; existing agents keep their current mode.
- **AI agent creation recovers from a weak fast model.** Building or refining an agent from a natural-language instruction runs on the fast model; if it can't produce valid configuration, the request now retries once on the stronger general model before erroring, so a too-weak fast model no longer surfaces as a failure to the user.

### Removed

- **Trimmed the visual workflow builder to 9 core node types.** Sixteen rarely-used utility and control-flow nodes — environment variables, HTTP request, code execution, iterator/loop, sub-workflow, template/list/transform helpers, and the parameter/question extractors and classifier — were removed so the builder focuses on orchestrating agents, connectors, MCP servers, and knowledge bases. As a side effect a shared workflow no longer carries embedded secrets: it is now purely a graph of references, and each referenced resource enforces its own per-user access at run time. Existing workflows built on a removed node will need to be rebuilt with the remaining set.

### Security

- **Database connectors can no longer be shared, and their raw-SQL tool is owner-only.** Publishing a database connector to an organization or globally is now rejected, and the arbitrary-SQL database tool is only ever offered to the connector's owner — never to a subscriber, regardless of the owner-credential fallback setting. Previously a shared database connector exposed unrestricted SQL over the owner's (typically high-privilege) database account to anyone who subscribed, with no per-caller scoping. Per-user scoped database access will return through a future declarative-action layer.
- **Webhook- and cron-triggered workflows now count against the owner's token quota.** An unattended workflow run — triggered through its public API key or on a schedule — used to execute LLM and agent steps without checking or recording any token usage, an unmetered free-LLM path that bypassed quotas entirely. Such runs are now gated on the workflow owner's quota up front (a public trigger is refused, and a scheduled run is skipped, when the owner is already over quota) and their token usage is recorded per run and counted toward the same monthly quota as chat.

### Fixed

- **Resumed DAG runs no longer lose the end of long step outputs.** Step evidence stored in the crash-resume checkpoint was cut head-only at the size cap, silently dropping whatever lived at the end of the output — which is exactly where conclusions, checksums, and final rows tend to be. Capped evidence now keeps both the head and the tail with an explicit omission marker in between.
- **Agents no longer "work" by printing their own notes through Python.** The efficiency guidance that encouraged writing one comprehensive script per tool call is now scoped to tasks that genuinely need code execution — knowledge questions, comparisons, and analysis the model can produce directly are answered directly instead of being routed through pointless sandbox scripts.
- **An agent step inside a workflow now runs the full agent, not just its prompt.** A workflow's Agent node used to execute with only the agent's instructions on a generic model and default toolset — silently dropping the agent's connectors, knowledge bases, MCP servers, and configured model. It now runs the agent exactly as it would in chat, with all of its bound resources and model, and only if that agent is visible to the workflow owner.
- **Leaving (or being removed from) an organization now revokes its shared access.** Resources you could reach only through that organization are unsubscribed, and the per-user connector/MCP credentials you saved for them are deleted — so you can no longer use those resources or fall back to the owner's credential after departing. Resources you subscribed to via the Market are unaffected.
- **Deleting an account now removes everything, consistently.** The admin "delete user" and self-serve "delete my account" paths used to diverge — each cleaned a different set of on-disk files (and both computed their file paths wrongly, so each silently missed some), and the admin path left behind API keys, login history, eval data, call logs, and subscriptions. Both now run through one routine that removes every record and file, and the delete no longer fails on databases that enforce foreign keys.
- **A user who still owns an organization can no longer be deleted.** The request is now rejected with a clear message to transfer ownership (or delete the organization) first, instead of failing obscurely or leaving the organization orphaned.
- **Deleting an agent no longer breaks past conversations.** Conversations that referenced the agent are kept as historical records and simply have the agent link cleared, rather than blocking the deletion.
- **Confirmation-required connector actions can no longer run unattended in a workflow.** A connector action flagged as requiring confirmation used to execute inside a workflow with the approval gate silently bypassed. The step now fails closed with a message to place a Human Intervention node before it (the workflow-native approval gate) or use an action that doesn't require confirmation.
- **Workflow steps no longer borrow the owner's MCP credentials.** When a workflow's MCP server had owner-credential fallback disabled, a non-owner running that workflow silently fell back to the owner's server credentials instead of being stopped. The step now fails with a clear message to configure your own credentials, matching the chat path.
- **Connector calls made from workflows are now audit-logged.** A connector action run inside a workflow left no entry in the connector call log (only chat-initiated calls were recorded); workflow calls now write the same audit trail.
- **You can now attach a subscribed connector, knowledge base, or MCP server to an agent.** Binding used to require you to *own* the resource, so a connector you'd legitimately subscribed to (org-shared or Market-installed) was rejected as "not owned". Binding now follows the same visibility rule the rest of the app uses — anything you own or have subscribed to is bindable.
- **Workflow steps can only call connectors you actually have access to.** A workflow's connector step used to run any connector whose id it referenced, as long as that connector existed; it now enforces the runner's visibility (owned or subscribed), so a shared workflow can't reach a connector you have no access to just by referencing its id.
- **Knowledge base search now works against KBs you subscribed to, not just ones you own.** A KB's data lives under its owner's storage, but a workflow knowledge-base step (and knowledge-base chat without an agent) used to look under the caller's own storage — so searching a KB shared with you silently returned nothing. The owner is now resolved from the KB itself and the search is access-checked (owner or subscriber), so shared KBs return results and KBs you can't see return nothing instead of a confusing empty hit.
- **Background jobs no longer vanish at random.** Document ingestion, webhook delivery, eval runs, and post-response notifications were launched as fire-and-forget tasks the runtime only weakly referenced, so under load they could be garbage-collected mid-flight and stop silently. They are now held until completion (and their failures logged) so they reliably finish.
- **Large file uploads no longer stall other requests.** Text extraction from an uploaded PDF/DOCX ran synchronously on the main event loop, briefly freezing all concurrent requests while a big file was parsed. Extraction is now offloaded to a worker thread.
- **Multi-step (DAG) answers no longer misrepresent their sources.** When a plan's research step fetched a page and summarized it, only that summary flowed onward — so a source that listed 11 items could surface in the final answer as 6, or an item's severity could be mislabeled, and the goal-evaluation step couldn't catch it because it never saw the original source. Each step now retains its raw tool output as authoritative source evidence, which the final synthesis and the evaluator check the answer against, so totals, enumerations, and attributes match what the sources actually said (and confidence drops with a named discrepancy when they don't).
- **The workflow LLM node no longer shows model controls that didn't mean what they implied.** It had a hardcoded model dropdown whose selection was ignored at run time, plus a Fast/Main tier toggle exposing an internal (auto-degrading) concept. Both are removed — the node now always runs your system-configured model (Model Provider, falling back to `.env`), the same way the playground resolves it, with a one-line note pointing to where the model is configured.

## [v0.8.8] - 2026-06-22

### Changed

- **Agents now own mistakes more cleanly.** When a tool result contradicts something an agent said, it acknowledges and corrects in the same turn without over-apologizing or padding the reply with self-criticism.

### Security

- **Blocked an SSRF bypass via IPv4-mapped IPv6 addresses.** A URL whose host was an IPv4-mapped IPv6 literal (e.g. `http://[::ffff:169.254.169.254]/`) slipped past the private-IP blocklist and could reach internal services — including cloud instance-metadata — on dual-stack hosts. These addresses are now unwrapped and checked against the IPv4 blocklist, closing the gap across every SSRF-protected path (web fetch, HTTP tool, connectors, RAG importer).
- **MCP SSE / Streamable-HTTP server URLs are now SSRF-validated.** An authenticated user could point an MCP server at an internal address and trigger a request to it when the server was tested or connected. Server URLs are now validated on create/update and again at connect time.
- **Docker Compose PostgreSQL credentials are now overridable via `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB`.** The previously hardcoded `fim:fim` default is single-sourced (the connection string is derived from the same vars) and documented with a warning to change it before exposing the database, so operators no longer ship default admin credentials by accident.

### Fixed

- **LLM access no longer dies after a quiet period.** The shared HTTP connection pool was installed once at startup and reused for every model call; after the system sat idle, the underlying client could be closed out from under the app, after which every LLM call failed with a connection error until the service was restarted. The pool is now re-validated and transparently recreated before each call, so service recovers on its own without a restart.
- **Sending a message in a chat now streams instantly instead of stalling.** Each send used to block on a full reload of the conversation's history before the answer could start, so longer chats felt frozen for a moment and refetched the entire transcript every turn. A completed turn is now folded into history in the background, so sends stream immediately and skip the redundant reload.
- **Extended thinking now works on newer Anthropic models (Opus 4.6+, Sonnet 4.6, Fable 5).** These models removed the old fixed-budget thinking parameter — Opus 4.7/4.8 and Fable 5 reject it with a 400 — so configuring reasoning effort either errored or silently did nothing. We now send the adaptive-thinking protocol for these models (and drop the sampling parameters they no longer accept), so reasoning effort takes effect correctly. A model that uses adaptive thinking but is connected through a generic OpenAI-compatible proxy (where thinking can't be enabled) now logs a clear warning instead of failing silently — configure it as an Anthropic provider to enable thinking.
- **Force-logout now compares timestamps correctly on PostgreSQL.** The session-invalidation check assumed the stored invalidation time was naive UTC and forced it as such, which silently corrupted comparisons against tz-aware non-UTC values that PostgreSQL can return. Timestamps are now normalized to UTC by conversion, not override, so revoked tokens are reliably rejected on every backend.
- **Enforcement hooks now fail closed when they crash.** A `PRE_TOOL_USE` hook (e.g. an approval gate) that raised an exception previously returned `allow=True`, so the blocked tool call proceeded anyway — a crashing gate silently became a bypass. PRE hooks now deny by default on error; non-enforcement hooks (rate limiter, loggers) keep the old fail-open behavior via a new `fail_open` flag.
- **Agent answers no longer drop the reasoning's conclusions.** When a reasoning model had already produced a final answer, the pipeline made a second, lossy synthesis call that could discard the model's own conclusions — and reasoning detail was further lost when conversations were compacted, guarded against the context limit, or routed through multi-step plans. The loop now streams its genuine final answer verbatim, and reasoning is carried through compaction, context rebuilds, and sub-agent steps, so the answer you see reflects the full chain of thought instead of a watered-down restatement.

## [v0.8.7] - 2026-06-10

### Security

- **Closed a two-factor-authentication bypass.** API and chat/SSE authentication now require a genuine access token (SSE streaming also accepts its short-lived ticket); the 2FA temp token, refresh tokens, and bind/SSE tickets — all signed with the same key — can no longer be replayed to authenticate, so a stolen password alone can no longer skip the second factor.
- **OAuth login no longer auto-links to an existing account on an unverified email.** A third-party account is matched to a local account by email only when the provider marks that email verified, preventing takeover via an attacker-controlled unverified address.

### Added

- **`file_ops.apply_patch` — apply V4A-format diff patches to files.** Lets agents make multi-line edits with line-based hunks and fuzzy whitespace matching, complementing the existing `find_replace` for cases where exact substring match is brittle.
- **Content guardrails for input and output validation.** A new `core/agent/guardrail` layer runs alongside (not replacing) existing tool-permission gates and security checks. Input guardrails (default: jailbreak phrase detector) run before any LLM call and abort the turn if triggered, saving tokens and surfacing a clear "blocked" notice in chat. Output guardrails run after the final answer. Configurable via `FIM_GUARDRAILS_INPUT` / `FIM_GUARDRAILS_OUTPUT` env vars; per-agent UI configuration coming in a future release.

### Changed

- **`/settings?tab=billing` now renders full-width and visually consistent with the rest of the Settings tabs.** Removed the `max-w-4xl` width cap and the redundant outer scroll container; dropped the page-title icon; rewrote the plan / usage / subscription / plans-comparison cards to use the same lean bordered-div pattern (compact labels + `tabular-nums` numbers) as the Usage tab. Old layout looked like a standalone page accidentally wedged into the settings frame.

### Fixed

- **Token quota now resets on your billing date, not the 1st of the month.** Usage was always counted per calendar month regardless of when you subscribed, so paid users could be charged on the 20th yet wait until the 1st for a fresh quota — and a subscription started late in the month effectively granted a second full quota days later. Quota now resets on each subscription's monthly anniversary (free users still reset on the calendar month). Annually-billed plans correctly refill every month, not once a year. The Plan & Billing tab, the Usage card, and the quota-exceeded dialog now all measure usage and show the reset date over this same window, so the displayed "usage this period" matches the point chat actually stops you.
- **Subscription renewals now advance the billing period.** On auto-renewal the displayed period-end date stayed frozen at the previous cycle even though Stripe had charged and rolled the subscription forward — the renewal handler read the new period only from the invoice payload, where it is unreliable. It now retrieves the authoritative period bounds from Stripe, so the cycle-end date (and quota reset) move forward on every renewal. This also removes a latent risk where canceling such a subscription could downgrade the account immediately instead of at the true period end.
- **Raw tool-call protocol no longer leaks into agent answers.** When a model improvises a tool call as plain text (e.g. emitting `<tool_call>`/`<tool_response>` blocks — common when it reaches for a tool that isn't available), that text — including any base64/file dumps inside it — could surface verbatim in the reply. All answer paths now strip this pseudo-protocol, and the parser additionally recognizes the `{"name","arguments"}` dialect as a genuine tool call instead of leaking it.
- **Intermittent `APIConnectionError: Connection error` bursts during agent turns.** The shared HTTP connection pool kept idle keep-alive connections for up to 30 s; when an upstream relay or NAT silently reaped an idle connection, the next request reused the half-dead socket and failed. Keep-alive expiry is now a short 5 s by default (warm connections within a turn are still reused), and the pool is tunable via `LLM_HTTP_MAX_CONNECTIONS` / `LLM_HTTP_MAX_KEEPALIVE` / `LLM_HTTP_KEEPALIVE_EXPIRY` — set `LLM_HTTP_MAX_KEEPALIVE=0` to disable connection reuse entirely behind an unreliable upstream.
- **API key usage stats (`total_requests`, `last_used_at`) now persist on every request.** Previously the increment was written on the request's database session, which is only committed by endpoints that perform their own writes — so read-only API-key calls (dashboard, files, models, exports, …) silently rolled the counter back. Usage is now recorded on an independent, self-committing session, decoupled from request success.

## [v0.8.6] - 2026-05-08

### Added

- **Stripe billing — Pro plan subscription.** New `Plan & Billing` tab under `/settings?tab=billing` shows current plan, monthly token usage, period reset, and either `Upgrade to Pro` (Stripe Checkout) or `Manage subscription` (Customer Portal). Successful checkout opens a confetti modal naming the purchased plan; redirect params are stripped only after dismissal so a refresh doesn't re-trigger it. Quota enforcement respects each user's plan; canceled subscriptions stay on Pro until the paid period ends; the mid-stream 402 quota dialog now lands on the billing tab. Admins manage plans and browse subscriptions under Admin Panel → Billing. Pro currently uses a Stripe **test-mode** price; production cutover replaces the price ID.
- **Admin-controlled billing feature flag.** `Enable Stripe Billing` toggle in Admin → System Settings gates the entire Stripe pipeline — user-facing `/api/billing/*`, Stripe webhook, admin plan/subscription CRUD, and frontend billing tab + admin nav all hide or 503 when off. First activation seeds Free + Pro, sets the `default_plan_id` pointer, and backfills `users.plan_id`; subsequent off/on is a pure flag flip. Private deployments without Stripe credentials stay clean. Quota chain falls back to the admin-set `Default Monthly Token Quota` when billing is off.
- **Per-user unlimited quota + Registered column.** Empty quota field inherits the global limit; `0` grants unlimited. Previously both collapsed into the same state. Users table also gains a Registered column.
- **Non-English docs (`zh` / `ja` / `ko` / `de` / `fr`) now show the full API Reference and Channels Configuration sections** — the `Endpoints` group and `Configuration > Channels` sub-group were previously English-only.

### Changed

- **`Plan & Billing` is a Settings tab, not a standalone page.** Folded `/settings/billing` back into `/settings?tab=billing` so the left nav stays visible while users switch plans (matches GitHub / Linear / Notion). The standalone route redirects, so old bookmarks and earlier-deploy Stripe Checkout return URLs keep working. The `Subscriptions` tab is renamed to `Marketplace` to disambiguate from plan subscriptions.
- **Free plan quota is read-only on the admin Plans page.** Sourced from System Settings → Default Monthly Token Quota; editing there propagates automatically. Backend silently ignores `monthly_token_quota` on PATCH for the Free plan.
- **Token quotas render as `5M` / `100K`** instead of `5,000,000` across billing page, plan cards, and admin Plans table. Admin INPUT fields still accept raw numbers.
- **Translation authority shifted from per-locale files to a single glossary.** Rules live in [`scripts/translation-glossary.md`](https://github.com/fim-ai/fim-one/blob/master/scripts/translation-glossary.md), loaded into every LLM translation call (JSON, MDX, README). The pre-commit hook unconditionally refuses manual edits to generated locale files. To fix a mistranslation, edit the glossary and regenerate with `--force`.
- **Licensor and governing law.** The FIM One Source Available License is now granted by **FIM Labs Pte. Ltd.** (Singapore); governing law moves from the PRC to Singapore; disputes go to SIAC arbitration in Singapore (one arbitrator, English). New top-level `NOTICE` file records R&D attribution, trademarks, and third-party component policy. No change to permitted-use or restriction terms.

### Fixed

- **Admin approve/reject of agents, connectors, knowledge bases, and MCP servers no longer fails on PostgreSQL.** The publish-review `reviewed_at` column is now timezone-aware, so approval writes succeed on PG (the bug was invisible on SQLite dev databases).
- **OAuth users can refresh their session again.** The OAuth-issued refresh token was stored in a form the refresh endpoint could never match, forcing a re-login once the access token expired; it is now stored as a digest like every other path.
- **Browser tab title now reflects the active sub-tab in `/settings` and `/admin`** (e.g. `Settings · Billing — FIM One`), so multiple pinned tabs are distinguishable.
- **Usage page no longer reports "Unlimited" when an admin has set a default token quota** — it now resolves through the unified quota chain (per-user override → plan tier → system default).
- **Agent settings: bound resources no longer flicker as "(已删除)" on entry.** Orphan badge waits for inventory fetches to settle before rendering.
- **Toasts now follow the light/dark theme** instead of being hardcoded to dark.
- **Usage by-agent breakdown no longer duplicates "Direct Chat" rows** for conversations tied to deleted agents.
- **Self-hosted `./deploy.sh` no longer fails with `container name already in use`** — sweeps hash-prefixed zombie containers and DooD sandbox children before `docker compose up`.
- **No more redundant `chore(i18n): sync translations` commits after pushes** — the pre-commit translation hook now stages `.translation-cache.json` alongside translated files.
- **Agent chat no longer crashes when a confirmation-required tool runs in an unbound-agent session** — the gate bows out gracefully when there's no agent to route for.
- **Retry no longer fails on strict-alternation providers (Claude) when history contains orphan user messages from stopped turns** — consecutive same-role messages collapse into a single turn before dispatch.
- **Playground retry no longer briefly shows the query twice** during the pre-stream window.
- **ReAct agent now acknowledges and stops after an operator rejects an approval request**, instead of retrying paraphrased tool calls.
- **Playground "Suggested follow-ups" returns and is now opt-in per agent** (default off; new `Follow-up Suggestions` toggle in agent settings).

## [v0.8.5] - 2026-04-23

### Added

- **Contributor-friendly i18n workflow**: contributors no longer need to configure `LLM_API_KEY` to submit PRs that touch English source files. If the local pre-commit translation step is skipped (no key), a new `.github/workflows/i18n-sync.yml` workflow translates EN → ZH/JA/KO/DE/FR on `master` after the PR is merged and auto-commits the result. The pre-commit hook also now refuses manual edits to generated locale files (with an `ALLOW_LOCALE_EDIT=1` override for legitimate translation fixes), preventing silent drift between EN sources and translated outputs.
- **i18n CI fallback end-to-end verified**: smoke-test push (EN-only, local translate hook skipped) confirmed the GitHub Actions workflow detects the changed source, translates into all five locales, and auto-commits the result to master with `[skip ci]` to prevent recursion.
- **Exa integration docs page**: dedicated Integrations section in the sidebar with a first-class Exa page covering the full Exa search surface (neural / fast / deep-reasoning / instant), filtering, content retrieval, and three tuned presets for news monitoring, research paper retrieval, and deep-reasoning agents. Serves as the partner-facing landing page for the Exa integration directory.
- **Xinchuang (信创) database support**: the Database Connector now lists KingbaseES (人大金仓), HighGo (瀚高), and DM8 (达梦) alongside PostgreSQL/MySQL. KingbaseES and HighGo are PG-compatible and reuse `asyncpg` with no extra dependencies; DM8 uses the official `dmPython` vendor wheel. A standalone `scripts/test_xinchuang_dbs.py` lets operators verify live connectivity from the CLI.
- **Feishu Channel + confirmation gate via IM**: new `Channel` resource type (org-scoped, credentials encrypted at rest) lets orgs connect a Feishu app for outbound messaging. Tools flagged `requires_confirmation=True` now send an Approve/Reject interactive card to the configured Feishu group instead of only showing the confirmation dialog in the portal — any authorized member of the group can approve or reject directly from Feishu. Covers Settings → Channels management UI (list, create/edit with dirty-state protection, details with copyable callback URL, test-send), CRUD API (`/api/channels`), and the Feishu event callback endpoint (`/api/channels/{id}/callback`) with signature verification and URL challenge support. First step of the v0.9 IM Channel Integration roadmap item, ships ahead of schedule for the 2026-04-24 roadshow.
- **Agent Hook System (skeleton)**: new `PreToolUseHook` / `PostToolUseHook` abstraction in `src/fim_one/core/hooks/` lets deterministic logic run outside the LLM loop — the FeishuGateHook is the first concrete implementation, attached to the confirmation-gate flow. Full hook lifecycle + user-defined YAML hooks remain v0.9 scope.
- **Hook System is now live in the ReAct and DAG runtime**: agents that declare `hooks.class_hooks` in their `model_config_json` have those hooks instantiated and registered on every chat session. The first consumer — `FeishuGateHook` — fires automatically when an agent calls a tool whose connector action is flagged `requires_confirmation=True`, posts an Approve/Reject card to the org's Feishu group, blocks the tool, and resumes or aborts based on the verdict. Previously the hook abstraction was in place but nothing in the web layer wired it to live chat.
- **Channels and the Hook System architecture documented**: new `docs/architecture/hook-system.mdx` explains the three hook points, why hooks run outside the LLM loop, and walks through FeishuGateHook end-to-end. Existing architecture pages (system-overview, organization, react-engine, philosophy) cross-link to it. README now lists Messaging Channels as a first-class v0.8 capability and the Application Layer diagram includes IM targets alongside Portal/API/iframe.
- **Hook Approval Playground**: Channels details sheet now has a "Test Approval Flow" action that simulates a sensitive tool call, pushes a real confirmation card to the linked Feishu group, and polls for the reviewer's decision live. Unlike the existing preview button, this exercises the full production path (genuine `ConfirmationRequest` row, real Feishu callback, status transitions), so demos and pre-rollout rehearsals use the same code path a production hook would.

- **Per-agent task completion notifications**: agents can now push a summary card to the org's channel (currently Feishu) when a long-running ReAct or DAG task finishes. Configurable per-agent in Settings → Agent → Notifications. First consumer of the generic outbound notification pattern.
- **Configurable confirmation gate — inline *or* channel**: every agent now has an "Approval" section in Settings with three routing modes (Auto / Inline only / Channel only), an approver-scope selector (initiator / agent owner / anyone in the org), a "require confirmation for every tool call" override, and an explicit approval-channel picker. Auto mode uses a linked channel if one exists and gracefully falls back to an inline approval card in the chat stream otherwise — so agents without any channel still get a real approval UX instead of silently failing. A new `POST /api/confirmations/{id}/respond` endpoint shares a single decision-recording path with the Feishu webhook, so every approval — whether clicked in chat or in a Feishu group — stamps the same `approver_user_id` and `decided_at` audit fields.

### Changed

- Playground loading indicators now use a subtle text shimmer instead of the fake-looking progress bar that froze at a pseudo-full width after 8 seconds. Unified the two existing shimmer implementations (`.shiny-text` and `.text-shimmer`) into a single theme-aware primitive with an optional warm preset.
- Connector cards now surface a "Private default" badge (with tooltip) when a connector has `allow_fallback` disabled, so owners can tell at a glance which connectors require every user to bring their own credentials.
