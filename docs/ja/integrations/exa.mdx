[Exa](https://exa.ai)はFIM Oneのオプションのウェブサーチバックエンドとして利用可能です。有効にすると、エージェントはExa検索サーフェス全体にアクセスできます — `auto`（Exaの推奨検索タイプ）、`neural`、`fast`、`deep-lite`、`deep`、`deep-reasoning`、`instant` — 構造化コンテンツ取得（ハイライト、テキスト、サマリー）とリッチフィルタリング（カテゴリ、ドメイン含有/除外、日付範囲、最大経過時間ウィンドウ）を備えています。合理的なExa側のデフォルトが最初から提供されるため、手動チューニングなしでExaのベストプラクティスを得られます。

## FIM One で Exa を使う理由

- **エージェント推論のためのニューラル検索** — Exa の埋め込みネイティブ検索は、キーワードマッチだけでなく意味的に関連する結果を返します。これはウェブコンテンツを推論する研究エージェントにとって重要です。
- **難しいクエリのための深い推論モード** — エージェント自体がサブクエリをオーケストレーションすることなく、オープンウェブ上で単一呼び出しの多段階推論を実行します。
- **組み込みコンテンツ抽出** — ハイライト + テキスト + オプションのサマリーが検索呼び出しで到着し、ページコンテンツをフェッチしてクリーンアップするための2番目のラウンドトリップを排除します。
- **厳密なドメイン / 鮮度制御** — ドメインリスト（最大1200エントリ）、ISO-8601 日付ウィンドウ、および時間に敏感なワークフロー向けの `maxAgeHours` を含みます。

## クイックスタート

### 1. Exa API キーを取得する

[exa.ai](https://exa.ai) にサインアップして、ダッシュボードから API キーを取得します。

### 2. FIM OneでExaを有効にする

`.env`に以下を追加します：

```bash
WEB_SEARCH_PROVIDER=exa
EXA_API_KEY=your_key_here
```

両方の変数を設定して、`web_search`がExaを経由するようにします。キーの自動検出に頼るだけでなく、明示的に`WEB_SEARCH_PROVIDER=exa`を指定することをお勧めします。

### 3. 任意のエージェントから使用する

ウェブ検索はエージェントに組み込みツールとして公開されます。追加の配線は不要です。上記のように Exa を設定すると、`web_search` が有効になっているエージェントは検索呼び出しを Exa 経由でルーティングします。

## 設定

すべてのExa固有の設定には適切なデフォルト値があります。環境変数を使用してこれらをオーバーライドできます：

| 変数 | デフォルト | 説明 |
|---|---|---|
| `EXA_API_KEY` | — | **必須。** あなたのExa API キー。 |
| `EXA_SEARCH_TYPE` | `auto` | `auto`、`neural`、`fast`、`deep-lite`、`deep`、`deep-reasoning`、`instant`のいずれか。 |
| `EXA_CATEGORY` | — | `company`、`research paper`、`news`、`personal site`、`financial report`、`people`のいずれか。 |
| `EXA_INCLUDE_DOMAINS` | — | カンマ区切りの許可リスト（最大1200エントリ）。 |
| `EXA_EXCLUDE_DOMAINS` | — | カンマ区切りのブロックリスト（最大1200エントリ）。 |
| `EXA_START_PUBLISHED_DATE` | — | ISO-8601形式、例：`2025-01-01`。 |
| `EXA_END_PUBLISHED_DATE` | — | ISO-8601形式。 |
| `EXA_MAX_AGE_HOURS` | — | 過去N時間以内にインデックスされたページのみを返します。 |
| `EXA_INCLUDE_HIGHLIGHTS` | `true` | 結果からハイライトスニペットを取得します。 |
| `EXA_TEXT_MAX_CHARS` | `800` | 結果ごとのテキスト/スニペット長の上限。 |
| `EXA_SUMMARY_QUERY` | — | 結果ごとのオプションのカスタム要約プロンプト。 |

### スニペットの組み立て方

FIM One は Exa のコンテンツフィールドをカスケード処理して、API が入力したコンテンツタイプに関わらず、すべての結果に対して有用なスニペットを生成します：

1. `highlights`（` … ` で結合）— 存在する場合は優先
2. `text` — 抽出された記事テキストにフォールバック、`EXA_TEXT_MAX_CHARS` に切り詰め
3. `summary` — 上記の両方が空の場合に使用

これにより、Exa がハイライトを抽出できなかった結果であっても、ダウンストリームの智能体は常に推論の対象となる空でないスニペットを持つことが保証されます。

### プリセット: ニュース監視

```bash
EXA_SEARCH_TYPE=fast
EXA_CATEGORY=news
EXA_MAX_AGE_HOURS=24
EXA_TEXT_MAX_CHARS=1200
```

# プリセット：研究論文検索

```bash
EXA_SEARCH_TYPE=neural
EXA_CATEGORY=research paper
EXA_INCLUDE_HIGHLIGHTS=true
EXA_TEXT_MAX_CHARS=2000
```

# プリセット：深い推論エージェント

```bash
EXA_SEARCH_TYPE=deep-reasoning
EXA_TEXT_MAX_CHARS=1500
EXA_SUMMARY_QUERY=What is the key finding and its supporting evidence?
```

## 帰属

FIM OneからのすべてのExa リクエストには、`x-exa-integration: fim-one` ヘッダーが含まれており、Exa はメンテナーダッシュボードでこの統合に API 使用状況を帰属させることができます。これは統合レベルの帰属のみに使用され、エンドユーザーの識別またはトラッキングには使用されません。
