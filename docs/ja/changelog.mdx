## [未リリース]

### 追加

- **GPT-5.x エージェントはツール呼び出し全体で推論を保持します。** FIM One は OpenAI Responses API を GPT-5.x モデル向けに直接使用し、各ターンの暗号化された推論を次のターンに引き継ぐため、マルチステップエージェントはすでに導き出した内容に基づいて構築され、ツールラウンドのたびに再導出することはありません。推論トークンカウントは使用量に表示され、思考パネルはモデル独自の要約を表示します。`FIM_GPT5_RESPONSES_MODE=bridge`（または `off`）を設定して以前の動作に戻すことができます。`/v1/responses` ルートを持たないエンドポイントは自動的にチャット補完にフォールバックします。

- **DAG プランの純粋な変換ステップは単一の直接 LLM 呼び出しとして実行されます。** プランナーは上流の出力のみを消費するマージ/書き換え/要約ステップを直接ステップとしてタグ付けし、使用されないツールループをスキップするため、コストとレイテンシが低下します。すべてのステップ結果は実行方法（直接呼び出しまたはエージェントループ、イテレーション、使用されたツール）も記録するようになりました。

- **エージェントは実行中に澄清用の複数選択肢質問を提示できます。** タスクが大きく異なる方向に進む可能性がある場合、エージェントは一時停止して最大 4 つの構造化された質問をチャットに提示します。各質問には 2～4 個のオプションと自由記述の「その他」があります。回答すると実行がその場で再開され、スキップまたはタイムアウトすると独自の判断で続行できます。

- **エージェントステップはライブの 1 行タイトルを持ちます。** エージェントが動作している間、各イテレーションは短い生成ラベル（「価格データを検証中…」）を取得し、単一の折りたたまれたヘッダーに表示されて最新のステップに循環します。展開するとステップタイムライン全体が表示され、ラベルは会話履歴に保持されます。

- **プロバイダーのモデルを一括削除できます。** Admin → Models の各モデル行にはチェックボックスがあり、ヘッダーはリスト全体を選択し、Shift キーを押しながらクリックすると行の範囲全体に選択を拡張します。選択を削除すると、選択されたすべてのモデルが 1 つのリクエストで削除され、カウントを名前に含む確認が表示されます。

- **チャット返信内の小さな比較表はカードスタイルレイアウトとしてレンダリングされるようになりました。** 最初の列が属性ラベルを保持する 2～3 列の表は、各属性を値セル内に表示します（AI チャット UI で普及している比較カードスタイルに一致）。より大きな表は従来のグリッドを保持します。

- **チャット返信は Mermaid ダイアグラムと SVG 図をレンダリングするようになりました。** `mermaid` コードブロックはテーマ付きダイアグラムになり、`svg` ブロックはソース切り替えとダウンロード付きの画像になります。どちらもソースが不完全または解析に失敗した場合は通常のコードにフォールバックするため、半分ストリーミングされたダイアグラムがエラーをフラッシュすることはありません。

- **回答、コードブロック、表をコピーできます。** すべての返信には Markdown としてコピーするアクション、コードブロックには言語を名前に含むヘッダー、表は Markdown としてコピーと CSV ダウンロード（UTF-8、Excel で正常に開く）があります。

- **引用はどのドキュメントから来たかを表示します。** 引用マーカーはソースのドキュメント名を含むピルとしてレンダリングされ、隣接するマーカーは 1 つのピルとカウントに折りたたまれます。ポップオーバーはその背後にあるすべてのソースをリストします。

- **`/clear` はチャット入力で機能します。** チャット入力に `/clear` と入力すると新しい会話が開始され、「新規チャット」をクリックするのと同じです。実行中のターンは最初に停止されます。

- **ダイアグラムとコードブロックはコピーするだけでなくダウンロードできます。** Mermaid ダイアグラムはレンダリングされた SVG をエクスポートし、すべてのコードブロックは言語に一致するファイル名でダウンロードされます。`csv` ブロックは Excel で正常に開く UTF-8 ファイルとしてダウンロードされます。

### 修正

- **Exa ドキュメントは Exa をデフォルト検索プロバイダーとして呼び出さなくなりました。** インテグレーションと環境変数ページでは、Exa を `WEB_SEARCH_PROVIDER=exa` で有効にするオプションのバックエンドとして説明するようになりました。デフォルトの検索パスは Jina のままです。

- **サイドバーロゴが再び実際のリンクになりました。** 中クリックと cmd/ctrl クリックでダッシュボードを新しいタブで開きます。左クリックはナビゲートして、短いバウンスアニメーションを保持します。

### Changed

- **サイドバーはナビゲーションを優先します。** モジュールナビゲーションは会話リストの上にコンパクトな連続リストとして配置され（Build / Resources / Operate セクションラベルなし）、ナビゲーション項目、新規チャット / 検索、会話行の間隔が狭くなり、サイドバーの下部のドックに隠れることがなくなりました。

- **ストリーミング返信はちらつかずに安定して表示されます。** 成長する回答はブロックごとにレンダリングされるようになりました。完成したブロックはフレームごとに再レンダリングされず安定したままで、途中の書式設定（太字、リンク、数式）は完成するまで保留されます。

- **最終回答は書き込まれたままストリーミングされます。** エージェントは情報収集の完了を通知し、ライブストリーミングターンとして回答を書き込むようになったため、長い返信はトークンごとに完全な詳細とともに到着し、待機後の再生はありません。`REACT_FINISH_SIGNAL=false` で以前の動作に戻ります。

- **アーキテクチャドキュメントはグラフエンジニアリングを FIM One にマッピングします。** [Planning Landscape](/architecture/planning-landscape) ではループ対グラフエンジニアリング、従来のビジュアルワークフローとの違い、Workflow / DAG / ReAct へのマッピング、各エンジンで活用する内容について説明しています。また、現在の事実として、すべての DAG ステップが既に完全な ReAct エージェント（ワンショット LLM 呼び出しではない）であることを述べています。ReAct と DAG エンジンページはこれにリンクしています。

- **プレーンチャットは常にフォローアップ提案を提供します。** バインドされたエージェントのない会話は各回答後に提案された次の質問を取得します。エージェントにバインドされたチャットは引き続きエージェントごとのフォローアップ提案トグル（デフォルトオフ）が必要です。挨拶やお礼などのクロージャーターンはチップを返さない場合があります。

- **新しく送信されたメッセージは画面の上部から始まります。** トランスクリプトは現在のターンの下に最初の行が画面の上部に到達するだけの十分なスペースを保持するため、質問は表示されたままで、回答は下のスペースに成長します。ターンが 1 画面を超えると、スペースは消えます。

- **推論ブロックはターンの実行中は折りたたまれたままです。** ReAct と DAG 出力の両方の推論は、デフォルトで 1 行のプレビューを表示するようになり、ストリーミング中に展開されず、結果が表示されたままになります。任意のブロックをクリックして完全なトレースを読むことができます。

- **エクスポートされた PDF と Word ファイルは中国語に適切に組版されます。** PDF エクスポートは参照ではなく実際の CJK フォントを埋め込むようになり、英語テキストの間隔の崩れと関連のない中国語文字としてレンダリングされた箇条書きが修正され、太字が機能するようになりました。Word エクスポートは東アジアフォントを宣言するため、混合中国語/英語の太字テキストは半分太字で出力されなくなり、両方の形式は見出しをトランスクリプト自体の構造に従属させたままにする 5 段階のサイズスケールを使用します。

- **エージェントは長いタスクを通じて計画を維持します。** エージェントは同じツールを無駄に繰り返す場合にアプローチを変更するよう通知され、計画なしで作業する場合は計画を書くよう促され、明示的な検証パスなしに計画項目がまだ開いている間に最終回答を提供することはできなくなりました。

- **ストリーミング回答はポップアップの代わりにイーズインします。** 新しく到着したブロックはストリーミング中に短くフェードインし、ユーザーの動きを減らす設定を尊重します。長いテーブルはカーソルの下の行をハイライトし、リスト箇条書きはテキストの後ろに配置され、テキストと競合しません。

- **ブロックアクションは到達するまで邪魔になりません。** 回答、コードブロック、図、テーブルのコピーとダウンロードはアイコンのみでツールチップ付き（ダウンロードは常に右端）で、ホバー時に表示され、キーボードでアクセス可能なままです。

- **サイドバーはチャットをまとめたままにします。** 会話リストは新規チャットと検索の直下に配置され、モジュールナビゲーションはユーザー領域の上のコンパクトな色付きドックに移動し、リストにより多くのスペースを提供し、サイドバーに明確な上から下への階層を与えます。

- **推論はデフォルトで折りたたまれています。** ライブ実行と過去の会話の両方の思考セクションは 1 行のプレビューに折りたたまれ、クリックで展開されます。推論は生成中はストリーミング中に開いたままで、ステップが完了すると折りたたまれます。

- **リストページはカードをスムーズに配置します。** エージェント、コネクタ、ナレッジベース、スキル、ワークフロー、ツール、会話、アーティファクト、マーケットは最初の読み込み時にカードを段階的に表示し、すべて一度に表示されるのではなく、フィルタリングとページング処理は即座に行われるため、検索ボックスへの入力は入場をリプレイしません。

### セキュリティ

- **レンダリングされたマークダウン内の生のHTMLがサニタイズされるようになりました。** モデル出力とアップロードされたマークダウンファイルは表示前にスクラブされるため、インジェクトされたスクリプト、イベントハンドラー、iframe、フォーム、スタイルオーバーライドはページに到達できなくなります。数式、構文ハイライト、テーブル、タスクリスト、ディスクロージャーブロックは影響を受けません。生のインライン`<svg>`はレンダリングされなくなります。代わりに`svg`コードブロックを使用してください。

### 修正

- **GPT-5.x 智能体现在在启用推理的情况下运行工具，而不是报错。** GPT-5.x 模型现在首先通过 Responses API，其中函数工具和推理协同工作；没有 `/v1/responses` 路由的端点会自动回退到聊天完成，其中 GPT-5.x 工具调用明确禁用推理，因为该 API 需要。OpenAI 兼容端点上的其他模型系列保持现有的聊天完成路径。

- **在 Planner 模式下，先问请求在一轮内完成。** 明确要求智能体在交付前通过多选问题澄清需求的目标（"问清楚我再出方案"）现在会生成一份清晰的问卷作为该轮的结果，而不是规划步骤等待答案、循环重新规划并以"目标未达成"加重复问题列表结束。Auto 模式将此类请求路由到 Standard 模式。

- **后续芯片不再将记录拉过答案。** 在一轮停在结果后，后续布局增长（建议、标题）保持原位，将实时轮折叠到历史记录中会重新停在同一对话的答案头，而不是跳到底部。

- **打开现有对话会进入最新消息。** 刷新聊天 URL 现在会像从侧边栏切换一样滚动到底部，而不是从线程顶部开始。

- **快速答案不再看起来卡在"处理中…"。** 没有生成步骤标题的完成轮显示思考过程标签，而不是实时处理微光文本。

- **动画现在遵循系统"减少动画"设置。** 登录背景的漂移渐变、英雄入场、呼吸注入消息文本和流式光标无论操作系统偏好如何都继续移动。它们现在保持静止，而报告工作进度的指示器保持可见，因此界面永远不会显示停滞。

- **执行模式选择器在轮运行时保持关闭。** 该芯片被灰显但仍在点击时打开其菜单，不像旁边的智能体选择器；两者现在在运行完成前都是惯性的。

- **推理在较新的模型上再次实时流式传输。** 实时推理是从硬编码的模型名称列表连接的，因此在该列表编写后发布的任何内容都显示微调器，然后一次性转储整个推理块。任何发出推理的模型现在都会流式传输它。

- **聊天视图跟上快速输出并进入答案。** 它不再在推理中期停滞并错误地报告下面有新内容，它跟随没有新事件而增长的内容，当轮完成时它在结果顶部而不是底部停止。滚动离开仍会交回控制权，返回底部会恢复跟随。

- **短答案在轮结束后保持在您阅读的位置。** 轮完成后，记录向下滑动，使问题及其回复紧贴输入框；回复现在在视图顶部保持其位置，直到发送下一条消息。

- **登录立即应用账户的首选语言。** 语言环境 cookie 现在在登录和 OAuth 回调期间同步，当账户的语言与登录页面呈现的语言不同时，登录页面会重新加载，因此目标不再在下次重新加载前以前一种语言出现。

- **Cmd+K 即使在侧边栏折叠时也能打开搜索。** 快捷键侦听器保持活动状态，但其对话框在折叠状态下从未挂载，因此快捷键无声地什么都不做。

- **引用再次命名它们来自的文档。** 在简单检索模式下，每个来源都被标记为"知识库"，因为检索工具丢弃了原始文件名；它现在报告来源，与接地管道已经做的相匹配。

- **长对话不太可能遇到硬上下文溢出错误。** 压缩现在以模型输入限制下方的安全边距触发，而不是完全在其上，启动时在快速模型的窗口太小无法容纳通用模型的上下文预算时记录警告。

- **SVG 图形在深色模式下保持可读。** 模型创作的 SVG 假设浅色画布，因此图形绘制在固定浅色表面上，而不是变成深色对深色。

- **浏览器标签忙指示器不再在轮中期消失。** 轮运行时，标签图标保持应用标记并在完整颜色和灰色之间脉冲，保持整个运行并在轮结束时可靠地恢复真实图标，即使在应用内导航后也是如此。启用减少动画时，它保持静态灰色标记而不是动画。

- **智能体不再在截断结果后数十次重新获取端点。** 截断通知现在以命令式指针开头指向保存的完整副本，持续用不同参数锤击同一端点的智能体会被警告，然后硬停止。

- **崩溃的运行现在报告错误而不是绿色"完成"。** 当智能体因内部故障而停止时，原始异常文本在成功复选标记下作为答案交付；故障现在通过错误通道，显示为错误通知。

- **重新连接到流不再重放您已看到的输出。** 实时流现在携带与恢复端点相同的位置光标，因此在连接断开后，只有错过的事件被重放，而不是整个轮。

- **跨网络块分割的流式事件不再丢失。** 恢复的流可能会丢弃其帧分两部分到达的事件；两个流路径现在共享一个处理任意块边界的解析器。

- **调用另一个智能体返回其实际答案。** 子智能体的回复过去到达时埋在原始执行跟踪内，淹没调用智能体的上下文；它现在只接收答案。

- **挂起的工具不再能无限期地停滞运行。** 每个工具调用现在都有墙钟时间限制（默认 180 秒），因此停滞的连接器或无响应的服务器以清晰的消息结束步骤，而不是卡住轮。

- **重复相同工具调用的卡住智能体现在会提前停止。** 相同的重复调用在几次尝试后被拒绝，而不是消耗整个迭代预算。

- **长对话压缩后不再丢失其早期上下文。** 压缩较早轮的摘要在下一次运行时被无声地丢弃；它现在被携带前进，因此智能体保持之前讨论的内容。

- **大型工具结果保持其结尾以及开头。** 当长结果被修剪以适应上下文窗口时，现在保持两端（命令输出的结论通常最重要），修剪正确考虑非拉丁文本，后续结果保证最小窗口而不是完全被清空。

- **相同的生成文件不再显示为两个下载。** 保存在真实文件名下的渲染 HTML 输出过去会生成两张具有相同内容的可交付卡；重复项现在按内容检测并折叠到特定命名文件。

- **内部卸载文件不再显示为可下载的可交付物。** 工具共享一个文件系统，代码执行运行期间卸载的大型工具输出可能被工件扫描拾取并显示为虚假下载卡。运行时簿记文件现在从工件检测中排除。

- **对话中的每个工具现在都在一个共享文件系统上工作。** 卸载的大型输出过去落在只有工作区读取工具可以看到的目录中，而 `file_ops`、`shell_exec` 和 `python_exec` 在其他地方操作——智能体会列出文件，然后被告知它不存在，并消耗其迭代预算寻找它。卸载的文件现在位于每个工具（包括执行容器）挂载的对话沙箱中；来自较早对话的文件保持可读。

- **读取大型卸载文件不再生成无尽的指针文件链。** 工作区读取的输出本身可能超过卸载阈值并保存为指向已在磁盘上的内容的新文件，将智能体发送到循环。工作区读取现在用精确恢复行而不是重新卸载进行限制。

- **DeepSeek 的即兴工具调用文本不再泄漏到答案中。** 当 DeepSeek 模型将工具调用写成纯 `<｜｜DSML｜｜Tool call: ...` 文本而不是使用函数调用通道时，原始标记到达聊天逐字。它现在被剥离，就像其他工具调用伪协议一样。

- **由模型输出限制截断的工具调用不再作为完成的工作通过。** 当长有效负载（例如编写完整 HTML 页面）耗尽输出预算中期调用时，半写的调用被无声地丢弃，智能体的前导文本——"现在我将保存文件"——成为步骤结果，因此产生任何内容的步骤被报告为已完成。截断现在被检测，智能体被告知重试，将工作分成较小的调用。

- **智能体确定其错过的目标现在被重试而不是结束运行。** 重新规划在分析器有信心时停止，这将有信心的"可交付物丢失"读作放弃的原因——重新规划存在的确切情况。运行现在仅在目标被判断为真正无法达到时提前停止，`DAG_MAX_REPLAN_ROUNDS` 限制其余的。

- **智能体的自检不再显示为答案。** 使用多个工具后，智能体在回复前运行一次性内部验证；该验证被逐字流式传输给您，因此答案到达为"让我验证：1. 完全解决？✅ …"而不是答案本身。检查现在是内部的，您看到的回复作为其自己的步骤编写。

- **刷新令牌轮换现在实际上使前一个令牌失效。** JWT `exp` 仅为秒精度，因此为同一用户在同一秒内发出的两个刷新令牌过去编码相同——轮换然后用相同值重写存储的哈希，被盗的刷新令牌可以永远续订。每个刷新令牌现在携带唯一的 `jti`，因此轮换的令牌不同，旧令牌立即停止工作。

- **当通过另一个智能体或工作流到达智能体时，审批闸门现在保持。** 在聊天中会要求确认的敏感连接器调用一旦通过 `call_agent` 委派或包装在工作流 `AGENT` 节点中，就会无检查地运行——这些路径启动智能体时没有任何钩子。两者现在都运行智能体自己的闸门，使用该智能体的确认设置，如果其钩子无法加载则拒绝运行它。

- **`SMTP_SSL` 中的拼写错误不再无声地以明文发送您的 SMTP 密码。** 以前任何值除了 `ssl` 或 `tls`（例如 `SMTP_SSL=true`）都会无警告地落入未加密连接，在系统电子邮件和电子邮件通知中都是如此。无法识别的值现在被完全拒绝，未加密交付必须明确请求为 `SMTP_SSL=none`，这在每次发送时记录警告。

### 削除

- **README Star History チャートとそのリフレッシュワークフロー。** GitHub が stargazers API を制限した後（2026年7月）、自社所有のチャートを維持するには、有効期限が切れて定期ジョブが失敗し続ける長期間有効な管理者 PAT が必要でした。チャート、SVG アセット、ジェネレータスクリプト、および `Star History` GitHub Actions ワークフローは削除されました。

- **アップグレード時に組織に共有されていた Knowledge bases は取り消されます。** v0.8.9 の例外措置により、すでに公開されている KB がサブスクライバーにアクセス可能に保たれていましたが、これは廃止されました。すべての共有 KB は個人用に戻され、サブスクリプションが削除され、残された非公開化アクションとサブスクライバー向けの KB バッジが消えます。Knowledge base は現在、共有 Agent を通じてのみ他のユーザーに到達でき、実行時に所有者のコンテンツを委譲します。

### 追加

- **スキルとワークフローはオプションモジュールになり、デフォルトではオフです。** 新規インストールはコア機能（チャット、エージェント、ナレッジベース、コネクタ）のみで起動し、管理者が Admin → Settings → Modules からスキルやワークフローを有効にできます。モジュールがオフの間、ナビゲーションとそのページ、API、マーケットエントリ、トリガーは非表示になります。何も削除されず、オンに戻すとすべてが復元されます。
- **DAG の再計画は完了した作業をやり直さず、中断された実行は中断した箇所から再開します。** プランの修正が必要な場合、既に完了したステップはその結果とともに新しいプランに引き継がれ、残りの作業だけが再計画・実行されます。ステップの進捗もリアルタイムでチェックポイントされるため、実行中に中断された場合（クラッシュ、デプロイ、接続切断）、同じリクエストを再試行すると完了したステップから再開され、最初からやり直されません。
- **遅いツールはエージェントをブロックせずにバックグラウンドで実行できるようになりました。** サンドボックス化されたコード実行（Python/Shell/Node）は `run_in_background` オプションを提供します。エージェントはタスク ID をすぐに取得し、他のステップで作業を続け、ツールが完了するとその結果を通知として受け取ります。エージェントがタスクがまだ実行中に完了しようとすると、それらを待機（制限付き）して結果を組み込んでから回答します。
- **会話履歴は圧縮前にスナップショットされ、予算によって切り詰められたツール結果はワークスペースに保存されます。** 長い会話の圧縮が履歴をサマリーに置き換える前に、完全なトランスクリプトが JSONL ファイルとしてコンバーセーションワークスペースに書き込まれます。同様に、集計トークン予算によって切り詰められたツール結果は完全な形でワークスペースに保存され、ポインタが残されます。どちらの場合もエージェント（およびあなた）は元のデータを読み戻すことができ、失われることはありません。
- **モデルが出力制限に達してもアンサーが途中で終わらなくなりました。** プロバイダーの出力トークン上限によって応答が切り詰められた場合、エージェントは自動的にモデルに中断した箇所から再開するよう要求し（最大 3 ラウンド）、セグメントを 1 つのシームレスな回答に結合します。推論ループと流式最終回答の両方で機能します。
- **LLM 呼び出しはプロバイダーの過負荷（HTTP 529）とゲートウェイタイムアウト（504）で再試行され、`Retry-After` を遵守します。** 以前は Anthropic からの 529 はフォールバックモデルが設定されていない限り即座に失敗していましたが、今は 429/5xx のように バックオフして再試行し、`Retry-After` ヘッダーが存在する場合はプロバイダーが指定した時間だけ正確に待機します。
- **エージェントは複数ステップのタスク中に表示されるプランを保持するようになりました。** ReAct エージェントは `update_plan` ツールを取得して、プランを TODO チェックリストとして書き込み、進捗に応じて更新できます。プランが複数のツール呼び出しの間に古くなった場合、完全なチェックリストがリマインダーとして再注入されます。長いタスクでもコンテキスト圧縮後に目標を維持できます。デフォルトでオン（`REACT_PLAN_TOOL_ENABLED`）。DAG サブステップとツールなしエージェントはスキップします。

- **エージェントは会話中にワークフローを実行できるようになりました。** あなたが所有または購読している、アクティブで人間の承認が不要なワークフローは、エージェントに `run_workflow` ツールとして提供されます。通常のチャットとエージェント選択時の両方で使用でき、タスクは決定論的で反復可能なサブプロセスをワークフローに引き渡し、その出力を取得できます。このような実行はワークフローの実行履歴に記録され、そのトークン使用量はワークフロー所有者のクォータに計上されます（所有者が既にクォータを超えている場合は実行が拒否されます）。Human Intervention ステップを含むワークフローはトリガーのみのままです（ワークフローページまたはその API キーから）。長時間ブロックされる可能性があるためです。
- **2 つの新しいワークフロースターターテンプレート：Connector Action と MCP Tool Call。** 「テンプレートから作成」ギャラリーはコネクタと MCP ノードを紹介するようになりました。外部システムまたは MCP ツールを呼び出し、結果を LLM でサマリーします。作成後に特定のコネクタ/サーバーを選択します。

### Changed

- **ナレッジベースは共有不可になりました。** ナレッジベースを組織またはマーケットプレイスに公開する機能が削除されました。ナレッジベースは共有エージェントにバインドされることでのみ他のユーザーに到達し、実行時に所有者のコンテンツを委譲します。既に公開されているナレッジベースは現在のサブスクライバーにアクセス可能なままで、メニューから個人用に戻すことができます。
- **コネクターと MCP サーバーはデフォルトで所有者の認証情報を共有しなくなりました（破壊的変更）。** 「所有者の認証情報へのフォールバックを許可」はオプトインになりました。新しいコネクター/MCP サーバーはこの設定がオフで作成され、既存のものもすべてオフに切り替わりました。共有コネクターまたは MCP サーバーの使用に所有者のトークンに依存していたサブスクライバーは、独自の認証情報を追加するか、所有者がそのリソースのフォールバックを再度有効にする必要があります。所有者は設定に関係なく常に独自の認証情報を使用できます。その結果、フォールバックがオフで認証情報がないコネクターは、MCP サーバーと同じように、エージェントのツールセットから非表示になります（呼び出し時に失敗するのではなく）。
- **新しいエージェントはデフォルトで ReAct 実行になります。** Auto モードはリクエストごとに 1 回の追加の高速モデル分類呼び出しを費やして ReAct と DAG を決定していました。新しいエージェント（および組み込み/マーケットプレイステンプレート）は ReAct がデフォルトになり、メッセージごとのレイテンシとコストが削減されます。Auto と DAG はエージェントごとに選択可能なままで、既存のエージェントは現在のモードを保持します。
- **AI エージェント作成は弱い高速モデルから復旧します。** 自然言語の指示からエージェントを構築または改善する場合、高速モデルで実行されます。有効な設定を生成できない場合、リクエストはエラーになる前に強力な汎用モデルで 1 回再試行されるため、弱すぎる高速モデルはユーザーに失敗として表示されなくなります。

### 削除

- **ビジュアルワークフロービルダーを9つのコアノードタイプに削減しました。** 環境変数、HTTPリクエスト、コード実行、イテレータ/ループ、サブワークフロー、テンプレート/リスト/変換ヘルパー、パラメータ/質問抽出器、分類器など、ほとんど使用されない16個のユーティリティおよび制御フローノードを削除しました。これにより、ビルダーは智能体、連接器、MCP サーバー、ナレッジベースのオーケストレーションに集中できるようになります。副作用として、共有ワークフローに埋め込まれたシークレットが不要になりました。現在は参照のグラフのみとなり、参照される各リソースは実行時にユーザーごとのアクセス制御を適用します。削除されたノードで構築された既存のワークフローは、残りのセットで再構築する必要があります。

### セキュリティ

- **APIキースコープがユーザーオブジェクトに付与されるのではなく、リクエストごとに保持されるようになりました。** これにより、キャッシュされたユーザーまたはアイデンティティマップで共有されたユーザーが別の認証コンテキストのスコープセットを継承する可能性があるという潜在的なスコープ混同パスが解決されます。
- **生成されたJWTシークレットを保持する自動作成の`.env`は、所有者のみ(0600)の権限で書き込まれるようになりました。** 既存の`.env`ファイルは権限が保持されます。
- **パスワードハッシュコストは`FIM_BCRYPT_COST`で調整可能になりました**(デフォルト12、bcryptの4～31の範囲に制限)。オペレーターはハードウェアとセキュリティ強化のバランスを取ることができます。
- **データベースコネクターは共有できなくなり、その生SQL ツールは所有者のみになりました。** データベースコネクターを組織またはグローバルに公開することは拒否されるようになり、任意SQLデータベースツールは、所有者認証情報フォールバック設定に関わらず、コネクターの所有者にのみ提供され、購読者には提供されません。以前は、共有データベースコネクターは所有者の(通常は高い権限を持つ)データベースアカウント上の制限されていないSQLを購読者に公開していました。ユーザーごとのスコープ付きデータベースアクセスは、将来の宣言的アクションレイヤーを通じて復帰します。
- **Webhookおよびcronでトリガーされるワークフローは、所有者のトークンクォータに対してカウントされるようになりました。** 公開APIキーまたはスケジュールでトリガーされる無人ワークフロー実行は、以前はトークン使用量をチェックまたは記録せずにLLMおよびエージェントステップを実行していました。これはクォータを完全にバイパスする計測されていない無料LLMパスでした。このような実行は、所有者のクォータに対して事前にゲートされるようになり(公開トリガーは拒否され、スケジュール実行は所有者がすでにクォータを超えている場合はスキップされます)、トークン使用量は実行ごとに記録され、チャットと同じ月間クォータに対してカウントされます。
- **Feishu承認カードは誰が承認できるかを強制するようになりました。** カードクリックは、クリッカーのFeishuアカウントがFIM Oneユーザーにリンクされており、そのユーザーがエージェントの承認者スコープ設定(イニシエーター、エージェント所有者、または組織メンバー)の下で実際に承認を許可されている場合にのみ受け入れられます。これはポータル内承認がすでに適用していたのと同じルールです。以前は、Feishuグループ内の誰もが保留中のアクションを承認または拒否でき、決定はアイデンティティなしで記録されていました。
- **Feishuチャネルは暗号化キーが必要になり、有効な署名のないコールバックは拒否されます。** 暗号化キーが設定されていない場合、コールバック署名検証は失敗に終わります(以前は署名なしのコールバックを受け入れていたため、チャネルのコールバックURLを知っている誰もが承認を偽造できました)。Feishuが暗号化を有効にしたときに送信する暗号化されたイベントエンベロープが復号化されるようになりました。新しいまたは編集されたFeishuチャネルは暗号化キーを提供する必要があります。
- **承認リクエストは意図しないチャネルにルーティングされなくなりました。** エージェントが明示的に設定された承認チャネルを持たない場合、保留中の承認はエージェントの完了通知チャネルに、またはそれが失敗した場合は組織の最初のチャネルにプッシュされる可能性がありました。これは機密アクションカードを承認者として選択されたことのないグループに表示していました。承認は現在、エージェントの明示的に設定された承認チャネルにのみ送信され、そうでない場合はポータル内承認にフォールバックします。
- **共有MCPサーバーとナレッジベースは、バインド時だけでなく、実行時にアクセスが再チェックされます。** ワークフローMCPステップ、エージェントのバインドされたMCPサーバー、またはエージェントのバインドされたナレッジベースは、実行するたびに現在のサブスクリプション状態に対して検証されるようになりました。そのため、組織を離れることによって取り消されたアクセスは、古いバインディングを通じて残るのではなく、すぐに有効になります。

### 修正

- **OAuth ログイン時に GitHub/Google/Discord/Feishu が遅い場合、ライブラリのデフォルトタイムアウトでハングするのではなく、「プロバイダーがタイムアウトしました」という明確なメッセージで素早く失敗するようになりました。** 汎用的なエラーメッセージの代わりに、わかりやすいエラーが表示されます。
- **HTML 成果物のスタイル変更を求められた場合、エージェントが不要な画像を生成しなくなり、実際にワークスペースに書き込まずにファイルが作成されたと主張することもなくなりました。** 画像生成はラスター画像に明確にスコープされ、ファイル成果物はツール呼び出しで書き込む必要があります。チャットにコンテンツを貼り付けるだけでは「ファイルを生成した」とは見なされません。
- **生成された HTML ページは、汎用的な紫グラデーションの外観ではなく、デフォルトで Claude にインスパイアされた温かみのあるパレットを使用するようになりました。** スタイルを指定しない場合、エージェントは温かみのあるミニマルなベースラインを使用します。指定されたスタイルは常に優先されます。
- **ツールが多い長い会話は、履歴がコンパクト化されても破損しなくなりました。** コンテキストコンパクト化により、ツール呼び出しとその結果の間の保持ウィンドウが切断される可能性があり、LLM プロバイダーが拒否するメッセージシーケンス（HTTP 400）が生成されていました。これはコンパクト化が最も必要な長い実行で発生していました。コンパクタは、各ツール呼び出しとその結果を保持側で一緒に保つようになりました。
- **バックグラウンドツール結果がステップストリームと DAG エビデンスに表示されるようになりました。** バックグラウンドで実行されたツールは、その実際の出力をエージェントの内部通知メッセージ内でのみ配信していました。UI のステップタイムラインと DAG 回答検証エビデンスには、ディスパッチプレースホルダーのみが表示されていました。ドレインされた結果は、実際のツール名の下で通常のツール完了イベントとして発行されるようになりました。
- **重複するステップ ID を持つ稀なプランナー出力が、DAG ターン全体を破損しなくなりました。** 重複する ID は以前「循環依存」エラーとして誤診断されていました。現在は決定論的に名前が変更され、計画が進行します。
- **複数の ReAct ループの正確性修正。** 空の出力を返すツールは、ワークスペースが有効な場合、「出力なしで完了」という注記を保持していました。DAG ステップが満たせない依存関係によってブロックされた場合、UI がハングするのではなく、適切な終了イベントが発行されるようになりました。ネイティブツール呼び出しがないモデルの場合、フォールバック回答合成はツール呼び出しだけでなくツール結果を確認するようになりました。
- **会話ワークスペースが実際にチャットに接続されるようになりました。** 大きなツール結果が回復可能になり、サイレントに失われることがなくなりました。エージェント層のワークスペース復旧パス（`workspace://` ポインタを使用した大出力オフロード、予算切り詰めツール結果の完全コピー救済、コンパクト化前のトランスクリプトスナップショット）は存在していましたが、チャットエンドポイントはワークスペースを作成しなかったため、実行されていませんでした。ツール結果予算が枯渇すると、モデルはデータを読み戻す方法がない空の観測を受け取り、推測から回答していました。ReAct と DAG ステップエージェントは、会話ごとのワークスペースを取得するようになりました。会話を削除すると、そのワークスペースファイルと残されたクラッシュ再開チェックポイントがクリーンアップされます。

- **Stripe 請求 — Pro プラン サブスクリプション。** `/settings?tab=billing` の新しい `Plan & Billing` タブに、現在のプラン、月次トークン使用量、期間リセット、および `Upgrade to Pro`（Stripe Checkout）または `Manage subscription`（Customer Portal）が表示されます。チェックアウト成功時に購入したプランを表示するコンフェッティモーダルが開き、リダイレクトパラメータは却下後にのみ削除されるため、更新時に再トリガーされません。クォータ強制は各ユーザーのプランを尊重します。キャンセルされたサブスクリプションは有料期間が終了するまで Pro に留まります。ストリーム中の 402 クォータダイアログは請求タブに移動します。管理者は Admin Panel → Billing でプランを管理し、サブスクリプションを参照できます。Pro は現在 Stripe **テストモード** 価格を使用しています。本番環境への切り替えは価格 ID を置き換えます。
- **管理者制御の請求機能フラグ。** Admin → System Settings の `Enable Stripe Billing` トグルは、ユーザー向け `/api/billing/*`、Stripe ウェブフック、管理者プラン/サブスクリプション CRUD、フロントエンド請求タブ + 管理者ナビゲーションを含む Stripe パイプライン全体をゲートします。オフの場合、すべて非表示または 503 になります。最初の有効化は Free + Pro をシードし、`default_plan_id` ポインタを設定し、`users.plan_id` をバックフィルします。その後のオン/オフは純粋なフラグ切り替えです。Stripe 認証情報のないプライベートデプロイメントはクリーンなままです。請求がオフの場合、クォータチェーンは管理者が設定した `Default Monthly Token Quota` にフォールバックします。
- **ユーザーごとの無制限クォータ + Registered 列。** 空のクォータフィールドはグローバルリミットを継承します。`0` は無制限を付与します。以前は両方が同じ状態に折りたたまれていました。ユーザーテーブルには Registered 列も追加されます。
- **非英語ドキュメント（`zh` / `ja` / `ko` / `de` / `fr`）は完全な API Reference および Channels Configuration セクションを表示するようになりました** — `Endpoints` グループと `Configuration > Channels` サブグループは以前は英語のみでした。

### Changed

- **`Plan & Billing` は Settings タブであり、スタンドアロンページではありません。** `/settings/billing` を `/settings?tab=billing` に戻し、ユーザーがプランを切り替える際に左ナビゲーションが表示されたままになるようにしました（GitHub / Linear / Notion と同じ）。スタンドアロンルートはリダイレクトされるため、古いブックマークと以前のデプロイの Stripe Checkout リターン URL は引き続き機能します。`Subscriptions` タブは `Marketplace` に名前変更され、プランサブスクリプションとの区別が明確になりました。
- **Free プランのクォータは admin Plans ページで読み取り専用です。** System Settings → Default Monthly Token Quota から取得され、そこでの編集は自動的に反映されます。バックエンドは Free プランの `monthly_token_quota` に対する PATCH を暗黙的に無視します。
- **トークンクォータは、課金ページ、プランカード、admin Plans テーブル全体で `5M` / `100K`** として表示されます（`5,000,000` の代わりに）。Admin INPUT フィールドは引き続き生の数値を受け入れます。
- **翻訳の権限がロケール別ファイルから単一の用語集にシフトしました。** ルールは [`scripts/translation-glossary.md`](https://github.com/fim-ai/fim-one/blob/master/scripts/translation-glossary.md) に存在し、すべての LLM 翻訳呼び出し（JSON、MDX、README）に読み込まれます。pre-commit フックは生成されたロケールファイルへの手動編集を無条件に拒否します。誤訳を修正するには、用語集を編集し、`--force` で再生成してください。
- **ライセンサーと準拠法。** FIM One Source Available License は現在 **FIM Labs Pte. Ltd.**（シンガポール）により付与されます。準拠法は中華人民共和国からシンガポールに移行し、紛争は SIAC 仲裁（シンガポール、仲裁人 1 名、英語）に移行します。新しいトップレベルの `NOTICE` ファイルは、R&D 帰属、商標、およびサードパーティコンポーネントポリシーを記録します。許可された使用または制限条件に変更はありません。

### 修复

- **管理员对智能体、连接器、知识库和 MCP 服务器的批准/拒绝操作不再在 PostgreSQL 上失败。** 发布审核 `reviewed_at` 列现已支持时区，因此批准写入在 PG 上成功（该 bug 在 SQLite 开发数据库上不可见）。
- **OAuth 用户可以再次刷新会话。** OAuth 颁发的刷新令牌以刷新端点无法匹配的形式存储，导致访问令牌过期后需要重新登录；现在它以与其他路径相同的摘要形式存储。
- **浏览器标签页标题现在反映 `/settings` 和 `/admin` 中的活跃子标签页**（例如 `Settings · Billing — FIM One`），因此多个固定标签页可以区分。
- **使用情况页面在管理员设置默认令牌配额时不再报告"无限制"** — 它现在通过统一配额链解析（按用户覆盖 → 计划层级 → 系统默认值）。
- **智能体设置：绑定资源在进入时不再闪烁显示"(已删除)"。** 孤立徽章在库存获取稳定后才呈现。
- **Toast 通知现在遵循浅色/深色主题**，而不是硬编码为深色。
- **按智能体的使用情况分解不再为与已删除智能体关联的对话重复"直接聊天"行。**
- **自托管 `./deploy.sh` 不再因 `container name already in use` 而失败** — 在 `docker compose up` 前清理哈希前缀的僵尸容器和 DooD 沙箱子进程。
- **推送后不再出现冗余的 `chore(i18n): sync translations` 提交** — 预提交翻译钩子现在将 `.translation-cache.json` 与翻译文件一起暂存。
- **当需要确认的工具在未绑定智能体的会话中运行时，智能体聊天不再崩溃** — 当没有智能体可路由时，闸门优雅地退出。
- **在严格交替提供商（Claude）上重试不再因历史记录中来自已停止轮次的孤立用户消息而失败** — 相同角色的连续消息在分发前折叠为单个轮次。
- **演练场重试在流前窗口期间不再短暂显示两次查询。**
- **ReAct 智能体现在在操作员拒绝批准请求后确认并停止**，而不是重试改写的工具调用。
- **演练场"建议后续问题"返回并现在是按智能体选择加入**（默认关闭；智能体设置中新增 `Follow-up Suggestions` 切换）。

## [v0.8.5] - 2026-04-23

### Added

- **貢献者向けi18n ワークフロー**: 貢献者は英語ソースファイルに触れるPRを送信するために `LLM_API_KEY` を設定する必要がなくなりました。ローカルのpre-commitの翻訳ステップがスキップされた場合（キーなし）、新しい `.github/workflows/i18n-sync.yml` ワークフローがPRマージ後に `master` で EN → ZH/JA/KO/DE/FR に翻訳し、自動コミットします。pre-commitフックは生成されたロケールファイルへの手動編集を拒否するようになりました（正当な翻訳修正のための `ALLOW_LOCALE_EDIT=1` オーバーライド付き）。これにより、英語ソースと翻訳出力の間の暗黙的なドリフトを防ぎます。
- **i18n CI フォールバック エンドツーエンド検証**: スモークテストプッシュ（英語のみ、ローカル翻訳フック スキップ）により、GitHub Actionsワークフローが変更されたソースを検出し、5つのロケールすべてに翻訳し、再帰を防ぐために `[skip ci]` を付けてmasterに自動コミットすることが確認されました。

- **信創（Xinchuang）データベースサポート**: Database Connectorは、PostgreSQL/MySQLと並んでKingbaseES（人大金仓）、HighGo（瀚高）、DM8（达梦）をリストするようになりました。KingbaseESとHighGoはPG互換で、追加の依存関係なしに `asyncpg` を再利用します。DM8は公式の `dmPython` ベンダーホイールを使用します。スタンドアロンの `scripts/test_xinchuang_dbs.py` により、オペレーターはCLIからライブ接続を検証できます。
- **Feishuチャネル + 確認闸門（IM経由）**: 新しい `Channel` リソースタイプ（組織スコープ、認証情報は保存時に暗号化）により、組織はFeishuアプリを接続して送信メッセージングを行うことができます。`requires_confirmation=True` でフラグが立てられたツールは、ポータルの確認ダイアログのみを表示するのではなく、設定されたFeishuグループに承認/却下のインタラクティブカードを送信するようになりました。グループの任意の認可されたメンバーがFeishuから直接承認または却下できます。Settings → Channels管理UI（リスト、ダーティ状態保護付きの作成/編集、コピー可能なコールバックURLを含む詳細、テスト送信）、CRUD API（`/api/channels`）、署名検証とURLチャレンジサポート付きのFeishuイベントコールバックエンドポイント（`/api/channels/{id}/callback`）をカバーします。v0.9 IM Channel Integration ロードマップアイテムの最初のステップで、2026-04-24ロードショーより前にリリースされます。

- **Channelsおよび Hook System アーキテクチャドキュメント**: 新しい `docs/architecture/hook-system.mdx` は3つのフックポイント、フックがLLMループの外で実行される理由、およびFeishuGateHookをエンドツーエンドで説明しています。既存のアーキテクチャページ（system-overview、organization、react-engine、philosophy）はそれにクロスリンクしています。READMEはMessaging Channelsをv0.8の最初のクラスの機能としてリストし、Application Layerダイアグラムには、Portal/API/iframeと並んでIM ターゲットが含まれます。

- **設定可能な確認闸門 — インライン*または*チャネル**: すべてのエージェントは、Settings内に「Approval」セクションを持つようになりました。3つのルーティングモード（Auto / Inline only / Channel only）、承認者スコープセレクター（initiator / agent owner / anyone in the org）、「すべてのツール呼び出しに確認を要求」オーバーライド、および明示的な承認チャネルピッカーがあります。Autoモードは、リンクされたチャネルが存在する場合はそれを使用し、チャットストリーム内のインライン承認カードに適切にフォールバックします。したがって、チャネルを持たないエージェントは、サイレント失敗する代わりに実際の承認UXを取得します。新しい `POST /api/confirmations/{id}/respond` エンドポイントはFeishuウェブフックと単一の決定記録パスを共有するため、チャットでクリックされたか、Feishuグループでクリックされたかに関わらず、すべての承認は同じ `approver_user_id` および `decided_at` 監査フィールドをスタンプします。

### 修复

- 连接器所有者使用 `allow_fallback=false` 且仅有默认凭证（无按用户凭证）发起的连接器调用不再返回 401"需要身份验证"错误。所有者现已豁免于回退闸门——该标志仅控制*其他*用户是否可以借用所有者的默认凭证。之前所有者自己的智能体在无声地发送未认证请求，同样的问题也影响了工作流 `connector_action` 节点。
- 对话导出现在为自动路由的 DAG 对话显示正确的模式标签（"Planner"/"规划"），而不是始终显示"Standard"。
- 导出时间戳现在遵循用户配置的时区，而不是显示原始 UTC。
- 上传的文件内容不再泄露到导出的对话中；仅包含用户的消息文本。
- 当提供商为每个流式工具调用增量重复使用 `index=0` 时，并行工具调用不再发生碰撞；聚合器现在通过 id 或名称变化检测边界，并将后续增量重新映射到正确的槽位。
- 设置 → 通道现在反映当前用户的组织角色：成员（非管理员/所有者）看到禁用的"新建通道"按钮、隐藏的编辑/启用-禁用/删除操作、只读横幅和权限感知的空状态——而不是提交时失败并显示"需要组织管理员访问权限"的启用 CTA。
- 会话过期重定向现在保留查询字符串，因此用户在重新身份验证后会回到他们正在查看的确切标签/筛选器，而不是裸路径。
- Feishu 通道表单不再在与分层在对话框上方的聊天选择器交互时显示虚假的"放弃未保存的更改"提示。
- Feishu 通道设置提示在 UI 本身已是中文时不再重复中文标签（例如之前渲染为"事件与回调（事件与回调）"）。
- 架构管理器中的"全部标注"不再返回 500 内部服务器错误——完整标注后端路径存在未绑定变量错误，阻止了每次调用。
- 编辑数据库连接器现在在密码字段中显示 `********` 占位符，而不是三个项目符号掩码文本，使得留空字段以保留存储密码的意图显而易见。
- 更新连接器操作不再折叠详情面板——编辑的操作保持选中状态，以便用户可以继续迭代。
- AI 连接器编辑器现在区分成功、部分失败和完全失败，而不是对所有三种情况显示相同的"已完成"消息。失败原因内联显示，以便用户可以看到实际出错的地方。
- AI 连接器编辑器不再能够一次性无声地清除多个操作。批量删除（>2 个操作）现在需要用户指令中的显式破坏性关键字（"rebuild"、"全部重建"、"wipe" 等）；否则操作被拒绝并显示清晰的错误，保护 `requires_confirmation` / JMESPath 设置免受意外丢失。
- 门户聊天中的确认卡片现在显示请求是否被路由到通道（例如 Feishu）或内联处理，以及关于谁被允许批准的人类可读提示（发起者、智能体所有者或任何组织成员）。通道路由的请求还会生成内联待处理卡片，以便用户不会想知道通知是否真的被发送了。
- Feishu 批准卡片在第一次决定后变为只读：`/callback` webhook 返回替换卡片，其中批准/拒绝按钮被移除，标题着色为绿色（已批准）或红色（已拒绝），防止重复点击。来自过时 Feishu 客户端的仍然到达的重复点击会收到"此请求已被批准/拒绝。"提示和一份新的已决定卡片副本，以便过时的视图赶上。
- 恢复了通道行和详情表上的纯"发送测试消息"操作。批准演练场执行完整的钩子往返，但仅通知通道（未连接批准钩子）仍需要快速凭证/连接性健全性检查，纯测试发送涵盖了这一点。
- 对同一 Feishu 批准卡片的并发点击不再都能成功。`/callback` 处理器现在通过条件 `UPDATE ... WHERE status='pending'` 翻转 `ConfirmationRequest` 状态，并使用受影响的行数来决定哪个调用者"赢"；之前两个并行请求都可能读取 `pending` 并竞争写入，可能导致同一行上批准后拒绝。
- 待处理的批准请求现在在 `CHANNEL_CONFIRMATION_TTL_MINUTES`（默认 24 小时）后通过后台清理器自动过期。防止数天后的过时点击翻转已被拆除的智能体状态；对过期卡片的下一次点击会收到灰色"已过期"已决定卡片和"不再活跃"提示。
- 发送测试消息现在传递纯文本通知（无批准/拒绝按钮）并仅存在于通道详情表中——不在行下拉菜单中。不打算使用批准钩子的用户不会被"测试"消息上的交互按钮混淆。批准往返测试仍可通过批准演练场按钮获得。
- 通道详情表紧凑化："如何完成设置"现在是默认折叠的可折叠部分（因此对于已配置的通道不会主导表），外部填充减少了，使内容更靠近表边缘。
- Builder AI 不再将掩码（`****`）凭证报告为缺失——它现在将其识别为已配置并跳过虚假的"凭证缺失"指导。
- 演练场智能体列表现在显示所有可访问的智能体，而不仅仅是已发布的智能体，因此草稿智能体可以在不发布的情况下进行测试。

## [v0.8.3] - 2026-04-16

### 追加

- **`convert_to_markdown` 組み込みツール** — Microsoft の MarkItDown を使用して、任意のファイル、URL、YouTube リンク、またはデータ URI をクリーンな Markdown に変換する新しい汎用エージェントツール。PDF、Word（.docx）、Excel（.xlsx/.xls）、PowerPoint（.pptx）、HTML、JSON、CSV、XML、ZIP、EPUB、Outlook .msg、画像、音声（音声→テキスト）、YouTube トランスクリプトに対応。すべてのエージェントでデフォルトで利用可能 — `web_fetch` と同じレベル。ビジョン対応 LLM が設定されている場合、埋め込み画像とスキャン済み PDF ページは公式の `markitdown-ocr` プラグイン経由で自動的に OCR されます。以前はこの機能は背景の RAG 取り込みパイプライン内に隠されていました。エージェントはインタラクティブな会話パス上でこれを利用できるようになりました。

- **`markitdown-ocr` 経由のドキュメント OCR** — DOCX / XLSX / PPTX 内の埋め込み画像とスキャン済み PDF ページは、FIM One の残りの部分がルーティングするのと同じビジョン対応 LLM を使用して OCR されるようになりました。組み込みの `convert_to_markdown` ツールと RAG 取り込みパイプラインの両方に適用されるため、チャット時の変換とナレッジベース取り込みは同じ入力に対してバイト単位で同一の Markdown を生成します。

- **ドキュメント OCR 用のユニバーサルビジョンプロバイダーサポート** — 新しい `LiteLLMOpenAIShim` ダックタイプは、任意の FIM One `OpenAICompatibleLLM` を openai SDK の `.chat.completions.create(...)` API 形状でラップし、`litellm.completion()` 経由でディスパッチします。MarkItDown（openai SDK サーフェスをハードコードしている）は Anthropic Claude、Google Gemini、Azure、Bedrock、および LiteLLM がサポートするその他のプロバイダーを利用できるようになりました — FIM One 内のプロバイダー固有のアダプターコードは不要です。

- **ビジョン対応 RAG 取り込み** — Office ドキュメントとスキャン済み PDF のナレッジベースアップロードは、ワークスペースのデフォルトビジョン LLM（DB ファースト、ENV フォールバック）を解決し、取り込み中に OCR 用に MarkItDown に渡すようになりました。ゼロリグレッション：ビジョン対応モデルが利用できない場合、取り込みはサイレントにテキストのみモードにフォールバックします — 機能前の動作とまったく同じです。

- **拡張 MarkItDown フォーマットカバレッジ** — RAG は MarkItDown の音声トランスクリプションと Outlook エクストラ経由で `.pdf`、`.msg`（Outlook）、`.epub`、`.mp3`、`.wav`、`.m4a` をネイティブに取り込むようになりました。YouTube URL は `markitdown[youtube-transcription]` 経由で `convert_to_markdown` を通じてフローします。

- **`LLM_SUPPORTS_VISION` 環境変数** — ENV モードのドキュメント OCR フォールバック用のオプションのオプトアウト（`=false`）。デフォルト動作は楽観的（`true`）で、一般的な ENV セットアップ（`gpt-4o`、`claude-3-5-sonnet`、`gemini-1.5-pro/flash`）をカバーします。ENV で設定された `LLM_MODEL` がビジョンをサポートしない場合（例：`deepseek-v3`、`qwen-chat`、`llama-3.1`、`gpt-3.5-turbo`、`o1-mini`）のみ `false` に設定して、ドキュメントアップロードのたびに失敗するビジョン呼び出しをスキップします。管理者がキュレーションした ModelGroup がアクティブな場合は完全に無視されます — DB モードが利用可能な場合は常に真実のソースです。

- **ターンレベルプロファイラー** — 各 ReAct ターンは、フェーズレベルのタイミング（`memory_load`、`compact`、`tool_schema_build`、`llm_first_token`、`llm_total`、`tool_exec`）をターンごとに単一の構造化ログ行で記録するようになりました。`REACT_TURN_PROFILE_ENABLED` 経由でトグル可能（デフォルト：オン；ゼロオーバーヘッドのノーオプの場合は `false` に設定）。

- **構造化コンパクトワークカード** — 会話圧縮は、独自の 9 セクション Markdown 出力を型付き `WorkCard` に解析し、新しいコンパクトを前のものにマージするようになりました。これにより、長いセッション全体でのエラーと保留中のタスクは、複数の圧縮ラウンド全体で生き残り、最初からやり直して再要約されるのではなく保持されます。

- **動的システムプロンプト予算配分** — コンテキスト予算計算から固定の`SYSTEM_PROMPT_RESERVE`（4Kトークン）を削除しました。ContextGuardはシステムプロンプトを動的に考慮し、各イテレーションで約4Kの追加利用可能コンテキストを提供します。
- **一元化されたツール切り詰め** — すべてのツールタイプが共有モジュールへの切り詰めを委譲するようになりました。デフォルトは`TOOL_OUTPUT_MAX_CHARS`、`TOOL_OUTPUT_MAX_ITEMS`、`TOOL_OUTPUT_MAX_BYTES`環境変数で設定可能です。
- **ドメイン検出の分離** — ドメイン分類は各エンドポイントで独立して実行され、自動ルーティングにバンドルされなくなりました。ドメインSOP指示は、Webサーチを強制するのではなくガイドするようにソフト化されました。
- **`AUTO_ROUTING`環境変数を削除** — 自動エンドポイントは常にクエリを分類します。

### 修正

- **重複メッセージ送信** — チャット入力は同期ガードを使用して、急速なクリックで同じメッセージが複数回送信されるのを防ぐようになりました。
- **構造化出力デグラデーションチェーン** — 3レベルのフォールバック（ネイティブ FC → JSON モード → プレーンテキスト）が全レベルを正しく通過するようになりました。
- **`json_mode_enabled` DB値が無視される** — Admin経由で設定されたモデルは、環境変数に常にフォールバックするのではなく、モデルごとの設定を正しく使用するようになりました。
- **DAG計画失敗メッセージ** — 生のパイプラインエラーの代わりに、ユーザーフレンドリーな二言語メッセージを表示するようになりました。
- **MCP サーバーオーナーの allow_fallback バイパス** — サーバーオーナーは `allow_fallback=False` によってブロックされなくなりました。
