## [v0.8.7] - 2026-06-10

### セキュリティ

- **二要素認証のバイパスを修正しました。** API とチャット/SSE 認証は現在、genuine なアクセストークンが必要です（SSE ストリーミングは短命なチケットも受け入れます）。2FA テンポラリトークン、リフレッシュトークン、バインド/SSE チケット——すべて同じキーで署名されているもの——は認証のために再利用できなくなったため、盗まれたパスワードだけでは二番目の要素をスキップできません。
- **OAuth ログインは未検証のメールアドレスで既存アカウントに自動リンクされなくなりました。** サードパーティアカウントは、プロバイダがそのメールアドレスを検証済みとマークした場合にのみ、メールでローカルアカウントにマッチするようになり、攻撃者が制御する未検証アドレスを介した乗っ取りを防ぎます。

### 追加

- **`file_ops.apply_patch` — V4A形式のdiffパッチをファイルに適用します。** エージェントが行ベースのハンクとファジィ空白マッチング対応で複数行編集を実行できます。既存の`find_replace`を補完し、完全な部分文字列マッチが脆い場合に対応します。
- **入力と出力の検証用コンテンツガードレール。** 新しい`core/agent/guardrail`レイヤーが既存のツール権限ゲートとセキュリティチェックと並行して実行されます（置き換えではなく）。入力ガードレール（デフォルト：ジェイルブレークフレーズ検出器）はLLM呼び出しの前に実行され、トリガーされた場合はターンを中止してトークンを節約し、チャットに明確な「ブロック済み」通知を表示します。出力ガードレールは最終的な回答の後に実行されます。`FIM_GUARDRAILS_INPUT` / `FIM_GUARDRAILS_OUTPUT`環境変数で設定可能です。エージェント単位のUI設定は将来のリリースで提供される予定です。

### Changed

- **`/settings?tab=billing` がフルウィルスでレンダリングされ、他の Settings タブと視覚的に一貫するようになりました。** `max-w-4xl` 幅制限と冗長な外側スクロールコンテナを削除し、ページタイトルアイコンを削除し、プラン / 使用量 / サブスクリプション / プラン比較カードを書き直して、Usage タブと同じシンプルなボーダー付きdiv パターン（コンパクトラベル + `tabular-nums` 数字）を使用するようにしました。以前のレイアウトは、Settings フレームに誤って挿入されたスタンドアロンページのように見えていました。

### 修正内容

- **トークンクォータがご利用月の初日ではなく、お客様の請求日にリセットされるようになりました。** 使用状況は常にカレンダー月単位でカウントされていましたが、有料ユーザーは 20 日に課金されながら 1 日まで新しいクォータを待つ必要がありました。また、月の後半に開始されたサブスクリプションは、数日後に実質的に 2 番目の満杯なクォータを取得していました。クォータは現在各サブスクリプションの月次記念日にリセットされます（無料ユーザーはカレンダー月にリセットされたままです）。年間請求プランは、年に 1 度ではなく毎月正しく補充されます。プラン & 請求タブ、使用状況カード、クォータ超過ダイアログはすべて同じ期間内の使用状況を測定し、リセット日を表示するようになったため、表示される「この期間の使用状況」はチャットが実際に停止する地点と一致します。

- **サブスクリプション更新が請求期間を進めるようになりました。** 自動更新時に、Stripe が課金して請求をロールフォワードしたにもかかわらず、表示される期間終了日は前のサイクルで固定したままでした——更新ハンドラーは請求書ペイロード内の新しい期間のみを読み取っていましたが、そこは信頼できません。現在は Stripe から信頼できる期間の境界を取得するため、サイクル終了日（およびクォータリセット）は毎回の更新時に進みます。これにより、このようなサブスクリプションをキャンセルすると、真の期間終了ではなく直ちにアカウントをダウングレードする潜在的なリスクも排除されます。

- **生のツール呼び出しプロトコルがエージェント回答に漏れなくなりました。** モデルがツール呼び出しをプレーンテキストとして即興する場合（例えば `<tool_call>`/`<tool_response>` ブロックを発行する——利用可能でないツールに到達するときに一般的）、そのテキスト（その内部の base64/ファイルダンプを含む）は回答に逐語的に表示される可能性がありました。すべての回答パスはこの疑似プロトコルを削除し、パーサーは `{"name","arguments"}` 方言を実際のツール呼び出しとして認識し、漏出させなくなりました。

- **エージェント ターン中の `APIConnectionError: Connection error` の断続的なバースト。** 共有 HTTP 接続プールは、最大 30 秒間のアイドル接続を保持していました。アップストリーム リレーまたは NAT がアイドル接続を無音で回収した場合、次のリクエストは半分死んだソケットを再利用して失敗しました。キープアライブ有効期限はデフォルトで短い 5 秒に設定され（ターン内のウォーム接続は引き続き再利用されます）、プールは `LLM_HTTP_MAX_CONNECTIONS` / `LLM_HTTP_MAX_KEEPALIVE` / `LLM_HTTP_KEEPALIVE_EXPIRY` で調整可能になりました——信頼できないアップストリームの背後で接続の再利用を完全に無効にするには `LLM_HTTP_MAX_KEEPALIVE=0` を設定します。

- **API キー使用統計（`total_requests`、`last_used_at`）がすべてのリクエストで永続化されるようになりました。** 以前は増分がリクエストのデータベース セッションに書き込まれていましたが、これはそれ自身の書き込みを実行するエンドポイントによってのみコミットされます——読み取り専用の API キー呼び出し（ダッシュボード、ファイル、モデル、エクスポート、...）はカウンターを無音でロールバックしていました。使用状況は現在、独立した自動コミット セッションに記録され、リクエスト成功から切り離されます。

## [v0.8.6] - 2026-05-08

### 追加

- **Stripe 請求 — Pro プラン サブスクリプション。** `/settings?tab=billing` の新しい `Plan & Billing` タブに、現在のプラン、月次トークン使用量、期間リセット、および `Upgrade to Pro`（Stripe Checkout）または `Manage subscription`（Customer Portal）が表示されます。チェックアウト成功時に購入したプランを表示する紙吹雪モーダルが開き、リダイレクトパラメータは却下後にのみ削除されるため、更新時に再トリガーされません。クォータ強制は各ユーザーのプランを尊重します。キャンセルされたサブスクリプションは有料期間終了まで Pro のままです。ストリーム中の 402 クォータダイアログは請求タブに移動します。管理者は Admin Panel → Billing でプランを管理し、サブスクリプションを参照できます。Pro は現在 Stripe **テストモード** 価格を使用しています。本番環境への切り替えでは価格 ID を置き換えます。
- **管理者制御の請求機能フラグ。** Admin → System Settings の `Enable Stripe Billing` トグルは、ユーザー向け `/api/billing/*`、Stripe ウェブフック、管理者プラン/サブスクリプション CRUD、フロントエンド請求タブ + 管理者ナビを含む Stripe パイプライン全体をゲートします。オフの場合、すべて非表示または 503 になります。最初の有効化は Free + Pro をシード設定し、`default_plan_id` ポインタを設定し、`users.plan_id` をバックフィルします。その後のオン/オフは純粋なフラグ切り替えです。Stripe 認証情報のないプライベートデプロイメントはクリーンなままです。請求がオフの場合、クォータチェーンは管理者が設定した `Default Monthly Token Quota` にフォールバックします。
- **ユーザーごとの無制限クォータ + Registered 列。** 空のクォータフィールドはグローバルリミットを継承します。`0` は無制限を付与します。以前は両方が同じ状態に折りたたまれていました。ユーザーテーブルには Registered 列も追加されます。
- **英語以外のドキュメント（`zh` / `ja` / `ko` / `de` / `fr`）は、完全な API Reference および Channels Configuration セクションを表示するようになりました** — `Endpoints` グループと `Configuration > Channels` サブグループは以前は英語のみでした。

### Changed

- **`Plan & Billing` は Settings タブであり、スタンドアロン ページではありません。** `/settings/billing` を `/settings?tab=billing` に統合したため、ユーザーがプランを切り替える際も左のナビゲーションが表示されたままになります (GitHub / Linear / Notion に合わせています)。スタンドアロン ルートはリダイレクトするため、古いブックマークや以前のデプロイの Stripe Checkout リターン URL は引き続き機能します。`Subscriptions` タブの名前は `Marketplace` に変更され、プラン サブスクリプションとの区別が明確になります。
- **Free プランのクォータは Admin Plans ページで読み取り専用です。** System Settings → Default Monthly Token Quota から取得します。そこで編集すると自動的に反映されます。バックエンドは Free プランの `monthly_token_quota` への PATCH リクエストを無視します。
- **トークン クォータは、billing ページ、プラン カード、admin Plans テーブル全体で `5M` / `100K`** で表示されます (`5,000,000` ではなく)。Admin INPUT フィールドは引き続き生の数値を受け入れます。
- **翻訳の権限がロケール別ファイルから単一の用語集に移行しました。** ルールは [`scripts/translation-glossary.md`](https://github.com/fim-ai/fim-one/blob/master/scripts/translation-glossary.md) に存在し、すべての LLM 翻訳呼び出し (JSON、MDX、README) に読み込まれます。pre-commit フックは生成されたロケール ファイルへの手動編集を無条件に拒否します。誤訳を修正するには、用語集を編集して `--force` で再生成してください。
- **ライセンサーと準拠法。** FIM One Source Available License は **FIM Labs Pte. Ltd.** (シンガポール) が付与するようになりました。準拠法は中国から シンガポール に移行します。紛争は シンガポール の SIAC 仲裁 (仲裁人 1 名、英語) に進みます。新しいトップレベル `NOTICE` ファイルでは、R&D 属性、商標、サードパーティ コンポーネント ポリシーを記録しています。許可される使用または制限の条件に変更はありません。

### Fixed

- **Admin approve/reject of agents, connectors, knowledge bases, and MCP servers no longer fails on PostgreSQL.** The publish-review `reviewed_at` column is now timezone-aware, so approval writes succeed on PG (the bug was invisible on SQLite dev databases).
- **OAuth users can refresh their session again.** The OAuth-issued refresh token was stored in a form the refresh endpoint could never match, forcing a re-login once the access token expired; it is now stored as a digest like every other path.
- **Browser tab title now reflects the active sub-tab in `/settings` and `/admin`** (e.g. `Settings · Billing — FIM One`)。これにより複数のピン留めされたタブを区別できるようになります。
- **Usage page no longer reports "Unlimited" when an admin has set a default token quota** — it now resolves through the unified quota chain (per-user override → plan tier → system default).
- **Agent settings: bound resources no longer flicker as "(已删除)" on entry.** Orphan badge waits for inventory fetches to settle before rendering.
- **Toasts now follow the light/dark theme** instead of being hardcoded to dark.
- **Usage by-agent breakdown no longer duplicates "Direct Chat" rows** for conversations tied to deleted agents.
- **Self-hosted `./deploy.sh` no longer fails with `container name already in use`** — sweeps hash-prefixed zombie containers and DooD sandbox children before `docker compose up`.
- **No more redundant `chore(i18n): sync translations` commits after pushes** — the pre-commit translation hook now stages `.translation-cache.json` alongside translated files.
- **Agent chat no longer crashes when a confirmation-required tool runs in an unbound-agent session** — the gate bows out gracefully when there's no agent to route for.
- **Retry no longer fails on strict-alternation providers (Claude) when history contains orphan user messages from stopped turns** — consecutive same-role messages collapse into a single turn before dispatch.
- **Playground retry no longer briefly shows the query twice** during the pre-stream window.
- **ReAct agent now acknowledges and stops after an operator rejects an approval request**, instead of retrying paraphrased tool calls.
- **Playground "Suggested follow-ups" returns and is now opt-in per agent** (default off; new `Follow-up Suggestions` toggle in agent settings).

## [v0.8.5] - 2026-04-23

### Added

- **貢献者フレンドリーなi18nワークフロー**: 貢献者はEnglishソースファイルへのPRを提出する際に`LLM_API_KEY`を設定する必要がなくなりました。ローカルのプリコミット翻訳ステップをスキップした場合（キーなし）、新しい`.github/workflows/i18n-sync.yml`ワークフローがPRマージ後にEN → ZH/JA/KO/DE/FRに翻訳し、結果を自動コミットします。プリコミットフックは生成されたロケールファイルへの手動編集を拒否するようになりました（正当な翻訳修正用の`ALLOW_LOCALE_EDIT=1`オーバーライド付き）。これによりENソースと翻訳出力間のサイレント・ドリフトを防止します。
- **i18n CIフォールバックのエンドツーエンド検証**: スモークテストプッシュ（ENのみ、ローカル翻訳フック省略）により、GitHub Actionsワークフローが変更されたソースを検出し、5つのロケール全てに翻訳し、再帰を防ぐための`[skip ci]`を付けてmasterに自動コミットされることが確認されました。
- **Exa統合ドキュメンテーションページ**: サイドバーに専用の統合セクションを追加し、最初のExa ページはフルExa検索サーフェス（neural/fast/deep-reasoning/instant）、フィルタリング、コンテンツ取得、およびニュース監視、研究論文検索、深い推論エージェント向けの3つのチューニング済みプリセットをカバーします。Exa統合ディレクトリのパートナー向けランディングページとして機能します。
- **信創データベースサポート**: データベースコネクタは、PostgreSQL/MySQLとともにKingbaseES（人大金仓）、HighGo（瀚高）、DM8（达梦）をリストするようになりました。KingbaseESとHighGoはPG互換で`asyncpg`を再利用し、追加の依存関係はありません。DM8は公式の`dmPython`ベンダーホイールを使用します。独立した`scripts/test_xinchuang_dbs.py`でオペレータはCLIからライブ接続性を検証できます。
- **Feishuチャネル + IM経由の確認ゲート**: 新しい`Channel`リソースタイプ（組織スコープ、認証情報は保存時に暗号化）により、組織はFeishuアプリを接続して送信メッセージを行えます。`requires_confirmation=True`でフラグされたツールは、ポータルの確認ダイアログにのみ表示される代わりに、設定されたFeishuグループに対して承認/却下のインタラクティブカードを送信します。グループの任意の認可メンバーがFeishuから直接承認または却下できます。設定 → チャネル管理UI（リスト、作成/編集（ダーティ状態保護）、コールバックURL表示可能な詳細情報）、CRUD API（`/api/channels`）、およびFeishuイベントコールバックエンドポイント（`/api/channels/{id}/callback`）にはシグネチャ検証とURLチャレンジサポートが含まれます。v0.9 IM Channel統合ロードマップアイテムの第一段階で、2026-04-24路演向けにスケジュールより前に出荷されます。
- **Agent Hook System（スケルトン）**: `src/fim_one/core/hooks/`の新しい`PreToolUseHook` / `PostToolUseHook`抽象化により、決定的ロジックがLLMループ外で実行できます。FeishuGateHookは最初の具体的実装で、確認ゲートフローに接続されています。完全なフックライフサイクルとユーザー定義YAMLフックはv0.9スコープのままです。
- **Hook Systemがnow live in ReAct and DAG runtime**: `model_config_json`で`hooks.class_hooks`を宣言するエージェントは、すべてのチャットセッションでそれらのフックがインスタンス化および登録されます。最初のコンシューマであるFeishuGateHookは、エージェントが`requires_confirmation=True`でフラグされたコネクタアクションのツールを呼び出すときに自動的に発火し、組織のFeishuグループに承認/却下カードをポストし、ツールをブロック、判定に基づいて再開またはアボートします。以前はフック抽象化が実装されていましたが、Webレイヤーの何もそれをライブチャットに接続していませんでした。
- **ChannelsおよびHook System アーキテクチャドキュメント**: 新しい`docs/architecture/hook-system.mdx`は3つのフックポイント、フックがLLMループ外で実行される理由、およびFeishuGateHookをエンドツーエンドで説明します。既存のアーキテクチャページ（system-overview、organization、react-engine、philosophy）はそれにクロスリンクします。READMEはメッセージングチャネルをv0.8の第一級機能としてリストし、Application Layer図にはPortal/API/iframeとともにIM ターゲットが含まれます。
- **Hook Approval Playground**: チャネル詳細シートに「Test Approval Flow」アクションが追加され、機密ツール呼び出しをシミュレートし、リンクされたFeishuグループに実際の確認カードをプッシュ、レビュアーの決定をライブでポーリングします。既存のプレビューボタンとは異なり、これは完全な本番パス（本物の`ConfirmationRequest`行、実際のFeishuコールバック、ステータス遷移）を実行するため、デモと実装前のリハーサルは本番フックが使用するのと同じコードパスを使用します。

- **エージェント単位のタスク完了通知**: エージェントは長時間実行のReActまたはDAGタスクが終了したときに、組織のチャネル（現在Feishu）にサマリーカードをプッシュできるようになりました。設定 → エージェント → 通知でエージェント単位で設定可能です。汎用送信通知パターンの最初のコンシューマです。
- **設定可能な確認ゲート — インラインまたはチャネル**: すべてのエージェントは設定で「承認」セクションを持つようになりました。3つのルーティングモード（自動/インラインのみ/チャネルのみ）、承認者スコープセレクタ（イニシエータ/エージェント所有者/組織内の全員）、「すべてのツール呼び出しで確認が必要」オーバーライド、および明示的な承認チャネルピッカーがあります。自動モード（Auto mode）は、リンクされたチャネルが存在する場合はそれを使用し、チャネルがない場合はチャットストリーム内のインライン承認カードに適切にフォールバックします。これにより、チャネルのないエージェントはサイレント失敗ではなく、実際の承認UXを取得します。新しい`POST /api/confirmations/{id}/respond`エンドポイントはFeishuウェブフックと単一の決定記録パスを共有するため、すべての承認——チャットでクリックされたかFeishuグループでクリックされたかに関わらず——同じ`approver_user_id`と`decided_at`監査フィールドをスタンプします。

### 変更内容

- Playground読み込みインジケーターは、8秒後に疑似的な最大幅で止まっていた見た目の悪いプログレスバーの代わりに、微妙なテキストシマーを使用するようになりました。2つの既存のシマー実装（`.shiny-text`と`.text-shimmer`）を、オプションのウォームプリセット付きの単一のテーマ対応プリミティブに統合しました。
- Connector カードは、connectorに`allow_fallback`が無効な場合、「Private default」バッジ（ツールチップ付き）を表示するようになりました。これにより、所有者は一目で、どのコネクターがすべてのユーザーに独自の認証情報を持ってくることを要求するかを判断できます。コネクター設定フォームの「Allow-Fallback」トグルの下のヘルプテキストも、このフラグが他のユーザーとの共有のみをゲートするということ——所有者は自分のデフォルト認証情報をいつでも使用できる——を明確にしています。

### Fixed

- `allow_fallback=false` と default credential のみ (per-user credential なし) を持つ connector の owner による connector calls は、"Requires authentication" で 401 を返さなくなりました。owner は fallback gate から除外されるようになり、そのフラグは*他の*ユーザーが owner の default credential を借用できるかどうかのみを制御します。以前は owner 自身の agents が黙ってunauthenticated requests を送信していた問題、および同じ問題が workflow `connector_action` ノードにも影響していました。
- Conversation export は、auto-routed DAG conversations に対して常に "Standard" を表示するのではなく、正しいモードラベル ("Planner" / "規画") を表示するようになりました。
- Export timestamps は raw UTC を表示するのではなく、ユーザーが設定したタイムゾーンを尊重するようになりました。
- Uploaded file content は exported conversations に漏出しなくなりました。ユーザーのメッセージテキストのみが含まれます。

- Feishu channel setup hints は、UI 自体が既に中文である場合、中文ラベルを重複表示しなくなりました (例：以前は "事件与回调 (事件与回调)" をレンダリングしていました)。

- Playground agent list は published ones のみではなく、すべての accessible agents を表示するようになり、draft agents は最初に publish せずにテストできます。

## [v0.8.3] - 2026-04-16

### 追加機能

- **`convert_to_markdown` 組み込みツール** — Microsoft の MarkItDown を使用して、任意のファイル、URL、YouTube リンク、またはデータ URI をクリーンな Markdown に変換する新しい汎用エージェントツール。PDF、Word（.docx）、Excel（.xlsx/.xls）、PowerPoint（.pptx）、HTML、JSON、CSV、XML、ZIP、EPUB、Outlook .msg、画像、オーディオ（音声→テキスト）、YouTube トランスクリプトに対応。すべてのエージェントでデフォルトで利用可能——`web_fetch` と同じティア。ビジョン対応 LLM が設定されている場合、埋め込み画像とスキャン済み PDF ページは、公式の `markitdown-ocr` プラグイン経由で自動的に OCR されます。これまでこの機能はバックグラウンド RAG 取り込みパイプラインに隠されていましたが、エージェントが対話的な会話パスで利用できるようになりました。

- **ビジョン対応 RAG 取り込み** — Office ドキュメントとスキャン済み PDF の知識ベースアップロードは、ワークスペースのデフォルトビジョン LLM（DB 優先、ENV フォールバック）を解決し、取り込み中に OCR のために MarkItDown に渡すようになりました。ゼロリグレッション：ビジョン対応モデルが利用できない場合、取り込みはサイレントにテキストのみモードにフォールバックします——機能前の動作と完全に同じです。

- **チャット応答の完了が高速化** — SSEストリームはエージェント完了直後に閉じるようになり、タイトル生成とフォローアップ提案は応答をブロックせずにバックグラウンドで実行されます。

- **モデルごとのネイティブ関数呼び出しトグル** — `tool_choice_enabled`設定（ENV + 管理者によるモデルごと）により、強制ツール選択を拒否するモデルはレベル1をスキップしてJSONモードに直接進むことができます。設定 → モデル → 詳細で設定可能。
- **DAG品質の大幅改善** — 5つの改善：非高速ステップの汎用モデルへのデフォルトモデルアップグレード、計画におけるスキル自動検出、法務/医療/金融ドメイン向けの引用検証、設定可能な切り詰め乗数を備えた構造化コンテンツコンテキスト保持、ルーターのドメイン分類とドメイン対応モデル選択。
- **ReActのドメインモデルエスカレーション** — 専門ドメイン（法務/医療/金融）は、推論モデルへの自動エスカレーション、必須のウェブ検索、および引用検証を行います。
- **ファイル添付ダウンロード** — チャットメッセージのファイルカードはクリック可能になり、元のファイルをダウンロードできます。
- **管理者通知マスタースイッチ** — 管理者メール通知のグローバルオン/オフトグル、ランタイムSMTP検出付き。SMTPが設定されていない場合は警告バナーを表示し、すべての通知コントロールを無効にします。
- **SMTP Reply-Toヘッダー** — 新しい`SMTP_REPLY_TO`環境変数により、返信を送信者とは異なるアドレスに送信できます。
- **リソースフォークフェーズ1（MCPサーバー + スキル）** — `POST /api/mcp-servers/{id}/fork`および`POST /api/skills/{id}/fork`エンドポイントは、`visibility=personal`と`forked_from`系統追跡を備えたユーザー所有の深いコピーを作成します。MCPサーバーフォークでは暗号化されたenv/ヘッダーがスキップされ、スキルフォークでは公開ステータスがスキップされます。Alembic移行により、両方のテーブルに`forked_from`列が追加されます。41個のテスト。
- **ワークフロー接続依存関係の自動サブスクライブ** — `DependencyAnalyzer._resolve_workflow`は、サイクル検出（訪問済みセット）を使用してサブワークフロー依存関係を再帰的に解決するようになりました。エージェントおよびサブワークフロー ノードは、依存関係マニフェストのコンテンツ依存関係として正しく追加されます。不足しているリソースは適切に処理されます（ログ警告、失敗なし）。19個のテスト。
- **プリビルトソリューションテンプレート（マーケットシードコンテンツ）** — 8つの業界別ソリューションテンプレートが初回ユーザー登録時にべき等にブートストラップされます：財務監査、契約レビュー、データレポート、ITヘルプデスク、HR オンボーディング、営業アシスタント、コンテンツライター、会議サマリー。各テンプレートは、中国語のSOPを含むエージェント + スキルをバンドルしています。マーケットプレイスの即座の利用可能性のためにマーケット組織に公開されます（`visibility=org`、`publish_status=approved`）。4個のテスト。
- **ReActサイクル検出** — 繰り返される同一のツール呼び出しの決定論的検出。同じ引数を持つ3つの連続呼び出しの後に警告を挿入し、エージェントが失敗するツールでループするのを防ぎます。`REACT_CYCLE_DETECTION_THRESHOLD`で設定可能。
- **ReAct完了チェックリスト** — ツールが使用された場合の最終回答を受け入れる前の1回限りの検証プロンプト、時期尚早または不完全な応答を削減します。エージェントインスタンスごとにトグル可能。

### Changed

- **完了チェックリスト最小ツール閾値** — チェックリストは、エージェントが3回以上のツール呼び出しを行った場合にのみ実行されるようになりました（`REACT_COMPLETION_CHECK_MIN_TOOLS`で設定可能）。シンプルな1～2ツールタスクは不要なレイテンシを避けるため検証をスキップします。
- **動的システムプロンプト予算配分** — コンテキスト予算計算から固定の`SYSTEM_PROMPT_RESERVE`（4Kトークン）を削除しました。ContextGuardはシステムプロンプトを動的に考慮し、各イテレーションに約4Kの追加利用可能コンテキストを提供します。
- **一元化されたツール切り詰め** — すべてのツールタイプが共有モジュールに切り詰めを委譲するようになりました。デフォルトは`TOOL_OUTPUT_MAX_CHARS`、`TOOL_OUTPUT_MAX_ITEMS`、`TOOL_OUTPUT_MAX_BYTES`環境変数で設定可能です。
- **ドメイン検出の分離** — ドメイン分類は各エンドポイントで独立して実行され、自動ルーティングにバンドルされなくなりました。ドメインSOP指示は、Webサーチを強制するのではなくガイドするようにソフト化されました。
- **`AUTO_ROUTING`環境変数を削除** — 自動エンドポイントは常にクエリを分類します。

### 修正済み

- **メッセージの重複送信** — チャット入力は同期ガードを使用して、ラピッドクリック時に同じメッセージが複数回送信されるのを防ぐようになりました。
- **構造化出力デグラデーションチェーン** — 3レベルのフォールバック（ネイティブFC → JSONモード → プレーンテキスト）が全レベルを正しく通過するようになりました。
- **`json_mode_enabled` DB値が無視される** — 管理画面経由で構成されたモデルが、環境変数へのフォールバックではなく、モデル単位の設定を正しく使用するようになりました。
- **DAG計画失敗メッセージ** — 生のパイプラインエラーではなく、ユーザーフレンドリーな二言語メッセージを表示するようになりました。
- **MCP サーバーオーナーのallow_fallbackバイパス** — サーバーオーナーが`allow_fallback=False`でブロックされなくなりました。
